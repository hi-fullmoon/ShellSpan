# Remote sandbox infrastructure and binding

Infrastructure inspection and target-specific verification are distinct. Neither command changes user policy, persists a session/grant, installs components or modifies remote security. Actual restricted admission uses the production native verifier and the current frozen header.

`agent_runtime_probe_remote_sandbox_backend` accepts `input: { sessionId, requestId }`, where requestId is a UUID. The backend reads the current Agent header and connected SSH terminal, validates the frozen profile/account, and runs a fixed bounded command using the existing reviewed SSH executor and known-host verification. All connection/SSH work runs in a blocking worker. Registration precedes worker queuing. Output limits are 4096 bytes per stream and 16384 bytes total; command timeout is 15 seconds. Existing blocking DNS/handshake calls retain connection-layer timeouts and may finish teardown after the caller observes cancellation.

The response has `target`, `bindingRevision`, `infrastructureAvailable`, `launcherAvailable`, `executionOs` (`linux`, `macos`, `unsupported`), `backend` (`bubblewrap`, `seatbelt`, null), `workspaceVerified: false`, `admissionEnabled: false`, and `gaps`. Availability means an existing executable or a fixed ephemeral launcher check, not verified project/sensitive/network/process restrictions. The response is discarded if the header, connection generation, account, authentication binding or profile changes before completion. There is no probe cache or recovery replay.

`agent_runtime_cancel_remote_sandbox_probe` accepts the same input and only cancels the probe operation derived from that session and UUID. Its operation namespace is separate from deployment/other reviewed execution IDs. Cancellation does not claim remote process-tree termination. The fixed probe has no installation, configuration change or user command input. Invalid/missing operations return the existing cancellation-registry error.

`agent_runtime_verify_remote_sandbox_target` accepts `input: { target, policy, requestId }`, with restricted policy and UUID requestId. Native creates a transient probe header, validates the real connected target/profile and invokes production prepare_sandbox in a blocking worker. Output `RemoteSandboxVerification` has target, policy, executionSurface=direct, canonicalRoot, remoteUid, sshHostKeySha256, sourceBindingDigest and capability. The digest covers native config nonce/generation and is a fact identifier, not authority. UI matches the current target and discards stale responses; actual start validates its own header/revision. Mac availability requires real SFTP canonical root/home/UID, fixed file/network kernel tests, then actual native stdin/cancel/signed cleanup on that target. Infrastructure flags do not satisfy this.

NativeAdapter pending calls retain native-only `RemoteExecutionBinding`: connected terminal generation, full FrozenTargetIdentity, main/jump credential references and Database-controlled nonce. TEMP SQLite triggers on the product connection atomically change it on profile writes; caller timestamps and restored logs do not revive authority. External DB writes are outside this same-connection guarantee. NativeEngine captures a backend stamp at prepare, checks it at issue, binds it into sandbox digest and rechecks at dispatch. Old signed capabilities stay invalid after re-verification. Inline jump secrets are rejected. This binding is not serialized as a grant.

Frozen host keys are compared after handshake/known_hosts validation and before authenticate. Unverified restricted jump routes are rejected, while Host uses its existing path. Frozen root/readAllow/writeAllow/deny feed the actual remote Seatbelt profile; all remote resource/network extensions remain unsupported. Paths come from SFTP and remote pwd, not desktop filesystem inference. Standard POSIX path helpers avoid desktop-specific separators.

Static control code uses an existing remote interpreter without installing files. Control requests/token travel through bounded JSON lines on encrypted SSH stdin, never argv/environment/logs/ordinary config. Native waits for a separate signed ready receipt before queued user stdin. HMAC receipts bind job/root/command+policy digest, started, controllerFinished and group termination before owned cleanup. Unknown cleanup pauses dispatch, never derives success from child stdout/channel close or replays commands. Capability remains partial with processLifecycle=false for known hostile-descendant/same-account/path-alias limits.

Host Direct results add `sandboxPolicy: "host"`, `executionTarget`, `sandboxBackend: "host-account"` and the existing `sandboxCapability` facts with file/network/process isolation false. Approval mode and individual tool contracts still apply. A cancelled/timed-out SSH channel retains `terminationConfirmed: false` with controller `terminationUnconfirmed` facts; it does not promise that background descendants stopped.

The existing v5 envelope and native tool schema version are unchanged. Verified remote Direct result uses sandboxBackend=remote-macos-seatbelt with matching contract/partial capability. Non-Shell tools remain individually gated at prepare/execute; MCP also checks issuance. Remote file/HTTP/SFTP/deployment/MCP tools do not inherit Shell isolation. Unverified targets, systems, root accounts and restricted jump routes remain closed.
