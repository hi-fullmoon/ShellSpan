# 流式事件追加与容量统计

## 提交约束

仅包含 `assistant/chunk` 的批次采用增量追加。这类事件不改变 Model Surface、Inbox 或会话状态，因此不复制已有事件、不重新推导完整 Surface。每条新增事件仍完成身份、连续序号、时间戳、作用域、大小、状态及脱敏校验。混合批次和其他事件继续使用完整事务候选记录。

校验与编码全部通过后，先追加日志并执行 `sync_data()`，成功后才推进内存事件、观察器和快照缓存，再发布事件。校验失败或写入失败不发布事件、不更新内存会话。启动恢复继续执行完整日志重放和校验。

活动和归档日志的总容量在配置存储时扫描一次。创建、追加和删除成功后按实际编码长度或文件长度更新总数；归档移动不改变总数。子会话创建时先计入子日志，再提交父描述事件。磁盘操作失败或子日志回滚时使缓存失效，下次写入重新扫描两个目录。该缓存由单个运行时存储实例维护，不支持其他进程同时修改其私有日志目录。

同步写盘与存储锁的串行提交边界保持原有语义。本次减少锁内的历史处理和目录扫描，不改动前端 Markdown 渲染及刷新频率。

## 回归与测量

回归覆盖新增事件批次拒绝、真实文件错误、提交后发布、恢复后的事件与 Surface 一致性、归档和删除的容量更新，以及子会话描述提交失败后的回滚。

手工运行性能测量：

```sh
cargo test --manifest-path src-tauri/Cargo.toml durable_stream_append_scaling --lib -- --ignored --nocapture
```

测量重复回放仓库已录制的两条流式事件，使用临时目录和真实同步写盘。分别预置 0 或 2,000 批历史，再测量 100 次追加；默认测试不采用机器相关的耗时阈值。

2026-09-28，本机 macOS 调试构建单次对比：

| 预置历史 | 优化前中位数 | 优化后中位数 | 优化前 P95 | 优化后 P95 |
| --- | --- | --- | --- | --- |
| 0 批 | 5.47 ms | 5.00 ms | 7.89 ms | 6.51 ms |
| 2,000 批 / 4,000 条流式事件 | 6.62 ms | 4.99 ms | 8.89 ms | 6.91 ms |

这些数字包含本机文件同步耗时，不代表模型生成速度或界面帧率。
