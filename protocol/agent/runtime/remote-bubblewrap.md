# Remote Bubblewrap execution, version 1

The saved SSH profile selects `readOnly` or `workspaceWrite` and a remote workspace. The desktop Rust broker owns policy lookup, host-key verification, credentials, approval, dispatch, cancellation and result projection. The administrator owns the Linux runner, Bubblewrap package, runtime filesystem and workspace mount. See [deployment](../../../docs/remote-agent-sandbox.md).

- Both modes use the same Bubblewrap mount, user, PID, IPC and network namespaces, dedicated proc and device mounts, private temporary directories and a socket-blocking seccomp filter. The runtime filesystem is read-only; the only persistent data mounted for the job is the configured workspace. SFTP runs OpenSSH `sftp-server` inside this same policy; `readOnly` also passes `-R`. File previews, paths and contents, search, writes and patches, transfers, file references and remote skill discovery use the Agent SFTP route. No host SFTP connection or login shell is used for these operations. A download may still write to the separately authorized local target.
- SSH and both host keys are checked before credentials or subsystem traffic. The SSH subsystem is `shellspan-bwrap-v1`. UTF-8 JSON lines carry `inspect`, `probe`, `sftp` or `command` setup requests. The SFTP version receipt is followed by SFTP v3 over the same channel. The command runner sends a one-use receipt before receiving the command. The response contains the receipt, a confirmed terminal state, exit code, truncation and bounded base64 streams. It is generated outside the program's stdout and stderr pipes. No command is read or accepted by preflight.
- Preflight uses the saved account, the configured workspace, the real launcher arguments and the actual SFTP client and server. It checks the protocol version, Linux, Bubblewrap, workspace read/write behavior, the host witness, PID and network namespaces, blocked socket creation, and SFTP visibility and write behavior. All writes are to randomly named temporary probe files that are removed by the probe and on runner shutdown. Missing Bubblewrap can produce a fixed installation suggestion for the detected distribution and package manager; no install is dispatched by ShellSpan.
- Approval and sandbox policy are independent. Each call is bound to the normalized tool arguments, frozen target, connection revision, trusted host keys and policy version. Changing the profile host, SSH account or jump configuration, or the sandbox workspace or mode, revokes old approvals, including a change away and back. The approval and dispatch paths recheck the binding; a preflight result is a point-in-time observation and cannot grant future execution. Each new operation verifies the actual executor again. Manual terminal, manual SFTP and the separately authorized restricted sudo path keep their existing behavior.
- Sandboxed `run_terminal_command` is foreground Direct execution and starts in the configured workspace. Agent use of the existing terminal, old process handles, host diagnostics, network probes, scratch provisioning and other unsandboxed paths is refused. Cancellation sends SSH EOF and waits for a bounded terminal receipt. A missing receipt after possible dispatch returns `Uncertain` with `doNotRetry`; reconcile the workspace before continuing. The existing durable tool journal never replays an unresolved dispatch. There is no fallback on a missing executor, a protocol mismatch, capability failure or transport failure.
