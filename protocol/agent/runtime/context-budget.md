# 请求预算、工具结果与上下文恢复

## 本地存储目录

Agent 与数据库共用 ShellSpan 数据根目录：正式版为 `~/.shellspan`，开发版为 `~/.shellspan-dev`；显式 `SHELLSPAN_DATA_DIR` 配置优先。会话和归档位于 `agent-runtime/sessions-v5`、`agent-runtime/archives-v5`，产物位于 `agent-runtime/artifacts-v2`，图片位于 `agent-runtime/images-v1`，原生命令恢复记录位于 `agent-native-call-checkpoints`。这些路径均相对于同一个数据根目录，原生工具的数据保护也使用该根目录。

不读取或迁移 Tauri 应用数据目录中的旧 Agent 数据。Tauri identifier 不再隔离 Agent 存储，独立验证必须显式指定 `SHELLSPAN_DATA_DIR`。

应用日志的写入和读取统一使用数据根目录下的 `logs/`。远程文件打开缓存必须使用 `open-cache/`，无法解析数据目录时直接报错，不回退系统临时目录。UI 偏好与图片草稿保存在同一根目录的 `frontend-state.db`；主题继续使用主数据库中的偏好。应用不再使用 localStorage 或 IndexedDB 持久化这些数据，也不迁移或读取旧 WebView 记录。

图片草稿的正文、图片与待发送身份以 SQLite 事务保存。写入、从编辑器移交至待发送记录、取消恢复和确认删除均检查相关记录的版本；任一版本冲突时整批回滚，保留较新的编辑内容。SQLite 操作在阻塞工作线程执行，IPC 不记录草稿正文、图片或参数内容。

## 请求预算

Agent 在每次请求前分别估算系统提示词、工具定义和消息的 tokens 与字节数，预留本次请求的输出预算及安全空间。压缩触发阈值为可用输入的 85%，常规目标为 60%。这些值属于应用的容量策略，不是服务端实际 tokenizer 的计数。

模型定义中的 `maxOutputTokens` 声明模型输出能力，独立的可选 `requestOutputTokens` 决定单次请求实际输出上限和输出预留，必须为正整数且不超过模型能力。未设置时取 `min(maxOutputTokens, 16384, max(1, floor(contextWindow / 8)))`，包括缺少该字段的旧定义；明确设置的请求预算保持不变。200,000 上下文配合 131,072 输出能力时，默认请求预算为 16,384，压缩触发线为 147,573。用户设置的上下文可以小于模型输出能力；保存时不缩小能力声明，输入空间按实际请求输出预算检查。用户设置的上下文容量保持不变。请求参数、不可变请求快照、文件编辑输出提示和准入预算均采用同一有效请求输出值；摘要与连接测试仍采用各自更小的请求预算。

`request/context` 的可选 `requestBudget` 记录 `outputTokens`、`safetyTokens`、`usableInputTokens`、`compactionThresholdTokens` 和 `compactionTargetTokens`。上下文详情按此请求证据显示预留、输入容量、压缩触发线与目标；触发线另显示其占总上下文的比例。旧事件缺少预算时不推测历史阈值，代次推进或模型容量改变时清除旧阈值，等待新的请求证据。

后台请求计量覆盖系统、工具、消息、图片和准备后的私有 replay。`requestBudget.inputMeasurement` 只保存公开模型/路由配置的 SHA-256、原始 `heuristicTokens`、`usageAdjustmentTokens` 和可选 `anchorRequestId`，不保存请求正文或凭据。相同配置、相同上下文代次中最近一个具有完整输入 usage 的请求可作为基准：实际输入为未缓存输入、缓存读取及缓存写入之和；本次压力为实际输入加上相对该基准的启发式增减量，且不低于本次原始估算。输出及 reasoning 用量不重复加入输入基准。新增消息、工具结果缩减和准备阶段新增的 replay 都重新计量；校正只影响总量，分项继续标记为估算。缺失计量证据或完整 usage、配置改变、成功压缩时回到原始估算，不跨代复用；重新打开会话可从日志恢复有效基准。每个新基准使用原始估算，避免把已校正总量再次作为原始估算而累加误差。字节上限保持独立检查。

安全预留为上下文的 5%（最低 1024 tokens）。模型配置必须在请求输出预算与安全预留之外留下可用输入；运行时还会检查输入预算能否容纳不可压缩的系统提示词和工具定义。无有效输入空间时，以 `INVALID_MODEL_TOKEN_BUDGET` 提示降低请求输出预算或增大上下文，不将输入容量兜底为 1 token，也不执行无效的工具结果外置或压缩。

预算压力出现时，`context-budget` 产物记录总预算、消息类别的数量/tokens/字节数和各工具结果的大小。记录不包含消息正文、工具参数、主机信息或凭据。工具输出缩减前后均可形成记录，相同内容与类型不重复发布。

界面将内部工具结果、预算诊断、压缩证据和恢复检查点按轮次合并为默认收起的“运行详情”，保留逐项查看与原始审计事件。交付给用户的报告、导出文件等其他产物继续单独展示。

请求准备完成后再次估算预算，包括准备阶段生成的 provider native replay。只有满足可用输入 tokens 和字节上限的请求才会发送；服务端仍可能因 tokenizer 或容量声明差异返回 `ContextTooLarge`。

## 上下文占用显示

主指标使用当前 surface generation 中最近一次服务商确认的输入用量，包含未缓存输入与缓存输入。新请求开始时保留该确认值，不切回整段请求的本地估算；新响应提供完整输入计数后再更新。最新请求估算及系统、工具、消息分项在详情中单独标注，不能将估算分项按比例显示成实际用量的组成。

尚无服务商确认值时，主指标明确显示为估算。成功压缩或提交新 surface generation 时清除旧确认值及旧估算；尚无新计数时显示“待确认”，不能显示零占用。新请求估算到达后显示压缩后估算，直到同一代上下文收到新的服务商确认。旧代请求的迟到 usage 不得恢复旧值；失败的压缩不清除当前计数。后台准入与压缩阈值使用上述具有启发式下限的请求计量。

## 工具结果

原有超过 8 KiB 的普通工具数据继续保存为脱敏 `tool-result` 产物。在出现预算压力且请求具备 `read_tool_result` 能力时，单项内联结果的目标字节数为可用输入字节数的 1/16，范围限定在 1–8 KiB。超过目标的完整脱敏结果保存为 `model-tool-result` 产物，模型收到状态、摘要、退出码/进程句柄等必要标量和产物引用。

`read_tool_result` 参数为：

- `artifactId`：当前会话已提交的 `tool-result` 或 `model-tool-result` 引用。
- `offset`：可选，默认 0；从 0 开始的 UTF-8 字节位置，后续使用返回的 `nextOffset`。
- `maxBytes`：可选，默认 2048；正整数超过 2048 时按 2048 读取。零、负数和非法类型仍拒绝；不足以容纳下一个完整字符时拒绝请求，并提示省略该参数使用默认页大小。

返回 `untrustedExcerpt`、本次采用的页大小 `maxBytes`、实际读取字节数 `readBytes`、`nextOffset`、`hasMore`、总大小和 SHA-256。片段末尾对齐 UTF-8 字符边界，实际字节数可能小于页大小。`hasMore` 为 true 时，以 `nextOffset` 作为下一次 `offset`，不得用请求页大小推算；到达末尾返回空片段、`readBytes=0` 和 `hasMore=false`。读取前验证归属与完整性；禁止跨会话读取或读取 replay/摘要等其他类型的产物。片段属于不可信数据。文件读取在阻塞任务中执行，工具调用保留能力、取消、审计与生命周期检查。

具有读取能力的 `SafePrefix` 子代理，在首次准备包含继承上下文的请求时，将被引用的工具结果转存到自己的产物目录，并提交自身的产物元数据。可复制范围仅限父会话已冻结继承边界之前提交的 `tool-result` / `model-tool-result`；嵌套引用也遵循同一范围。未引用的结果、边界之后的结果、其他会话、replay 和摘要产物均不转存。空白继承与未授予读取能力的子代理不执行转存。

副本保留原 ID、完整字节、SHA-256、类型和敏感级别，读取工具继续只查当前会话。重复准备与重启后校验并复用已提交副本；父文件之后缺失不会阻止读取有效副本。父数据在首次复制时损坏，或子副本损坏时，停止该转存流程，不自动覆盖或修复历史证据。转存在阻塞任务中执行，并在各产物之间及发布元数据前检查取消。

完整 Skill 指令、`read_terminal`/`wait_terminal` 的临时观测保持现有语义，不因预算管理写入持久化产物。`ask_user_question` 的用户回答保留完整的原始格式，不作为普通工具输出外置；回答自身过大时通过整体预算和超限恢复处理。历史工具调用及结果的身份和配对不被删改。

## 压缩

压缩在确认有安全边界之后、生成摘要之前提交并发布 `compaction/start`，附带唯一的 `compactionId`。整个过程（包括分片、重试、回退及产物保存）使用单调时钟计时；结束时的 `compaction/end` 携带同一 ID 和 `durationMs`，状态为 `completed`、`failed` 或 `cancelled`。成功的产物事件、摘要和完成事件仍在同一批次原子提交；失败或取消只结束进度，不推进上下文代次。异步任务被丢弃时也结束进度，存储故障仍按原有错误路径处理。

对话在开始事件到达后显示“正在压缩上下文”和已用时，即使新一轮尚未提交 `turn/start` 和运行状态，活动压缩也会被投影为正在运行。结束后停止计时与动画并保留结果及实际耗时；失败与中断原因脱敏后保存在结束事件的可选 `reason` 字段。历史日志中没有上述 ID 和计时字段的旧事件不用于推断耗时。分页只取得结束事件时，仍可显示后端记录的耗时。中断恢复前保留未结束压缩的恢复门禁，显式恢复后清除其活动状态，不重放摘要或工具操作。

检查点的当前目标、成功条件和当前轮次用户输入从原始已提交事件确定，不再固定使用会话创建时的目标。即使当前请求位于压缩边界之后的保留后缀，它仍决定检查点服务的当前任务。语义模型不能改写这些字段；其提炼的历史约束单独标注为仅在仍适用时参考，一次性回复要求只属于原轮次。每个摘要请求都携带同一份当前任务依据，并区分用户、运行时及其他消息来源；旧的运行时成功条件注入不作为新的用户指令进入摘要来源。

后续主请求另外从原始日志重建当前任务，因此即便历史摘要曾误写目标，也不能据此恢复旧的一次性指令。当前任务输入完整纳入实际请求预算，不能通过压缩删除其尾部要求来宣称请求可发送。

压缩边界必须包含完整工具交互。等待审批时的 `step/end` 不构成安全边界；审批结束、全部模型工具调用都有已提交结果之后，同一步骤后续的 `toolsCompleted` 边界可以使用。调用身份由步骤与调用 ID 共同确定，避免 provider 在不同步骤复用 ID 导致误判。未解决的恢复状态继续阻止跨界压缩。

摘要空间从固定输入及保留消息的预算中扣除后计算。如果固定部分已经无法低于触发阈值，不调用模型生成注定无法容纳的摘要。语义摘要必须符合完整结构；有效候选超过动态输出预算时，允许一次更简洁的语义重写，受原有总时间与输入预算限制，不静默截断已验证的语义内容。

语义摘要使用同一模型、连接和凭据的独立调用配置，不改变主任务的模型选择或推理设置。根据模型明确声明的能力，优先选择 `off`、`none`、`minimal` 或 `low`，没有这些选项时保留原设置；输出 tokens 上限不超过原值及 2048。结构化正文目标最多 4 KiB，正文与推理输出分别受 16 KiB 和 64 KiB 的硬限制约束，推理文本不占用 JSON 正文预算。

摘要按实际请求容量切片并顺序携带已有语义结果。总时限为首片 45 秒、每个后续片段增加 20 秒，最多 180 秒；网络重试和精简重写共用此总时限、512 KiB 累计输入预算和取消信号。超过限制仍保留原有失败记录及安全回退，不提交不完整的语义结果。

常规目标未达到时，只有压缩结果低于触发阈值、满足字节上限且至少减少原输入的 10%（最低 256 tokens），才允许提交并继续。最终产物引用和保留图片均纳入投影，提交后验证；下一次请求仍重新组装并检查实际预算。

投影使用实际组装请求中 Assistant 消息与工具结果的大小。Assistant 消息按保留后缀对齐，包括终端临时参数与准备后的 replay 元数据；继承上下文位于本地消息之前，其占用继续保留。预算诊断仅保存大小，不保存临时参数或私有 replay 正文。

## 超限恢复

请求准备后因 replay 等新增内容超限时，每个步骤先允许一次基于准备后预算的压缩，成功后丢弃旧 PreparedCall 并重新组装与准备请求。取消时停止；同一步骤不重复触发此恢复。任务累计 tokens 的准入判断也使用准备后的最终预算。

已准入的 PreparedCall 在网络或限流重试期间保持同一份输入，不重新执行普通预算压缩；需要上下文恢复时先结束该冻结请求，再重新准备。

内部压缩无法达到目标，但完整请求仍符合硬上限时，可保留原历史继续请求。超过硬上限且无法通过上述恢复继续，或服务端上下文错误的有界恢复失败时：

1. 保存 `context-budget-checkpoint`，包含任务状态、未完成工作、证据和当前 surface generation。
2. 结束当前步骤/轮次，以 `contextBudgetExceeded:` 说明原因，暂停其余排队输入。
3. 会话保持可继续的 idle 状态，不写入失败的 `session/ended`。

用户可调整模型或输入后继续。已完成操作及原始历史保留，不自动重放工具操作。界面沿用现有错误展示，并给出对应的双语恢复提示。

`HTTP_429` 继续使用独立的 provider 重试策略和服务端等待提示；不与上下文超限混合处理。

## 验证

相关 Rust 回归测试位于 `agent_runtime/tests/compaction.rs`、`tests/tool_output.rs` 和 `tests/runtime/mod.rs`。工具输出测试使用仓库真实文件以及真实产物存储、分段读取、归属和完整性验证。

真实历史会话的只读复核可通过环境变量 `SHELLSPAN_CONTEXT_AUDIT_LOG` 指定日志，并运行忽略测试 `historical_approval_budget_audit`。可选的 `SHELLSPAN_CONTEXT_AUDIT_REPORT` 输出仅含大小与边界的报告；不会修改原日志或保存其正文。该复核验证本次截图所涉的历史边界和结构化检查点投影，不替代真实服务端的语义摘要与续跑验证。
