# Agent 执行安全与使用体验设计

状态：总体设计；2026-09-27 已实施首版审批底线、单文件回收站工具与“帮我批准”的受限读取自动审核，其他阶段待实施。设计日期：2026-09-26。

首版实际范围：“完全访问”保留原名称与免逐次审批语义，包括命令、终端/进程输入、敏感操作及 MCP 调用。“帮我批准”通过后端规则自动审核明确工作目录内的普通读取，以及 macOS/Linux 上受限的本地直接读取命令；删除、提权、敏感访问、复杂脚本、远程命令、终端输入和 MCP 继续询问。新增本地 `trash_file`，要求当前摘要且只接受工作目录内的单个普通文件；结果说明从系统回收站手动恢复。复用单次凭证、角色限制、现有审批和工具结果。原生结构化写入不得修改受保护系统资源及 ShellSpan 应用数据；有限的字面量危险命令检查只作为辅助。

自动审核不调用额外模型，也不相信模型的授权声明。支持的本地单条命令为 `pwd`、`uname`、`ls`、`cat`、`head`、`tail` 的有限参数；固定系统程序直接执行，不经过 shell 或用户 PATH。文件通过目录句柄逐级打开，拒绝符号链接，目录身份绑定到单次凭证；边界失效就停止，不回退。具体限制和输出证据见当前协议。此能力不提供任意写操作的沙箱，Windows 命令和无法验证的操作仍请求人工批准。

首版未交付生产沙箱、远端执行器、目录/批量删除计划、应用内一键撤销或对恶意并发路径替换的原子保护。“范围内自动执行”的完整目标尚未启用。当前协议详见 `protocol/agent/runtime/file-and-script-execution.md`；下文为完整目标设计，不能将后续阶段视为当前已有能力。

适用范围：Agent 发起的本地文件操作、直接命令执行、可视终端输入、远程 SSH、MCP 和子 Agent。用户亲自在终端输入命令的行为保持原有终端语义。本文不授权修改其他页面，也不改变当前协议实现。

## 1. 产品目标与设计决策

让用户在明确范围内放心使用自动执行，同时让重要操作能够预览、停止和追查。日常操作少打断；确认必须有实际意义；能恢复时优先提供恢复。

推荐采用一套分层方案：后端统一策略、按主机和目录授权、进程级隔离、结构化可恢复删除，以及少量针对具体操作的确认。

核心决策：

1. 自动执行不扩大访问范围。执行方式与权限相互独立。
2. 默认继续使用现有“只读自动批准”的语义，不能升级后自动开放写入。“完全访问”是用户主动选择的免逐次审批模式；后续范围内自动审核用于增强“帮我批准”，不替换完全访问。
3. 普通文件移入回收站可以由会话范围授权覆盖，不逐个弹窗。目录删除、批量删除和永久删除单独处理。
4. 不提供一个永久关闭所有防护的 Agent 总开关。必要的范围扩展使用精确、有限期授权。
5. 不以命令名称、模型解释或另一个模型的判断代替执行边界。风险识别用于决定确认和给出解释，沙箱负责约束实际影响。
6. 没有隔离能力的 SSH 或已有交互式 shell 必须如实标注。用户确认可授权一次操作，但不能把它变成“有沙箱保护”。
7. 不承诺所有删除可恢复。允许任意程序写入一个目录时，程序也可能覆盖或删除该目录中的数据。

## 3. 用户如何使用

### 3.1 权限入口

沿用输入框底部现有权限菜单的位置、控件和布局，保留三个选项：

| 显示名称（建议） | 行为 |
| --- | --- |
| 只读自动执行（默认） | 普通结构化查询自动运行；修改操作请求批准。它不是绝对只读模式，说明中明确“修改前确认”。 |
| 每次确认 | 每次有实际副作用或读取行为的工具调用都确认；内部策略预检、等待已授权进程和停止操作不反复确认。 |
| 完全访问 | 沿用原逻辑，已提供的工具免逐次审批；仍校验目标、角色能力及强制拒绝规则。 |

“直接执行／可视终端”入口保持原位，只控制执行通道，不改变以上规则。不增加长期占位的安全侧栏或新的全局模式按钮。

启用完全访问时沿用现有确认对话框，说明目标连接、免逐次审批和无沙箱的实际权限，并保留现有偏好持久化行为。后续为“帮我批准”增加范围内自动审核时，再通过具体目录和网络授权减少打断，不改变完全访问。

没有项目目录时允许继续普通查询；直到任务需要写入，才请求选择目录。不能默认授权 `/`、用户整个主目录或所有磁盘。需要第二个目录时就地增加具体目录，不要求重新建会话。

菜单内显示简短状态，例如“本机 · 已限制在项目目录”或“远程 · 未启用隔离”。仅当探测和实际执行都满足隔离契约时显示前者。

### 3.2 后续“帮我批准”的代表性流程与打断预算

| 用户任务 | 推荐体验 | 自动模式确认预算 |
| --- | --- | --- |
| 查询文件、搜索项目、读取普通文件 | 连续返回结果 | 0 次 |
| 修改项目并运行构建、测试 | 首次授权项目范围后连续执行；缺少缓存或网络权限时合并请求所需资源 | 已授权资源内 0 次 |
| 删除明确指定的一个普通文件 | 移入系统回收站，结果给出真实可用的恢复入口 | 已授权范围内 0 次 |
| 清理一批旧文件 | 先生成确定清单，一次确认整批，显示总量和排除项 | 1 次，目标未变化时不重复 |
| 删除一个目录 | 展示目录及有界扫描得到的数量、大小；无法完成扫描时明确不确定性 | 1 次，不能因只是一个路径而当作单文件 |
| 修改范围外的普通配置 | 展示精确文件，可仅允许本次；执行后继续任务 | 1 次，不再要求同时切权限模式 |
| 删除系统关键资源 | 在当前任务中解释原因，提供可行的维护方式 | 不给无效“批准”按钮 |
| 没有隔离的远程运维 | 在已有审批位置确认本次完整命令，明确权限和影响不确定性 | 每次独立变更 1 次，不追加重复警告 |

以上预算不覆盖“每次确认”或“完全访问”；完全访问免逐次审批，强制拒绝规则仍然适用。用户拒绝后停止该操作，继续真正独立且已授权的工作，不反复询问同一个被拒绝操作。

### 3.3 审批呈现

复用现有 Agent 审批卡，不叠加一个内容相同的 Modal。只有首次范围配置等确需独立交互的流程使用共享 Dialog。

默认先显示操作、真实主机与账号、目标路径、影响范围、是否可恢复。具体命令、完整清单和策略原因在详情中查看；不可恢复性必须直接可见，不藏在详情。

按钮使用动作词，如“移入回收站”“允许本次执行”“取消”。只有普通、范围明确的资源授权才提供“本次会话允许”；永久删除、未知范围脚本、生产高权限变更不提供“以后不再询问”。默认焦点不落在永久删除按钮上。

用户说“删除这个文件”且上下文存在多个候选时，需要澄清目标；不能由模型猜测后直接执行。目标已通过选中文件或明确路径确定时不重复询问文件名。只有已授予的后端会话能力才能免审批，自然语言意图不直接生成高权限凭证。

批量操作共享一个冻结计划。审批与执行之间若新增目标、变更目标身份或扩大范围，重新展示差异；不能用一个批准覆盖随后生成的任意路径。超大或无法穷举的任务展示已知边界与未知项，不能伪造精确预览。

成功操作保留简短工具结果；仅对有即时动作价值的恢复入口给出一次 Toast，避免消息、Alert 和 Toast 重复报成功。历史工具卡仍能找到恢复入口，不依赖几秒后消失的 Toast。

## 4. 后端策略模型

### 4.1 独立维度

不要继续用单个 permission mode 表达全部安全状态。复用现有会话和目标标识，新增版本化策略快照，概念字段如下，具体 wire schema 在实施阶段确定：

| 字段 | 含义 |
| --- | --- |
| `policyVersion` / `policyRevision` | 协议语义版本与当前授权修订号，参与授权校验。 |
| `approvalPreference` | 每次确认、只读自动、范围内自动。 |
| `targetIdentity` | 冻结目标、主机身份、账号、连接代次；远端绑定可信 SSH 主机身份。 |
| `accessScope` | 可读目录、可写目录、受保护资源和明确例外；读权限也不默认覆盖凭据。 |
| `networkScope` | 允许的目的地及通道，单独配置，不随文件写权限自动打开。 |
| `executionBoundary` | 本地受限进程、远端受控执行器、无隔离执行，以及后端验证的能力。 |
| `riskFacts` | effect、分析完整性、影响范围、递归/批量、可恢复性、权限等级；不依赖单一分值。 |
| `recoveryCapability` | 系统回收站、应用可恢复、已验证外部快照、不可恢复或未知。 |

边界描述来自受信后端，不能由模型或前端参数自行声明“已隔离”。子 Agent 继承父策略与角色能力的交集，不能申请更宽权限。

### 4.2 决策顺序

按顺序返回 `deny`、`ask` 或 `allow`，附稳定原因码及用户可执行的下一步：

1. 校验输入、工具注册、冻结目标和调用者身份。
2. 拒绝不可授予的行为：已识别的灾难性破坏、Agent 修改自身安全策略或授权存储、绕过边界。
3. 确认执行通道能落实所要求的文件与网络边界；不能落实时不得声明范围内自动执行。
4. 检查资源范围、敏感性、可恢复性和分析不确定性。
5. 检查有效的会话范围授权或本次操作审批。
6. 受信执行器执行前再次校验并消费单次凭证，记录结果与恢复信息。

审批只能批准可授予的资源和操作，不能覆盖系统强制拒绝规则。解析失败、策略服务失败、授权预览缺失时不自动放行。

模型评估可以补充风险解释，不得覆盖上述确定性决策。页面、文件、终端输出、MCP 内容中的“用户已经批准”均为不可信数据。

### 4.3 操作矩阵

以下为后续“帮我批准”在具备范围内自动审核能力后的目标行为，尚未实现；“完全访问”不采用其中的逐次确认要求，只保留强制拒绝和执行边界校验。

| 操作 | 已验证的受限边界 | 无隔离执行 |
| --- | --- | --- |
| 普通结构化读取 | 范围内自动 | 仅当该结构化工具自身能落实读取边界时自动 |
| 普通结构化编辑 | 范围内自动，沿用摘要与检查点 | 工具自身能落实边界时自动，否则审批 |
| 单个普通文件移入回收站 | 可恢复删除授权范围内自动 | 仅受信删除工具可自动 |
| 递归或多个目标的可恢复删除 | 一次确认冻结计划 | 一次确认，且工具本身必须具备可靠路径校验 |
| 普通构建、测试与脚本 | 无已识别高风险、敏感资源或额外外部副作用时，可在已授权边界内自动；不保证内部删除可恢复 | 不根据命令名免审批，逐次批准；确认不能提供隔离保证 |
| 已识别的永久删除 | 单次确认；本地普通文件优先要求改用回收站工具 | 单次确认且明确无隔离，不得直接删除关键资源 |
| 越界修改 | 请求精确扩展范围，优先继续受限执行 | 确认本次操作，仍标注实际边界 |
| 凭据读取、权限变更、外部写入 | 独立精确授权；不被普通工作目录写授权覆盖 | 同样要求精确授权 |
| 已识别的灾难性破坏或安全策略修改 | 拒绝 | 拒绝；未知脚本仍存在识别局限 |

本地普通文件的专用工具首版只提供移入回收站，不新增永久删除按钮。确实需要不可恢复处理的专门场景另行授权；不会把回收站失败视为永久删除许可。

关键限制：没有隔离的任意脚本无法靠静态识别保证不访问关键资源。因此“拒绝已识别危险操作”属于风险降低，不能称为完整核心目录保护。对生产环境要求强保证时，必须使用远端受控执行器或精确的结构化运维操作；不能开放无隔离任意 shell 自动执行。

## 5. 文件删除与恢复

### 5.1 专用工具

新增模型侧 `trash_files`，输入为明确的目标列表，不接受 shell 字符串或通配符。后端完成预检、生成有期限的冻结计划并进入现有审批流程；模型不负责生成可信预览。

目标使用明确路径，结合冻结根目录按平台规范解析。检查空路径、根目录、路径穿越、系统保护资源、目录挂载点、软链接和目标身份。首版对经过软链接祖先的目标拒绝操作；删除链接本身需后续明确实现链接语义，不跟随链接删除实际目标。

仅字符串规范化或先 `canonicalize` 再删除不足以解决检查与执行之间的竞态。受信文件执行器优先使用成熟的目录句柄相对访问机制和平台 API；执行前校验目标身份。无法可靠处理的路径或文件系统不声称满足同等保护能力。

返回每个目标的实际结果，而不是批量一个布尔值：成功、失败、取消、结果不确定；包含恢复方式和可用操作。一次执行只消费一次凭证，重复请求先查询已有结果，不能重新删除相同路径上新出现的文件。

部分成功不自动回滚；展示已完成项和失败项。取消只阻止未开始的项，已经移入回收站的内容保留真实状态。预检有数量、时间和字节预算，不为删除一个大目录无限阻塞界面。

### 5.2 回收站与恢复能力

本地沿用现有 `trash` 依赖。先验证各平台能否可靠获得回收条目标识与按条目恢复：

- 支持可靠程序化恢复：显示“撤销删除”，按操作记录恢复。
- 仅能可靠送入系统回收站：显示“打开回收站”，说明从系统恢复；不显示无效撤销按钮。
- 文件系统或平台不支持回收站：保留文件，报告失败，提供明确下一步；不降级永久删除。

恢复时目标路径已存在，默认不覆盖；让用户选择恢复到其他位置。缺失、被清空或已由用户恢复的回收条目展示真实状态，不猜测成功。

回收站的清理由操作系统或用户控制，不承诺固定保留天数。操作记录只保存恢复所需元数据，文件内容不进入聊天、日志或额外明文备份。对敏感凭据文件，移入回收站不等于安全擦除，界面如实说明。

### 5.3 远程恢复

普通 SFTP/SSH 不假定存在系统回收站。首阶段远程删除必须说明永久性，完全访问以外的模式请求批准；本地回收站功能不能包装成远程恢复能力。

后续远端执行器可提供受保护回收区：限制访问权限、保留元数据、记录原始路径和目标身份；同文件系统优先原子移动。跨文件系统不能把复制后删除当成无条件可恢复移动，需要单独验证或拒绝。运行中的数据库目录不通过普通移动实现备份。

远程回收区不得由 Agent 普通 shell 清空；容量不足时阻止新操作并提供管理入口，不静默删旧记录释放空间。自动清理必须有用户预先配置的保留政策。

### 5.4 任意脚本与数据保护边界

不得自动把 `rm` 替换为 `mv`，也不设置 shell alias 假装所有删除进入回收站。Python、安装脚本、构建程序和文件覆盖都有独立副作用。

本地沙箱保护授权目录之外的数据；授权目录内的重要未提交文件、未跟踪文件、数据库和上传资源需要独立备份。现有检查点仅覆盖支持它的结构化编辑。不能用 Git 工作树、审计日志或程序退出码声称可以完整恢复数据。

## 6. 所有执行入口的边界

### 6.1 本地直接执行

接入平台原生限制，统一约束 shell 与全部子进程。允许项目目录、隔离临时目录及明确授予的缓存路径写入；其他目录默认不可写。凭据、权限配置、授权记录、恢复记录和审计数据按策略不可读或不可写。

禁止通过继承环境中的密钥、SSH agent、Docker socket、任意 IPC、桌面自动化、特权辅助程序或宽泛网络授权绕过边界。平台支持矩阵必须列出这些限制，不仅验证文件路径。

沙箱不可用时提供“修复隔离环境”或“本次无隔离执行”的明确选择；后者仅对可授予的精确操作生效，始终需要确认。强制隔离的主机策略不提供后者。不静默重试，不永久记住无隔离通配授权。

### 6.2 可视终端

已有交互式 shell 不能事后因为贴上标签就变成沙箱。首版将现有 `boundTerminal` 视为无隔离通道，完全访问免逐次审批，其他模式逐次审批，继续保留 lease、接管和不确定状态处理。

用户切换到直接执行后，明确提示其使用独立进程及冻结目录，不继承现有 alias、函数或未导出变量。不得为了避免确认偷偷切换通道。

`write_terminal_input`、REPL 输入、后台进程 stdin 也是执行入口：仅可向所属已授权进程发送符合原授权协议的数据；任意代码输入重新审批。Agent 不能借“发送文本”往用户的 unrestricted shell 绕过命令策略。

### 6.3 远程 SSH

按真实能力分为远端受限执行与无隔离执行。使用专用低权限账号、远端执行器和服务器端文件/网络权限建立受限边界；SSH 身份验证成功不代表限制已经生效。

root 和宽泛 sudo 权限不进入自动任意命令路径。常见维护动作后续通过明确参数、固定实现的专用工具开放，例如重启指定服务；不允许参数夹带任意脚本。

跨主机、重连导致身份或连接代次变化时重新校验授权。生产主机由用户配置，不让模型自行决定哪些主机属于测试环境。

### 6.4 MCP、子 Agent 和其他文件入口

MCP 的工具自述与只读注解只作为输入，不作为可信安全证明。未配置可信操作边界的 MCP 调用保守审批；独立 MCP 服务的实际权限由该服务限制，不能宣称本地沙箱覆盖远程服务。

子 Agent 共用父级策略边界与预算，统一走审批。文件写入、补丁删除、传输覆盖、恢复检查点等都进入相同资源策略；不能只防 `trash_files`。SFTP 人工操作的现有 UI 不在本次重设计范围，Agent 使用相关后端能力时仍需携带并校验授权。

## 7. 授权生命周期、竞态与审计

沿用当前 `call_digest`、冻结 target、短 TTL 与 `max_uses = 1`，补充绑定策略修订号、执行边界和删除计划标识。批准命令文本不意味着批准随后被替换的脚本文件或目标；可冻结的计划与内容记录摘要并重新校验，任意脚本最终仍靠执行边界约束。

用户收窄授权时使旧凭证失效并停止新调用；对仍运行且权限过宽的进程请求终止整个进程组。不能即时确认停止时显示结果不确定，不能声称已经撤销其副作用。扩大范围只能由用户界面或受信管理策略触发。

审批后目标变化、目录被替换、计划过期、断线、应用重启或持久化失败都不自动重放变更。恢复会话先核对执行记录，无法确定是否已执行时进入人工处理流程。

记录调用者、主机、操作、策略理由、授权来源、结果及恢复标识，继续沿用脱敏和输出限制。操作前记录意图，完成后记录结果；记录不可用时不启动新的破坏性操作。文件变更与日志无法组成跨系统原子事务，必须显式支持“执行结果待核对”。

## 8. 兼容与最小界面范围

`fullAccess` / `operator` 保留原持久化语义，旧会话继续免逐次审批，不要求重新选择权限。新增的原生强制拒绝规则独立于审批偏好。

`autoApproveReadOnly` 和 `requestApproval` 的偏好保留，额外安全底线统一生效。后续为“帮我批准”增加自动审核能力时使用明确版本的策略字段，不借用 `operator` 表示范围授权。

本次不迁移或重置完全访问偏好。未来其他策略迁移只在确有必要时提示一次；目标身份校验和原菜单中的权限切换继续保留。

允许的 UI 修改仅限现有权限菜单与确认对话框、审批卡、工具结果的恢复入口。沿用共享组件和 i18n，保持现有布局与操作位置。窄面板中长路径可换行、详情可滚动、确认按钮始终可见；不新增固定警告条挤占终端或聊天区。

## 9. 实施阶段与交付门禁

| 阶段 | 交付内容 | 对用户的变化与门禁 |
| --- | --- | --- |
| A：统一底线 | 原生/MCP/终端保持一致的权限模式语义；完全访问免审批，其他模式精确授权；新增稳定拒绝原因 | 保留完全访问习惯，增加关键资源防护，不宣称已完成沙箱。相关真实执行测试通过。 |
| B：可恢复删除 | 本地 `trash_files`、冻结计划、逐项结果、平台恢复能力探测、现有审批和工具卡接入 | 单个普通文件在已授予可恢复删除范围内不再反复确认；失败不永久删除；真实回收站往返验证。 |
| C：范围内自动执行 | 本地生产沙箱、独立读写与网络范围、环境/IPC限制、撤销与平台支持矩阵 | 已授权项目编辑和测试可连续运行。每个平台独立验收，缺失能力不自动降级。 |
| D：远端受控执行 | 专用账号/执行器接入、远端能力验证、受保护回收区、精确运维工具 | 具备远端隔离时提供范围内自动化；普通 SSH 保持真实的逐次审批语义。 |

A 是风险修复阶段，不能把“变成大量审批”作为最终完成状态。面向日常本地自动化的完整交付至少覆盖 A–C，并通过下节的使用体验门禁。D 单独按服务器端部署能力交付。

## 10. 验收标准

### 安全与正确性

使用真实临时目录、真实进程、系统回收站和隔离 SSH 测试环境；不得在宿主机真实核心目录上运行破坏性测试，不以 mock 替代实际隔离验证。

- 在临时隔离文件系统中验证根目录、保护目录、路径穿越、软链接祖先、目录替换、挂载点和权限变化。
- 验证 shell、Python、子进程、重定向、脚本及命令替换无法写出已授权边界；验证凭据、网络、socket 与提升权限通道。
- 同一操作通过 direct、PTY 输入、stdin、MCP、子 Agent、补丁删除等入口不能绕过适用策略；外部服务无法落实的边界如实报告。
- 审批后替换参数、目标、策略或计划，凭证失效；消费后重放无副作用；拒绝后不换工具重试。
- 回收站失败保留原文件；批量部分失败、取消、断电窗口、恢复同名冲突、回收站被清空均返回真实状态。
- 停止与超时不能承诺回滚；不确定状态不自动重试。日志或恢复记录不可用时不继续危险操作。
- 平台不支持、缺失依赖、SSH 断线、主机身份变化和升级旧会话均不得放宽权限。

### 使用体验

- 预先授权项目范围后，完成“读取→编辑→构建→测试”标准流程没有额外权限确认；只在真实新增资源需求时请求授权。
- 同一冻结批量删除计划只确认一次，后台预检不额外触发确认；计划变化时解释具体差异。
- 单个明确普通文件的可恢复删除在已授权范围内自动完成；用户能从结果找到有效恢复入口。
- 没有目录绑定也能做普通查询；需要写入时原地授权后继续，不丢失任务上下文。
- 审批没有重复 Modal，成功没有重复 Toast；等待状态可取消，失败给出明确下一步。
- 宽、窄 AI 面板实际渲染验证：主机、路径、不可恢复提示、确认按钮清楚可见；键盘与焦点可用；中英文文案语义一致。

测试与指标使用本地可复现流程统计确认次数、重复请求和恢复结果，不额外采集用户文件内容或引入遥测。纯文档设计阶段不执行破坏性验证；实现时按影响范围运行 Rust 测试、TypeScript 构建与就近 UI 回归。

## 11. 实施前必须验证的技术事项

以下不改变产品方向，属于对应阶段的技术门禁：

1. 当前 `trash` 版本各平台的稳定恢复 API、文件系统限制及取消能力。结果决定显示“撤销删除”还是“打开回收站”。
2. 现有测试沙箱转生产后的平台支持、进程树、环境与 IPC 隔离能力。不能只移除 `cfg(test)` 就宣布完成。
3. 基于目录句柄的安全删除与系统回收站 API 如何衔接；若平台不能闭合竞态窗口，必须限制支持范围并记录边界。
4. 远端执行器的部署、升级、身份验证和权限撤销方式。未部署时不展示已隔离。
5. 跨版本会话事件与 native contract 的迁移门禁，确保旧客户端无法按旧 full-access 语义执行新授权。
