# macOS 原生终端六期验收计划

Windows 正在由另一台电脑独立进行原生终端验收。本计划仅负责本机 macOS arm64 的验收，两端分别记录源码、制品、运行结果和结论。共享代码发生变化时核对影响并补验，不修改或代替 Windows 验收结论。

覆盖四个本地 PTY 组合：Zsh 5.9 / ZLE 5.9，以及 Bash / Readline 4.1 / 6.0、4.4 / 7.0、5.3 / 8.3.6。制定日期为 2026-11-07，时区 Asia/Shanghai。

## 标准与证据

- [统一验收清单](agent-terminal-input-acceptance-checklist.md)规定 A01–E08 的标准和平台适用范围。本计划调整执行顺序，不删减标准，也不将一个子项通过计为整行通过。
- [macOS 验收记录](agent-terminal-input-macos-acceptance-2026-11-06.md)保留历史批次、实际结果和证据索引。每次继续执行前读取最新台账，不把历史通过当作当前代码通过。
- [NIP 契约](../../protocol/agent/runtime/native-input.md)和[显示契约](../../protocol/native-input-display.md)说明当前实现、资源入口及输入和显示的边界。
- 本机证据统一放在 `.artifacts/tests/agent-terminal-input/`，构建及资源产物沿用仓库规定目录；计划和结果索引留在仓库文档中。

## 分期安排

各期分别记录检查或用例清单、源码与制品身份、实际结果、证据路径和剩余阻塞。阶段有阻塞时可以继续其他独立项目，但该阶段保持未完成。已有证据先核对适用性，只重验受影响范围。

| 阶段 | 范围 | 完成条件 | 前台安排 |
| --- | --- | --- | --- |
| 第1期 固定当前基线 | 冻结完整源码、依赖、配置和资源；重建失效资源；审查 Windows 与共享终端改动的 macOS 影响；完成相关编译、测试和严格检查 | 源码、资源及候选制品对应一致，检查清单与实际执行一致，所有本期必需检查通过；后续补验范围明确 | 不启动新的前台 App、模型或手工交互验收 |
| 第2期 日常终端与显示 | 四组合普通编辑和粘贴、Tab、搜索、正反向选择与复制、Unicode 游标、动态尺寸、历史视口、默认显示模式；实际 TUI 和 raw 拒绝；对应 D01–D05、E02、E04 范围 | 逐项取得真实输入、输出、显示及交互证据；Chromium / WebKit、默认 / WebGL 与原生 WebView 分别记录；各条款全部满足后才关闭 | 集中安排前台时段，必须由真实鼠标、键盘和系统剪贴板完成的项目单列 |
| 第3期 提交安全与恢复 | 不可变源码、审批与冻结目标；单次提交及重复调用；取消清稿、人工争用、多 Agent、任务切换；崩溃重启、断线、超时与结果不明围栏；重点对应 B03、B05、C01–C07 | 各关键切点有直接证据；取消后 Enter 不执行残稿；重复调用不增加可能提交；未确认清理或结果不明时恢复门禁有效 | 真实 App 的崩溃、重启、争用和接管在明确安排的时段执行 |
| 第4期 Shell 历史与后台作业 | 输入及 8192 字节边界、父 Shell 环境、启动文件、退出状态、历史配置、双进程共享历史、后台输出与轮询/停止、临时脚本；重点对应 B01、B04、B06–B08 | 四组合的实际语义、后台身份、Started / Settled、输出尾部及脚本引用逐项对应；未终止或结果不明的文件继续保留引用 | 组件与静态检查分别记录；实际 App 和模型矩阵另安排前台时段 |
| 第5期 资源异常与正常清理 | 错误摘要、未知构建、错误平台、缺失符号、实验配置隔离、随包资源与实际加载；确认本批临时脚本、CredentialRef、进程、目录与端口的归属并通过正常 API 清理；重点对应 A03、A04、E07 | 异常资源不能获得能力；只清理确认归本批次所有且允许清理的资源；清理结果有独立核验 | 资源构建先行；实际 App 加载和依赖 App 的正常 API 清理在安排的时段执行 |
| 第6期 最终核验与封存 | 复核全部必测清单与适用性；完成最终质量门禁、SSH 历史超时项审定、源码及制品独立归档、解包与摘要核验；重点对应 A05、E05、E08 | 本机适用的必需条款全部闭合，证据与最终源码/制品匹配；未覆盖环境和未决操作明确保留；交付最终台账、证据索引及准入结论 | 仅对必要的受影响运行项安排前台复核 |

## 执行与交接规则

1. 每次开始先检查 `git status --short`、最新提交和完整源码差异。保留另一台电脑及其他任务的改动，不恢复旧代码，不批量格式化 Windows 验收文件。
2. 每期建立可追溯的输入清单。运行期间共享代码变化时，原冻结结果保持原范围；新批次重新冻结并说明受影响项，不能直接给旧结果贴上“当前通过”。
3. 前置失败时停止其依赖项。保留原失败、日志、账本和制品；修正后使用新记录复验，不覆盖原结果、不重放结果不明的操作。
4. 真实 App、浏览器显示、模型及人工交互仅在用户明确安排的时段执行。已有授权按本会话有效范围使用，前台开关只传给该次验收命令，不写入默认脚本或用户配置。
5. 不使用 mock 或伪造回执，不修改原模型参数、额外解码模型源码或放宽逐字节断言。程序驱动的显示检查不能代替必须由真实人工操作完成的条款。
6. Bash 本地矩阵 18 项与完整本地 / SSH 矩阵 39 项分别列出。其余 SSH 项记录环境及未完成范围；不得以本地结果关闭要求完整矩阵的条款。macOS、Windows、Linux / SSH 结果不互相替代。
7. 严格 Unicode 模型子项按用户决定暂缓；Zsh、Bash 5.3 已记录的模型 TUI 参数准备拒绝继续留证。可以推进其他独立项目，相关必需项未补齐时不宣告整体验收完成。
8. 每期交付一份结果摘要和证据索引，分别列出通过、失败、待验、不适用与跳过。统计按统一清单的完整条款计算，不以测试条数、操作次数或阶段数换算整体完成百分比。
9. 保持生产编辑器准入关闭，不自动创建 commit、tag，不推送或发布。第1期完成只关闭第1期 goal，不关闭完整原生终端验收 goal。
