# Windows Agent 沙箱后续研发计划

制定日期：2026-10-10。适用范围：Windows 本地 Agent Shell。基线以 [阶段 A 最新交接](agent-shell-sandbox-windows-stage-a-handoff.md)、[A/B 验收表](agent-shell-sandbox-windows-ab-checklist.md) 和 [首版设计](agent-shell-sandbox-windows-v1-design.md) 为准。

## 当前判断

Windows 仍处于阶段 A 隔离原型验证，NO-GO；生产能力 unavailable。专用账户、LPAC 身份、Job、有限文件与网络拒绝、固定工具运行及部分精确恢复已有实机证据。冻结依赖的完整 SYSTEM 物化 system-r3 已完成：43290 项实际创建并全部退役，677 页终态核验通过，namespace 已不存在。另有失败物化独立 SYSTEM 恢复证据。这些结果尚不代表完整项目已在 LPAC 下运行。

源码 SYSTEM 完整物化已确认 883 个对象全部创建并退役、14 页终态一致；全量检查点之后受控失败的独立 SYSTEM 恢复也已通过。这不覆盖进程崩溃或重启。源码与依赖组合的普通进程物化曾因回收站操作中止而失败，旧残留保持隔离；后续磁盘检查点正常退役复测及释放原 inventory 后的磁盘页故障恢复均已通过，分别耗时 3233.36 秒和 3438.69 秒。组合恢复仍在同一普通测试进程内，不替代独立 SYSTEM 恢复；原生 Project admission 尚关闭。实际 LPAC 项目工作负载仍待验收。默认 LPAC DNS 返回 87 未构成明确权限拒绝；internetClient 诊断存在系统服务代办绕过。历史加载 hive 债务尚需闭合。正式 broker、typed IPC、账户池和产品接入均未完成。

## 研发顺序与出口

| 顺序 | 研发工作 | 交付与验收门槛 |
| --- | --- | --- |
| A0：收束当前事务 | 跟踪原物化事务到终态；失败时独立恢复原 fixture；核验对象、分页、服务及 namespace。安排历史 hive 的重启后精确恢复验证。 | 每项资源有归属和最终 OS 证据；未知债务继续封锁。全量创建数与退役数分别报告，不能用 planned 退役数量替代实际创建数。 |
| A1：网络方案决策 | 固定默认 LPAC 能力集合；诊断 DNS 同步、异步、缓存与服务代办；补接收端正反对照及根/后代矩阵。若无法闭合，重新评审网络实现与工具支持范围。 | 声明范围内 v4/v6、TCP/UDP、DNS、私网、回环、入站和服务代办均有可解释的允许/拒绝证据。87、超时或零流量不单独算拒绝；不得通过扩大能力掩盖绕过。 |
| A2：真实项目与对象边界 | 先完成冻结依赖的全量创建/恢复与资源预算，再在专用账户 LPAC 下跑 ShellSpan TypeScript、Vite、前端测试；验证 Git/Node/PowerShell 声明范围。补只读/工作区、敏感文件、ADS、hardlink、short-name、reparse、跨卷与并发替换反例。Rust 工具链独立扩展验证。 | 真实工具根及后代身份/Job 正确，允许产物可重开，禁止路径实际拒绝，宿主凭据不参与；产物、执行结果与恢复回执匹配冻结输入。普通宿主构建成功不能替代此验收。 |
| A3：异常与安全矩阵 | 注入创建前、分页发布、授权、启动、撤销、profile 回收等故障窗口；覆盖取消、重复取消、断连、宿主/服务崩溃和重启；补跨槽、凭据与进程句柄负例。 | 未知状态不重放；只恢复精确拥有资源；树停止前不解除 SID 封锁；重启后权限、服务、账户/profile/hive 和网络规则均有核验。A1–A8 全部按范围签收，才关闭阶段 A。 |
| B：正式基础设施 | 先做最小设置程序与已认证本机 broker/typed IPC，再实现可信事务 journal 与独立恢复，最后做账户池 generation/租约/复用。 | 无任意高权限执行接口；版本、边界、预算、重放、取消与调用者校验均有真实 client/server 反例；UAC 取消、策略冲突和保存失败安全收束；脏槽不可复用。B1–B8 全部验收。 |
| C：产品接入 | 接入 NativeAdapter/process worker、默认 Direct、模型回合、审批、取消、重启恢复及能力摘要；同步 Rust command 注册、TS IPC 类型和协议。 | 无静默回退宿主执行；真实模型端到端验证；目标/策略变化使旧授权失效；恢复债务阻止派发；双语 UI、键盘/焦点和失败路径通过。初期资源扩展继续拒绝。 |
| D：发布验收 | 在明确支持的 Windows 版本/账户/工具组合完成干净安装、升级、卸载、恢复、长时与并发测试；审核安装包、权限与支持说明。 | 最终修订的前后端检查和实机矩阵通过；忽略/延期项明确披露；只开放已验收范围。文件 read grants、网络代理与缓存写入另立阶段。 |

## 排期方法

按验收门槛排期，不以原型代码量估算完成百分比。下一轮先交付 A0 终态报告与 A1 网络决策，随后依据真实项目兼容结果细化 A2/A3 工期。网络方案、工具兼容和重启恢复尚有不确定性，当前不承诺固定发布日期。

每个工作包绑定代码修订、固定 fixture、测试结果、原始失败记录和最终 OS 核验；状态统一为未开始、进行中、通过或阻塞。单元测试、普通宿主测试、SYSTEM 物化和实际 LPAC 执行分别列示。A 未签收前不推进正式 B 实施；可整理协议需求与接口草案。

当前 Windows 机器用于连续诊断；涉及崩溃和重启的扩大矩阵优先迁移到可恢复快照的专用 Windows VM，最终仍在支持的实机环境复验。保留原未知债务，不按进程名或路径猜测清理。
