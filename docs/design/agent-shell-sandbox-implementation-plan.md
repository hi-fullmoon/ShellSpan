> 状态（2026-10-07）：阶段 1 已实施；macOS 常规原生 Direct 经真实预检报告 `partial`，资源授权、真实依赖下载、会话隔离及正常资源清理已有对应证据。阶段 2 正补应用退出时阻止新派发的门禁；阶段 3 正补策略切换、配置记忆和授权审计；阶段 4 正接入真实 Mac SSH 受限控制链；阶段 5 保留逐项验收，不把子项通过视为整体验收。Windows 实机、普通可视终端与未接入工具不因此报告受限可用。[阶段 0](agent-shell-sandbox-phase-0-acceptance.md) 的对象隔离反例仍为首版已知限制。

## 1. 用户策略

2026-10-06 用户确认首版改为常规原生进程沙箱：提供工作区写入、敏感路径读取和网络限制，保留审批、取消与审计；明确记录既有硬链接别名、宿主同账户恶意并发修改及平台生命周期等限制，不再承诺完整文件对象隔离。macOS 使用 Seatbelt，保留宿主工具链和项目目录；不采用 Endpoint Security 服务，不新增其特殊权限或完整磁盘访问要求，不迁移到 Linux。此决策覆盖旧设计中的完整对象 provider 前置条件，但不允许隐藏限制、模拟成功或无限制回退。Windows 后续按同一常规契约接入并实测。

随后用户明确要求支持项目 .env.local 读取：当前基础策略允许只读访问冻结项目根目录的该文件，其写入和其他敏感拒绝仍保留。真实沙箱内 pnpm build 已退出 0，7 项相关测试通过。现已另行接入一次／当前会话的项目文件读取、明确缓存目录读写、公网 TCP 目标和 Node 本地服务授权；适用范围及未完成项见阶段 3 记录。

保留现有审批模式，独立增加执行策略。审批决定是否执行，沙箱决定获准后能够访问什么；选择完全访问不能隐式修改审批模式。

| 策略 | 文件权限 | 网络权限 | 典型用途 |
| --- | --- | --- | --- |
| 只读检查 | 指定项目和必要系统运行文件可读；仅允许运行所需的最小临时写入 | 默认禁止；可授权指定目标 | 代码阅读、日志检查、故障分析 |
| 工作区执行 | 项目可读写；独立临时目录和明确列出的缓存目录可写；其他资源按允许列表只读 | 默认禁止；需要时按目标授权 | 修改代码、构建、测试、运行开发服务 |
| 主机运维 | 使用目标账户已有权限；保留原生工具校验、取消与审计 | 使用目标账户已有网络权限 | SSH 运维、部署、系统配置 |

“主机运维”必须标明“未启用文件与网络隔离”；它不代表 root 权限，不自动授予 sudo，不自动开放结构化工具的路径限制。只读检查允许写最小临时资源，因此界面描述为“保护项目和主机文件不被修改”，不能声称进程完全没有写入。

新建本地项目会话默认工作区执行；没有确定工作区时要求选择目录后才启动该模式。新建远程运维会话默认主机运维，并沿用现有审批模式。远程只读检查、工作区执行仅在远端具备经过验证的执行后端时可选。历史会话保留原行为并准确标记；不静默收紧、放宽或转换会话策略。

## 2. 使用便利性与授权流程

- 会话设置提供上述三个选项，摘要显示执行主机、项目根目录及网络状态。详细目录与目标列表放在展开内容中；不改动其他页面。
- 工作区执行与现有 scopedAutopilot 组合时，在沙箱内允许普通修改、构建和测试自动执行；敏感读取、破坏性操作和外部副作用保留审批语义。命令分类服务于审批，不能代替沙箱。
- 越界授权直接显示需要增加的资源，例如“允许写入此缓存目录”或“允许访问此下载站点”。提供本次执行、当前会话两种范围，默认本次执行；一次批准同时满足该操作审批和资源扩展，避免重复弹框。
- 只有具备明确越界证据时才提出权限扩展。普通非零退出、编译失败和模型解释不能自动归因于沙箱，也不能据此自动提升权限。
- 不自动重试已执行或状态不确定的命令。扩权后，只有确认尚未执行的操作可重新派发；其他操作先检查副作用，再形成新的执行请求。
- 项目可记忆用户确认过的默认策略和非敏感目录配置；连接可记忆运维策略。保存配置不等于保存授权：会话授权在关闭、重绑、账户变化及恢复时失效。
- 策略只在空闲且没有受影响后台进程时切换。用户撤销会话授权时停止依赖该授权的进程树，再更新策略；无法确认清理完成时暂停新执行并提示处理。

## 3. 执行边界

### 文件与凭据

工作区根目录由会话冻结并在实际执行主机规范化。写权限覆盖项目和专用临时目录；缓存按实际工具链配置，不默认开放整个用户目录。必要运行文件可读，用户私钥、ShellSpan 凭据与其他敏感目录默认不可读。拒绝范围优先于允许范围；项目内敏感文件同样遵循敏感读取规则。

Shell 的已声明路径限制由系统后端执行；结构化文件工具继续执行自身路径契约并交叉检查会话策略。正常路径读写、符号链接行为、子进程继承与后台控制必须验证，不得通过命令字符串分类代替隔离。硬链接别名及宿主同账户恶意并发修改等既有反例保留为明确能力限制，不据此宣称对象级保护，也不重试此前被安全检查中止的反例。界面、模型上下文和报告必须使用同一真实能力描述。

清理继承环境，只传入工具运行必需的变量。模型 API 凭据留在应用侧，SSH 凭据留在连接层，默认不注入 Shell。工具确需凭据时，通过明确授权的代理或 credential reference 提供，并限制目的与生命周期。

### 网络

禁止网络必须约束任意程序及其子进程，不能只拦截 curl。指定目标授权包含协议、主机、端口及重定向规则；仅把 HTTP_PROXY 传入环境不构成隔离，必须阻止进程绕过代理直连。DNS、IPv4/IPv6、localhost、Unix socket、SSH 转发及云元数据访问分别定义边界。

开发服务通过独立“本地服务”授权开放指定监听地址和端口，配合现有结构化 probe_http 验证。默认不监听所有网卡，不把允许监听等同于任意外连。包管理器下载可能涉及多个源和重定向；审批展示实际目标集合，不因下载失败开放整个网络。

### 本地、远程与可视终端

受限 Shell 经统一沙箱执行入口进入 Direct；后端执行成功后才报告沙箱有效。不能把独立进程、cwd 或 worktree 当作隔离证据。平台后端使用成熟系统能力，不自行实现沙箱运行器或脆弱协议解析。

用户已有可视终端通常未被隔离，不能注入受限会话命令。选择受限策略时在会话启动前明确使用后台执行；当前可视会话切换必须先空闲并确认执行方式变化。后续如需沙箱可视终端，另行实现从启动时已受限的专用 PTY，不复用用户原终端。

远程沙箱在远端实施，本机隔离不能保护 SSH 目标。第一阶段远程主机运维保持现状；远端受限模式在专用执行后端具备文件、网络、取消和结果证据后再开放。不得在用户服务器自动安装依赖、修改安全配置或创建特权服务。

MCP、SFTP、部署与其他原生工具不是 Shell 子进程，不自动受 Shell 沙箱保护。会话授权协调器按各工具实际能力校验；不能实现对应限制的工具在受限策略下拒绝或要求显式切换，不能成为越界替代通道。

## 4. 后端契约

每次调用携带冻结的目标身份、策略版本、规范化根目录、读写允许与拒绝范围、网络授权、有效期和授权来源。子 Agent 继承不大于父会话的权限，不通过委派扩大范围。

后端报告文件限制、网络限制、进程生命周期控制各自的有效状态，以及 full / partial / unavailable 和具体缺口。已知路径别名或生命周期边界须报告 partial，不能隐藏成 full。具备并经实测的常规路径/网络后端可以按本版契约执行并准确展示剩余限制；缺少本版必要控制或启动失败时拒绝派发。不能仅因系统为 macOS 或存在 sandbox-exec 就报告可用，受限请求不能静默回退无限制执行。

审计记录策略、授权变化、执行主机、执行方式、拒绝原因与结果，按现有设施脱敏。工具结果与模型提示使用同一份后端策略事实，不由 UI 推断有效能力。

## 6. 交付顺序与完成标准

先完成 macOS 本地工作区沙箱与便捷授权，再按同一契约完成 Windows 实机验收；远端受限执行另行验证。每个平台独立通过门禁后才标记可用，不以其他平台成功代替验证。Windows 验证暂缓不妨碍 macOS 实施，也不表示 Windows 已通过。
