# Petdex 联动完善实施计划

日期：2026-09-29  
状态：阶段 0–5 本轮 SSH/SFTP/AI 与通用可靠性范围已完成，实现、回归与核心真实场景逐项证据见[最终审计](petdex-integration-acceptance.md#阶段-5-最终审计)。真实业务failed→waiting、取消、持续开启重启恢复、关闭/退出残留均已补验。非独立原生复演的分支与协议限制单独列明；部署继续延期。

## 1. 目标与边界

将 Petdex 联动完善为 ShellSpan 的任务状态提醒，本轮覆盖 SSH、文件传输和 AI 任务。优先解决状态准确性、等待用户操作提醒、连接诊断和恢复行为。根据用户最新要求，部署来源、部署分类和部署生命周期全部延期；保留规划，不属于本轮完成门槛。

- 保留总开关，默认关闭；关闭期间不读取 Petdex 令牌、不发送请求。
- 对外请求仍只包含有限动作状态和持续时间，不发送任务 ID、主机、路径、文件名、终端内容、AI 内容或自由文本。
- UI 修改只限设置页 Petdex 区域，复用现有组件，不改变终端、文件管理、AI 和部署页面布局。
- 不实现桌宠反向执行命令、自动审批、自动启动或安装 Petdex，不引入远程服务地址配置。
- 不自动提交、打标签、推送或准备发布。

## 3. 固定行为

### 3.1 动作映射

| 业务状态 | 动作 | 结束方式 |
| --- | --- | --- |
| SSH 正在连接 | `waiting` | 连接结束后重新仲裁 |
| SSH 连接成功 | `waving` | 约 1.2 秒后重新仲裁 |
| SSH 异常失败或断开 | `failed` | 约 2.5 秒后重新仲裁 |
| SFTP、AI、部署正在执行 | `running` | 所有适用活动结束后重新仲裁 |
| AI 等待审批、等待回答；部署等待审批 | `waiting` | 用户处理、取消或任务终止后重新仲裁 |
| SFTP、AI、部署最终成功 | `jumping` | 约 1.2 秒后重新仲裁 |
| 业务最终失败 | `failed` | 约 2.5 秒后重新仲裁 |
| 用户取消、主动断开 | 不生成结果动作 | 移除对应活动后重新仲裁 |
| 无活动 | `idle` | 新活动到达 |

内部重试失败不等于任务最终失败；审批拒绝若业务定义为取消，不映射为失败。部署恢复门禁和状态未知必须按真实领域语义单独确认，不能直接映射为成功或普通运行。

### 3.2 仲裁与生命周期

优先级：失败短提示 > 等待用户操作 > 成功短提示 > 正在执行 > SSH 正在连接 > 空闲。

- 活动以业务来源和运行标识区分；AI 使用一次实际运行或回合的标识，不能仅按可重复使用的会话 ID 去重。
- 结束事件只移除对应活动；重复和过期事件不得清除新运行。
- 成功、失败提示按原始发生时间计时；覆盖期间继续计时，过期后不补播。
- 批量传输优先复用已有批次 ID，不以文件名或时间猜测批次；没有父子关联时不新增脆弱的推断逻辑。
- 测试动作使用独立预览槽，不能清空业务提示。失败和等待用户状态优先于预览；预览被覆盖时明确提示测试请求成功但动作被任务状态覆盖。
- 启用、重新连接和开启分类时同步当前活动，不补播历史终态。
- 关闭分类时立即移除该来源的仲裁贡献；关闭总开关时取消请求与后台恢复工作。

### 3.3 连接与偏好

连接状态区分：已关闭、正在检测、已连接、未检测到凭证、无法连接、认证失败、请求被拒绝、凭证不可读取或格式异常。展示文案通过双语 i18n 映射，不能直接显示内部枚举。

诊断快照包含连接状态、有限错误原因、当前目标动作、最近成功通信时间和单调递增修订号。前端只接受更新的快照，避免初始化读取覆盖后到事件。最近成功通信时间不表示桌宠动画已被肉眼确认。

保留已有总开关；分类默认 SSH/SFTP 开启，新增 AI/部署关闭。分类偏好在总开关关闭时仍可保存，但不得启动通信。持久化成功状态以后台确认结果为准，保留现有串行配置和失败回退语义。

| AI（本轮） | 等待原因、继续执行、最终成功/失败、取消、恢复 |
| 部署（延期） | 等待原因、继续执行、最终成功/失败、取消、恢复、父子结果去重；不纳入本轮门槛 |

| 实际显示 | 代表性宽窄工作台容器、控件等高、图标间距、展开诊断后无溢出 |

先运行修改范围内测试，再执行相关完整检查。以下为已有命令，新测试按实际位置纳入：
