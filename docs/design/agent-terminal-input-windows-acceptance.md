## 批次运行规则

1. 先列阶段、要求 ID、宿主、正/负/故障子案、实际期限及必需证据；记录未执行、阻塞、跳过和人工交接。
2. 新批次使用新的源码/资源/应用包身份和独立 data、HOME、WebView 目录。源码与实际运行 PE、已加载模块、程序集及浏览器均核对摘要；只读索引不得改写。
3. Windows 原生 App 串行。复用包须匹配原制品和冻结控制器、源/索引、依赖、资源、CSP、端口及安装路径；活动或终止不明的批次不能复用，也不终止其他批次。
4. 模型原始参数、准备参数和审批参数逐字核对。执行、模型请求、审批、普通命令和未知次数分别计数；无法证明的 HTTP 或执行次数保留未知。
5. 成功案验证一次接受和一次预定效果；提交前拒绝/取消为零；不明保留门禁，真实匹配结束/清稿后才更新事实。复验新建身份，不覆盖旧失败。
6. PID 必须结合 exe 与创建时刻或原阶段起止时间判断。封存后核对原始记录、资源、资产和实际 PE；进程/终止状态未确认或封存后漂移时停止归档，不强行卸载。
7. 发布、安装、运行、清理、卸载及包复用分别记录。只读列举/核验不算真实 App；包普通子案不能替代模型、完整 B/C/D/E 父项或随包重建。

Windows 构建/测试子进程应按当前 `rust-toolchain.toml` 固定已验证的 MSVC 工具链并记录 `rustc -vV`；历史验证使用 `1.95.0-x86_64-pc-windows-msvc`。不要为测试修改系统默认工具链。每条命令先持久化实际退出码，再执行汇总断言；完整报告绿色和汇总进程失败分别留证，不补造丢失退出码。
