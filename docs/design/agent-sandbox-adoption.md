# ShellSpan Agent 沙箱实施计划

基线为 `6638bfc5`。桌面交付平台为 Windows 和 macOS。本地 Direct 先在 macOS 的受管工作区中验收 `nono`，Windows 单独选择并验证原生后端。Linux 容器结果用于验证沙箱机制和 Direct 进程管理。远端可见沙箱终端作为后续独立执行后端，优先验证 OpenSandbox 的 PTY。

## 配置与执行约定

沿用「设置 → AI → 终端 Agent → Agent 沙箱（实验性）」及其持久化配置 `ai.agentSandboxEnabled`，默认关闭。开启总开关后，再由用户明确选择使用沙箱的本地会话或远端连接。执行前由 Rust 解析有效策略，审批继续按当前权限模式判断。总开关、选定后端、工作区、策略版本或目标身份与审批时不一致时，拒绝尚未发送的调用，并要求重新授权。

| 目标 | 关闭总开关 | 开启总开关 |
| --- | --- | --- |
| 本地 Direct 普通会话 | 现有 Direct 路径 | 现有 Direct 路径 |
| 明确选择本地 Direct 沙箱的会话 | 拦截需要沙箱的调用 | 仅通过已验证的本地后端执行 |
| 普通本地或 SSH 可见终端 | 现有终端路径 | 现有终端路径。会话要求沙箱时，在申请终端输入权前拒绝向普通 PTY 提交 |
| 已配置 Bubblewrap 的 SSH 连接 | 保留配置并拦截需要沙箱的调用 | 使用现有 SSH 子系统及沙箱 SFTP |
| 已配置 OpenSandbox 的会话 | 拦截创建及新的 Agent 操作，并保留已有会话的停止、清理能力 | 在沙箱内创建和使用专用 PTY |

总开关和策略变更在最终派发时复核。已启动的一次性命令按启动时的策略结算，用户可通过原有入口停止。持久沙箱终端绑定启动时的策略与终端代次，新输入需要通过当前策略复核。策略变更后通过新代次取得输入权。

当前接入点为 [Agent 原生工具运行时](../../src-tauri/src/agent_runtime/native/runtime.rs)、[本地进程启动与管理](../../src-tauri/src/agent_runtime/native/process.rs)、[远端 Bubblewrap 策略和结果](../../src-tauri/src/remote_sandbox.rs)及[可见终端协议](../../protocol/agent/runtime/terminal-protocol-rfc.md)。

## 阶段一：验证本地启动器

1. 在 macOS 和 Linux 上使用隔离测试目录运行 `nono`。以单次受管命令和子进程树为单位，验证宿主工作区、工具链、私有临时目录和退出状态。记录所用版本、许可证、平台及 Linux Landlock 实测能力。原生 Windows 待有可验证的后端后开放。
2. 验证嵌入方式。候选实现是随 ShellSpan 打包的 Rust 启动器，在启动器自身施加 `nono` 策略，再执行 Rust 后端提供的程序与参数。Tauri 主进程继续管理子进程。验证收紧权限的调用只发生在启动器中、进程组可停止、退出码和 stdin/stdout/stderr 可传递。[nono Rust API](https://docs.rs/nono/latest/nono/)
3. 用独立安装、固定版本的 `srt` CLI 运行同一批命令，通过 `--settings` 提供由测试程序生成的绝对路径配置。比较文件访问、网络策略、标准流、取消、启动时延及依赖安装。报告记录哪些能力能直接复用、哪些依赖宿主配置。`srt` 的 CLI 与依赖只进入对照验证环境。[srt CLI 与平台要求](https://github.com/anthropics/sandbox-runtime#platform-support)
4. 用现有本地 Direct 测试路径作为行为基线。验收覆盖工作区内读写、单独控制的工作区外读写、父路径和符号链接、授权根目录替换、子进程继承、拒绝网络、stdout/stderr、stdin 关闭、取消和超时。未开启沙箱时运行同一套兼容性用例。测量同一设备上的冷启动及重复启动时延，随验证结果记录差异。

### 进入下一阶段的条件

至少一个平台通过真实命令验证，能证明约束来自实际启动器。后端不支持所选能力、策略无效或启动失败时，明确拒绝。功能探测和命令执行均使用固定来源的启动器；能力验证失败的平台报告不可用。`nono` 未通过则保留实验状态，使用对照结果定位差异，重新确认后端选择。

### 第一阶段实测 · 2026-11-18

已使用 [验证脚本](../../scripts/agent-sandbox/README.md)运行普通 Direct 基线、`nono` 0.82.0 Rust 启动器和 `srt` 0.0.83。macOS 使用 Apple Silicon 宿主机。Linux 使用 Docker Desktop 的 arm64 Linux 内核，`nono` 探测到 Landlock ABI 8、实际使用 ABI 6，`srt` 使用 Bubblewrap 0.8.0。

| 环境 | 普通 Direct | 原始 `nono` | 加固后的 `nono` | `srt` |
| --- | --- | --- | --- | --- |
| macOS arm64 | 14/14 | 14/15。运行中替换工作区后，写入落到替换目录 | 17/17，含两个新增的目录保护专项用例 | 13/15。写入落到替换目录，且改写 `TMPDIR` |
| Linux arm64 | 14/14 | 14/15。TCP 回环被阻止，UDP 回环仍收到回复 | 15/15。TCP、UDP 回环均返回 `EPERM` | 14/15。改写 `TMPDIR` |

两种后端均通过工作区内读写、显式授权临时目录写入、工作区外读写拒绝、子进程继承、标准流与退出码、取消及超时。Linux 的工作区替换用例中两种后端均未写入替换目录。`srt` 在两种环境中把测试进程的 `TMPDIR` 改为 `/tmp/claude`，在该测试配置下，该路径无法写入。

macOS 的验证程序锁定自己创建的两级父目录。运行中的工作区和两级父目录重命名均返回 `EPERM`，同一个命令随后写入原工作区。沙箱子进程清除父目录标志返回 `EPERM`，原工作区内部的创建、重命名和删除通过。这个方案适用于 ShellSpan 自己管理的工作区路径。目录所有者可以从沙箱外清除标志，现有任意用户工作区的原地保护仍待解决。接入前还需验证应用退出和重启后的清理、并发任务及实际安装包。[Apple BSD 文件标志说明](https://developer.apple.com/library/archive/documentation/FileManagement/Conceptual/FileSystemProgrammingGuide/FileSystemDetails/FileSystemDetails.html)

Linux 的候选启动器对同一份 `block_network()` 策略显式启用 `SeccompOpts::network_baseline()`。TCP 和 UDP 回环一同被阻止，文件操作和进程生命周期用例通过。结果来自 arm64 测试容器，可作为执行链和网络策略的对照证据。[nono 0.82.0 源码](https://docs.rs/crate/nono/0.82.0/source/src/sandbox/linux.rs)

复测中短命令首次总耗时及后五次中位数为 macOS 原始 `nono` 18/15 毫秒、加固组 19/14 毫秒。Linux 两组均为 3/2 毫秒。数据来自调试构建，计时从启动命令到退出，macOS 的父目录加锁与恢复位于计时范围外。原始报告位于 `artifacts/tests/agent-sandbox/`。

## 阶段二：把本地 Direct 接到 Agent 正常入口

1. 扩展现有会话执行配置。缺少新字段的旧会话继续按原配置恢复。启用沙箱的会话冻结工作区及策略；本地工作区不存在、身份变化或没有可用沙箱时，工具在派发前给出可操作的错误。切换可见终端时沿用所选执行面的校验规则。
2. 在原生工具授权中记录实际执行面、后端、工作区身份、策略版本和批准的调用内容，发放能力凭据时绑定这些值。最终派发使用同一份策略，再次校验开关和目标。保持本地预审读命令的固定程序、已验证路径与 stdin 约束。
3. 从 `exec_command` 的真实启动路径调用启动器，复用现有的进程句柄、持久审计、标准流、取消、超时与输出限制。将后端缺失、确认未启动、策略拒绝、普通命令退出和结果未知各自映射到现有结果语义；只有可信的启动证据可以证明命令未启动。命令或 PTY 打印的文本只作为输出。
4. 第一档以工作区和私有临时目录可写为目标，以运行所需路径可读为起点。将读范围、写范围和网络规则分别保存和验收。针对每个已支持平台验证网络规则的实际行为。内置文件、HTTP 与 MCP 走各自的执行入口；需要同一沙箱保证的会话中，将这些能力纳入策略，暂无法约束的能力在工具注册或派发时拒绝，并明确展示适用范围。
5. 固定依赖版本，记录许可证和构建来源。沿用仓库的原生可执行文件打包机制，校验应用资源路径与完整性。对本地开关、选择项和错误提示做中英文及键盘验收。接入结果、运行期事件或模型可见行为变化同时更新 Agent 协议。

### 交付条件

先打一个 macOS 专用测试包，使用应用创建的受管工作区和独立应用数据目录，通过桌面审批、实际 Direct 进程和会话存储完成以下验收。

1. 审批后关闭沙箱总开关，待派发命令被拒绝，工作区里没有生成目标文件。验证沙箱内写入和沙箱外拒绝。
2. 分开测试启动器失败与命令已经开始后非零退出。启动失败需要独立的启动证据，非零退出保留命令的真实退出码、输出和终态。
3. 取消和超时后确认进程组已停止。重启后复核会话记录。命令已派发且结果未确认时进入恢复流程，避免自动重跑。受管工作区一并验证应用异常退出后的目录保护恢复。

Windows 在原生系统上选择可验证的后端后，复用同一套桌面验收项，并验证 Windows 进程树的取消和超时。两平台分别通过验收才开放各自的实现。Linux 容器验收保留为开发阶段的测试证据。

### 测试接入实测 · 2026-11-18

- Linux arm64 在 Docker Desktop 容器内通过 ShellSpan 的原生授权、能力凭据和 `exec_command` 执行加固后的 `nono`，明确选用测试专用启动器。实测通过默认关闭、批准后关闭、授权的工作区被替换、启动器不可执行时拒绝派发、工作区写入边界、UDP 回环、标准流和退出码、取消与超时。取消和超时均确认测试子进程停止，普通原生进程回归 8 项通过。[验收入口](../../scripts/agent-sandbox/README.md#第二阶段的测试接入)
- macOS 的两个独立受管工作区并行实验通过。一条命令被 `SIGKILL` 后仅解除该命令的目录保护，另一条工作区继续拒绝替换，后续写入原工作区并正常清理。
- Linux 结果验证了原生工具和进程管理层。原始记录位于 `artifacts/tests/agent-sandbox/`。

### macOS arm64 专用桌面测试包实测

[桌面验收入口](../../scripts/agent-sandbox/README.md#macos-桌面验收包)完成 7 个真实调用。批准后关闭总开关时，会话依序保存审批请求、批准和撤销，命令没有派发或写入。启动器校验失败时，独立启动凭据记录 `started=false` 和启动器退出码 `125`。命令自身的退出码 `42` 和 `125` 均随 `started=true` 保存。两种 `125` 结果可区分，即使命令输出形似启动器诊断的文本。

主动取消和超时均确认测试子进程已停止。强制结束应用并重启后，六条终态结果与原记录一致，尚未结算的调用进入 `executionInFlight` 恢复状态，实际命令只启动一次。

### macOS 受管工作区崩溃恢复 · 2026-11-19

专用测试包由应用管理目录保护和恢复。应用写入目录身份和准备状态后加锁，启动器等待应用持久保存进程组后才执行命令。恢复只读取真实进程组存活情况。仍然运行或无法确认时，目录保持受保护。

在加锁后尚未启动、命令运行中、进程组退出后尚未解锁三个时点强制结束应用，再用同一个测试包重启。实测未启动的用例未派发或写入；运行中的用例在重启后仍受保护，进程组退出才解锁；已经退出的用例解除遗留保护，缺少结果的会话继续标记为待恢复。额外重启一次后，九条会话记录再次校验通过，所有崩溃用例均未重跑。结果保存在 `artifacts/tests/agent-sandbox/desktop-mac-*/`。这次验证覆盖受管临时工作区和应用进程崩溃，任意现有工作区的原地接入和 Windows 原生实现仍待验证。

## 阶段三：验证 OpenSandbox 的远端可见终端

1. 在专用测试环境部署固定版本的 OpenSandbox 与执行镜像，验证工作区以受控方式进入沙箱，并验证文件可见范围、网络出站规则和沙箱资源回收。记录部署所用执行运行时及其隔离能力。现有 Bubblewrap SSH 连接使用原有子系统及文件接口；OpenSandbox 使用明确配置的服务目标与自己的沙箱身份。[OpenSandbox 部署与执行](https://github.com/opensandbox-group/OpenSandbox) · [执行后端选型](https://github.com/opensandbox-group/OpenSandbox/blob/main/docs/guides/secure-container.md)
2. 先接通专用沙箱 PTY 的输出、输入、窗口尺寸、停止和关闭。Rust 后端通过 TLS 管理服务地址与凭据，凭据走现有钥匙串或授权引用。服务端 PTY ID、ShellSpan 会话 ID、终端代次、工作区和策略版本一同绑定；模型使用 ShellSpan 发放的句柄。
3. 用服务端 PTY 的单写入者和只读旁观能力接入现有终端输入租约。用户接管需要确认并使旧输入权失效，重连从已确认的输出偏移恢复。只有确认连回同一个沙箱、Shell 和代次才恢复输入，旧连接与旧帧直接拒绝。验证长时间运行、窗口缩放、ANSI、Vim 等全屏程序、并发旁观、主动接管与断线清理。[OpenSandbox PTY 协议](https://github.com/opensandbox-group/OpenSandbox/blob/main/components/execd/PTY.md)
4. 在沙箱 PTY 的 Shell 内接入 ShellSpan 已支持的命令提交协议，并验证每条命令的提交、结束和退出状态。服务的 PTY 退出帧描述 Shell 结束，单条命令完成需要单独的控制事件。带强生命周期要求的调用通过显式 Direct 执行。提交后断线且没有可信结束事件时，记录 `uncertain` 并进入恢复流程。只有控制事件和恢复验证通过的终端，才开放 Agent 可见命令和用户接管。

### 交付条件

真实远端服务完成「创建沙箱 → 打开专用 PTY → Agent 执行 → 用户接管 → 重连或停止」验收。检查策略变更后拒绝旧输入、沙箱或 PTY 不可用时拒绝派发、普通 SSH/SFTP 兼容性、断线后的结果状态与清理。测试工作区使用独立目录，验收后检查孤立沙箱、PTY 和凭据引用。

## 验收与回退

| 验证项 | 所需证据 |
| --- | --- |
| 开关默认关闭及持久化 | 真实桌面加载旧配置和空配置、切换、重新启动，核对实际执行行为 |
| 本地执行 | 受限读写、网络规则、真实子进程、超时/取消、退出码与输出；真实安装包验证 |
| SSH 兼容性 | 运行 `node scripts/remote-sandbox/verify-remote-sandbox.mjs --ui`，检查 Bubblewrap 正常、缺失和无法启动，以及关闭时拒绝已经批准的调用 |
| 远端可见终端 | 真实 PTY 的输入租约、单命令完成、回放、断线结果和清理记录 |
| 仓库检查 | 相关 Rust 与前端测试、`pnpm build`、Rust 格式与包含文件检查 |

验收证据保存到 `artifacts/tests/`。按阶段提交实现，使本地启动器接入和远端 PTY 接入可以独立审阅。回退时关闭对应后端的可选能力，保留用户的连接策略和已记录的审计结果；仍要求沙箱的调用在执行前被拒绝。运行中的会话通过现有取消或停止流程处理，结果无法确认时保留恢复状态。
