# Agent 沙箱实施计划

日期：2026-10-14。状态：待实施；本文中的勾选项均未验收，不代表已经提供生产沙箱能力。

关联设计：[Agent 执行安全与使用体验设计](agent-execution-safety-and-usability.md)。当前行为以 [文件与脚本执行协议](../../protocol/agent/runtime/file-and-script-execution.md) 为准。

## 实施原则与首版范围

参考 deepseek-harness 的统一策略、逐调用策略传递、执行后端与单次升权设计。ShellSpan 首版采用本地 Direct、Linux 隔离环境、独立工作副本和人工确认回写；命令与结构化文件工具访问同一工作副本。审批方式与隔离策略独立，保留现有三个权限模式和旧会话行为。

首版不提供原生 macOS／Windows 构建、普通 SSH 沙箱、已有终端隔离、目录批量回写删除。隔离环境与宿主工具链不同，必须明确呈现实际执行环境。容器信任运行时与内核，不承诺防御内核漏洞。

每个阶段独立验收，未通过时不开放对应生产能力。现有测试沙箱不能仅通过移除 `cfg(test)` 转成生产能力；不得解除其他尚未通过的验收门禁。实现与测试使用真实执行，不以 mock、虚假数据或仅为通过检查的变通方案作为验收证据。

## 阶段 1：确定契约与支持范围

- [ ] 确定首版范围和明确不支持的操作、文件类型及执行环境。
- [ ] 定义文件读取、写入、网络、进程、资源和宿主 IPC 的限制契约。
- [ ] 定义沙箱策略、按维度返回的能力报告、执行结果和稳定错误码。
- [ ] 文件模式定义为 `read-only`、`workspace-write`、`danger-full-access`；网络首版只支持关闭。
- [ ] 定义旧会话兼容规则；已有会话不自动切换执行环境，绑定项目不自动授权写入。
- [ ] 更新 Agent runtime 协议，记录实际能力、信任假设与限制。

验收：每项安全承诺都能对应到后端实现和测试，不能只依赖审批或提示词；策略要求与后端实际能力不匹配时拒绝执行。

## 阶段 2：接入统一策略与授权

- [ ] 新增后端沙箱策略解析模块，生成每次调用的不可变策略，包含会话、目标身份、执行环境和策略修订号。
- [ ] 将审批方式与隔离策略分开，保留三个现有权限模式。
- [ ] 扩展单次凭证，绑定调用摘要、目标身份、连接代次、策略修订号、执行环境、有效期和单次使用。
- [ ] 在 `native/runtime.rs` 的执行边界复核策略并消费凭证，禁止模型自行指定可信 runner 参数。
- [ ] 实现策略变更、授权撤销、过期和目标变化后的凭证失效。
- [ ] 后端不可用时返回 `SANDBOX_UNAVAILABLE`，不静默降级为宿主执行。
- [ ] 无隔离例外必须绑定精确调用并明确授权；强制隔离策略不提供例外。
- [ ] 增加策略与授权回归测试。

验收：篡改参数、重用凭证和使用旧策略均不能启动执行；现有审批行为不退化。

## 阶段 3：实现隔离执行后端

- [ ] 定义 `SandboxBackend`，统一探测、准备、启动、停止和恢复接口。
- [ ] 接入成熟的 Docker Rust 客户端；Linux 优先支持 rootless 配置，macOS／Windows 使用经过验证的 Docker Desktop 配置。
- [ ] 固定镜像摘要及工具链版本，制定更新与兼容规则。
- [ ] 配置只读系统、非 root、最小权限、禁止新增权限、独立工作卷和临时目录。
- [ ] 默认关闭网络，限制 CPU、内存、进程数量及磁盘使用；无法落实必需限额时拒绝选择该后端。
- [ ] 白名单构造环境变量，清理继承句柄，不加载宿主登录 shell 配置。
- [ ] 禁止暴露宿主项目、home、凭据、SSH agent、Docker socket和应用数据。
- [ ] 将 Direct 执行接入后端，复用现有有界输出、脱敏、进程句柄和取消接口。
- [ ] 覆盖后代进程、超时、取消和终止确认。

验收：真实程序能运行；越界访问失败；后台后代不能逃离管理；未确认终止时返回 `TERMINATION_UNCONFIRMED`，禁止自动重试。

## 阶段 4：实现工作副本与安全回写

- [ ] 生成有数量、大小和时间限制的导入清单。
- [ ] 支持未提交和未跟踪文件，展示排除项，不仅依赖 Git。
- [ ] 审查 `.env`、凭据及其他敏感文件；首版拒绝特殊文件、不支持的链接和无法稳定读取的目标。
- [ ] 通过受信服务复制批准的文件内容到独立工作卷，不绑定宿主项目，不保留宿主文件对象关系。
- [ ] 命令、读取、补丁和文件编辑统一访问工作副本，明确宿主路径与环境内路径映射。
- [ ] 停止所有写入者后冻结结果，生成不可变变更清单。
- [ ] 展示新增、修改和删除，首版人工确认回写。
- [ ] 回写前检查宿主目标身份和摘要，冲突时保留用户修改，不覆盖新内容。
- [ ] 使用受信文件服务和成熟的目录句柄访问能力执行回写，落实路径和文件对象检查，不直接写入可能存在外部硬链接别名的已有文件对象。
- [ ] 复用结构化编辑检查点，记录逐文件结果与部分成功；不承诺整批原子回写。
- [ ] 删除沿用现有单个普通文件的系统回收站路径；目录、批量或平台无法闭合安全契约的删除保持不可用。
- [ ] 增加硬链接、符号链接、并发替换、宿主修改冲突、部分成功和恢复测试。

验收：完成“导入项目→修改→构建测试→审查→回写”；外部文件不受影响，冲突不被覆盖。导入属于授权的数据读取，不宣称能自动证明项目内容不含敏感数据。

## 阶段 5：完成生命周期与恢复

- [ ] 创建环境前持久记录意图，取得确切环境 ID 后记录归属。
- [ ] 创建结果不确定时保留待核对记录，不重复创建或重放命令。
- [ ] 实现应用退出、Runtime shutdown、崩溃和重启恢复。
- [ ] 清理只使用经过验证的环境归属，不凭名称或标签删除资源。
- [ ] 审计失败时阻止新的变更执行，显式记录执行结果待核对状态。
- [ ] 策略收窄后使旧凭证失效并终止权限过宽的环境，确认停止后再继续。
- [ ] 将受信控制通道与程序输出分开，禁止 stdout／stderr 伪造启动、完成或可安全重试状态。
- [ ] 验证恢复不会重放已经发生或结果不确定的操作。

验收：正常结束和异常结束均有明确归属、真实状态和可执行的恢复步骤；缺失证据不能推断清理成功。

## 阶段 6：接入产品体验与自动执行

- [ ] 在现有权限和执行入口展示实际环境与隔离状态，不重设计无关界面。
- [ ] 增加导入、资源授权及回写审查交互，沿用共享组件和现有审批位置。
- [ ] 处理空态、加载、失败、冲突、取消和结果不确定状态。
- [ ] 完成双语、键盘、焦点和窄容器实际渲染检查，并增加就近 UI 回归测试。
- [ ] 首次范围授权后，允许“帮我批准”在已验收边界内连续执行。
- [ ] 资源扩展绑定精确操作，不永久扩大权限；拒绝后不得换工具或通道绕过。
- [ ] 子 Agent 继承父策略与角色能力的交集，并共享必要的资源预算。
- [ ] 检查 stdin、终端输入、MCP、传输和恢复入口不能绕过策略。
- [ ] 现有 `boundTerminal` 保持无隔离语义；需要沙箱交互时新建属于隔离环境的 PTY。
- [ ] 使用真实模型完成一次完整桌面任务，验证授权次数和实际执行路径。

验收：已授权范围内无需重复审批；越界请求有明确原因，拒绝后不能换通道绕过；界面描述与实际执行环境一致。

## 阶段 7：扩展平台与发布验收

- [ ] 接入受信依赖下载与缓存导入，安装脚本继续在沙箱内运行。
- [ ] 若开放网络，验证实际出口限制、直连绕过、宿主服务和云元数据访问；不能仅设置代理环境变量。
- [ ] 分别验证 Linux bubblewrap／Landlock、macOS Seatbelt、Windows 原生后端，按能力契约选择，不按平台名称推断安全性。
- [ ] 实现受信远端 runner，绑定 SSH 主机、账号和连接代次；普通 SSH 继续明确标记无隔离。
- [ ] 重连、身份变化和 runner 升级后重新校验能力与授权。
- [ ] 每个平台独立维护支持矩阵，未通过的能力保持关闭。
- [ ] 运行相关 Rust 测试、TypeScript 构建与就近 UI 回归；涉及 Rust 结构变化时检查格式和 includes。
- [ ] 完成真实桌面、故障恢复和安全边界验收。
- [ ] 更新协议、使用说明和限制说明，评审后逐步开放。

验收：每个平台、账号和执行通道独立提供证据。原生编译、候选后端探测和部分测试通过不能替代完整生产路径验收。

## 首个可交付版本与证据要求

首个可交付版本覆盖阶段 1–6；阶段 7 按后端分别交付。最终必须在真实桌面完成“导入项目→连续修改→构建测试→审查差异→安全回写”，并验证拒绝、停止、撤销、冲突和异常恢复。

至少覆盖外部硬链接、符号链接与并发替换、泄漏句柄、宿主 socket、后台后代、伪造完成信息、超时、断线、应用崩溃、未知创建结果、回写冲突和审计失败。验收记录写明平台版本、镜像摘要、源码版本、操作路径、真实结果与未验证项；不得将某个平台或选定测试的通过推广为全部后端完成。

纯文档阶段只检查内容、链接和变更范围，不执行破坏性测试，也不启用生产沙箱。
