## 执行约定

- 当前只允许编译、类型和静态检查。App、浏览器、模型、Shell/PTY/SSH运行验收须在用户明确安排后进行，集中使用验收窗口，避免反复启动开发应用打断前台工作。
- 原生App串行运行。只有已安排的前台验收命令可临时设置`SHELLSPAN_ALLOW_FOREGROUND_TESTS=1`，不写入默认脚本或用户配置。入口缺少门禁也不代表得到运行授权。
- 使用真实Shell、PTY、私有控制通道、SSH及浏览器，不使用mock、不合成生命周期或证明，不改写原始捕获。普通输出、OSC、屏幕文字和前端ready均不能作为执行授权证据。
- 只在本地独立验收目录或明确授权的受控测试环境创建无业务数据的验收产物。不对业务主机做有副作用的验收；不修改真实用户配置、执行权限、审批、冻结目标或无关UI。
- 凭据只使用系统钥匙串或CredentialRef。证据保留非秘密身份和摘要，不记录密码、私钥、token、私有控制端点或审批凭据。
- 仓库测试及验收产物统一放入`.artifacts/tests/`，发布产物使用`.artifacts/releases/`，临时构建配置使用`.artifacts/config/`。不重建已移除的根目录产物路径，也不复制其旧结果作为当前证据；工具默认缓存和构建目录保持既有约定。
- 不明结果、断线、中断、零个匹配测试、跳过用例及缺少环境均不能记为通过；不得自动重放可能已提交的操作。
- 不提交、不推送、不发布；生产准入另行明确决定。

状态统一使用：待验、通过、失败、阻塞、不适用。只有达到通过标准且登记证据才勾选；不适用须写明理由，不能缩小必需平台范围。环境缺失记阻塞；实际失败保留失败，不能改成不适用。开始前固定本批次必测项，不能在失败后删项或改变判定标准。

## 可核对的通过标准

| 观察 | 通过要求 |
| --- | --- |
| 提交次数 | 成功场景恰好一次原生接受和一次预定的隔离验收操作效果；准备、拒绝、未提交取消场景均为零。分别记录接受事实和实际效果，不能只统计Started。结果不明时保持未知及恢复门禁，不能按零或一次猜测 |
| 输入及输出 | 原生完整证明与实际输入逐字节一致；每条专用输出记录完整且出现次数符合预期，源码、计划交接及真实执行输出分别核对；截图不能替代字节及协议证据 |
| 取消/停止/恢复 | 按冻结记录中的实际期限观察；收到匹配的真实清稿/结束事实才更新相应结论，期限内未确认则进入约定的不明/恢复状态并维持门禁，不无限等待或悄悄重试 |
| 故障与拒绝 | 每个错误身份、过期、坏摘要、错平台、非法帧、存储失败或不支持输入均记录期望错误及实际输入/接受计数，不只检查错误字符串 |
| 显示及焦点 | 记录实际窗口尺寸、输入/后台输出/缩放操作及时间线；期望内容、光标、选择和视口有明确前后断言，焦点异常须保留触发时间和进程归属；没有采样不能填写“无失焦” |
| 用例覆盖 | 本批次预定必测清单与实际执行逐项对应，必测失败或跳过均阻止对应范围通过；GNU矩阵必须记录39个不同组合及其结果，重跑同一组合不增加覆盖数量 |
