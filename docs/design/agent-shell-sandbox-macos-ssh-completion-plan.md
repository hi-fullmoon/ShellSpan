# Agent Shell 沙箱 macOS 与 SSH 完善实施计划

日期：2026-10-08；状态更新：2026-10-09。状态：阶段 1 本轮完成，阶段 2 已有局部修复与分项验收、整体待完成，其余阶段待实施。不同真实 macOS SSH 账户验收因缺少主机列为后续补验，不记作通过；已知限制与生产门禁继续保留。本计划建立后续工作的执行顺序，不表示其余阶段的验收已经通过。

## 范围与基线

本轮完善 macOS 本地 Direct 和已验证普通账户 macOS SSH Direct。Windows 留待实机可用时继续阶段 A，不作为本轮前置条件；不新增 Linux 桌面支持、远端安装、特权服务、root 或受限跳板支持。

按用户最新要求，旧会话、旧版本及版本回退兼容验收不纳入本次完成条件。

当前生产后端报告 `partial`。硬链接别名、同账户恶意文件竞争和敌对后代逃离进程组仍是明确限制；本轮不承诺完整对象隔离。普通可视终端不属于受限 Shell。保留宿主工具链、现有项目目录、审批、取消、审计和凭据引用机制，不静默回退主机权限。

依据：[剩余问题](agent-shell-sandbox-remaining-work.md)、[阶段 3](agent-shell-sandbox-phase-3-acceptance.md)、[阶段 4](agent-shell-sandbox-phase-4-acceptance.md)、[阶段 5](agent-shell-sandbox-phase-5-acceptance.md)、[沙箱协议](../../protocol/agent/runtime/sandbox-policy.md)、[远端协议](../../protocol/agent/runtime/remote-sandbox-backend.md)。已有子项证据按其修订与覆盖范围复用，不重复计作整体验收。

## 执行原则

- 按阶段串行推进：先核对生产路径和已有证据，再实现缺失行为，最后完成真实验收。发现前序门禁缺陷时先修复，不带着缺陷扩大范围。
- 每阶段开始检查工作树，修改前读取当前文件；保留无关改动。实现优先复用现有运行器、取消机制、类型化 IPC、持久日志和共享组件。
- 不使用 mock、虚假数据或仅为通过验收的变通处理。测试覆盖实际组件和生产入口；静态检查不能代替真实进程、网络或 SSH 证据。
- 只调整本阶段必要的沙箱提示或恢复操作，不重设计其他 UI。若确实需要改变未指定的布局或控件，先明确影响并取得确认。
- 无法确认执行、终止或清理结果时保留 `uncertain` 并暂停相关派发。不得自动扩权、重放副作用命令，或根据名称、PID、历史记录认领资源。
- 不创建 commit、tag、推送或发布。本计划不授权操作用户服务器、修改远端安全配置或强制退出用户正在使用的应用。

## 阶段 1：异常恢复与资源归属（本轮完成）

目标：关闭、断网和崩溃后，不重复执行、不恢复过期授权、不误清理资源。

- [x] 核对本地与 SSH 的 prepare、issue、dispatch、取消、应用退出、重启恢复路径，建立执行状态与资源清理状态的对应表。
- [x] 在现有环境验证未知派发、待审批中断、执行中断和清理中断，以及授权关闭、重绑、连接代际和恢复失效；不同真实 macOS SSH 账户变化列为后续补验。
- [x] 补齐实际有限时长 SSH 离线／重连及应用崩溃后的状态核对；不能把通道关闭当作后代已终止，也不外推无限期离线。
- [x] 验证当前同一普通账户上独立远端会话的并发执行、取消和清理互不影响；清理只使用可验证的精确拥有凭据。
- [x] 对发现的阶段 1 缺陷增加就近回归，协议行为变化同步协议文档。

验收：使用独立测试应用、自有临时项目和普通账户 SSH fixture；记录执行效果、控制器回执、实际进程与资源终态。中断窗口至少覆盖派发前、派发后无持久结果、清理未完成。持续离线场景记录观察时长与恢复步骤，不能外推为无限期恢复。无法证明终态的场景必须保留债务并拒绝继续派发。

交付：路径核对表、缺陷修复、回归测试、匹配修订的恢复验收记录。

实施结果与逐项证据见 [阶段 1 验收记录](agent-shell-sandbox-macos-ssh-stage-1-acceptance.md)。真实模型待审批／已派发硬中断、SSH 应用崩溃的精确托管凭据清理、同一普通账户两个独立远端 Agent Session 已有修订证据；本地受限 Direct 的独立控制器已通过真实主 App 崩溃验收，模型中断的资源债务降为 0。2026-10-09 最终修订复验了首次预检的 Shell 启动前和实际已启动后两个主 App 中断窗口，后者使用 debug SIGSTOP 注入；两个窗口均通过生产签名恢复 resolved=1/uncertain=0。收尾审核修复了未闭合私钥遮蔽凭据提示后可能失去交互门禁的问题；最终真实密钥脱敏和 AppExit 竞争各重复 20 次通过，保留旧失败与证明范围。无法补回可信凭据的历史债务作为持续限制保留 uncertain，不再按 PID／名称清理。按用户决定，阶段 1 本轮完成；不同真实 macOS SSH 账户延期补验，阶段 2 仍待独立前置复核及实施。兼容验收已移出本次范围。

## 阶段 3：可信拒绝诊断

前置：阶段 2 的授权与提示链路通过。

- [ ] 盘点现有控制器能提供的事实，区分策略拒绝、后端不可用、基础设施故障、命令失败、取消、超时和终止未确认。
- [ ] 对明确且尚未执行的资源请求提供具体授权提示；授权范围沿用本次执行／当前会话、绑定、期限和撤销机制。
- [ ] 无可信越界事实时展示已有错误与限制，不从 stderr、退出码或模型解释推导需要扩权。
- [ ] 对已执行或状态未知的命令要求先核对副作用，再形成新请求；不自动重放。
- [ ] 远端尚未支持的资源扩展继续拒绝，不能通过诊断入口绕过现有能力门禁。

验收：真实策略拒绝与普通命令失败分别验证；前者有控制器事实，后者不会诱发扩权。诊断无法可靠获取时明确保留缺口，不制造完整越界遥测。

交付：诊断事实映射、必要的后端／类型化 IPC／双语提示修改、生产路径回归和验收记录。
