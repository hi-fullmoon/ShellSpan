# 现有 Compose 项目的通用部署

## 目标

保留独立发布目录模式，增加 `hostCompose` 配置，接管已有 Compose 项目的指定服务。项目名、服务器目录、文件、服务、备份程序和验证项全部来自项目配置。Abu Console 是接入实例，不进入执行器的分支判断。

## 执行契约

1. 从本地仓库指定 Git ref 解析提交，在隔离工作树中捕获源码；不包含用户未提交文件。审批记录保存实际提交和源码摘要。
2. 本地构建不可变镜像。原始 Compose 文件及明确声明的非敏感文件进入内容寻址制品，服务器环境文件仅保存路径引用。
3. 预检确认现有项目、目标服务、服务器文件和工具可用。审批冻结项目配置、制品、服务和执行器版本。
4. 审批后上传制品、加载镜像；备份将被替换的文件并执行配置的备份程序。备份失败不更新文件、不重建服务。备份输出留在服务器，不上传数据库内容。
5. 仅逐文件替换明确选择的非敏感文件，保留 `.env`、TLS、License、覆盖文件及其他主机私有状态。使用最后一个 Compose override 固定镜像，不改写 `.env`。
6. 使用服务器环境文件和覆盖文件，禁止服务器构建及隐式拉取。仅更新指定服务，按配置强制重建配套服务。
7. 验证容器镜像和配置的 HTTP 检查；完成后保存执行凭据。取消或断连后缺少凭据时保持未知状态，不盲目重试。

## 恢复

每次更新保留配置归档和旧镜像信息；数据库恢复始终人工执行，不纳入自动补偿。已有项目模式不得使用独立发布目录模式的自动恢复命令。首次接管与后续升级均需确认现有服务身份。

## 安全边界

文件路径必须为受限相对路径；拒绝符号链接、路径穿越及受保护文件覆盖。备份只允许指定仓库内脚本和独立参数，不接受任意 shell 字符串。Compose 配置解析采用成熟 YAML/Compose 工具。敏感环境值不进入制品、审批文本和日志。
