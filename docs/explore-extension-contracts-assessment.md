# EXPLORE 扩展格式与插件 API 前置契约评估

> 基线：`1ebd58a`
> 审核日期：2026-08-24
> 范围：连接、Runbook 和主题的扩展格式；先定义稳定数据契约，再评估插件 API

## 结论

本项保持 `candidate` / `researching`。稳定、可审阅的数据契约是任何外部生产者或插件 API 的必要前置，但当前没有证据证明 TermBridge 现在需要建立这个新的对外兼容承诺：

- 公开 issue 中没有插件、扩展、主题或 Runbook 扩展请求，且 issue 创建受限；零结果不能证明没有需求，也不能证明有需求。
- Runbook v1 已有较强的本地文件契约，而连接 v1–v3 是宽松的前端导入格式，主题/设置则不是对外格式。三者尚不共享稳定的版本、失败和测试语义。
- 连接导入没有读取前大小上限、条目数上限、根/配置对象未知字段拒绝或 Rust 端重新验证；这不能作为不受信任扩展的安全边界。
- 主题只有编译时 CSS token、两种应用外观和一组内置终端配色；`preferences` 是无版本 key/value 行，加载时大量使用 TypeScript 类型断言而不是运行时校验。
- 既有测试能证明局部基础，但没有跨格式金色夹具、N-1 迁移语义、较新格式失败关闭、前后端共享语料库、导入故障注入或两个正式平台的文件端到端证据。

因此本次不新增扩展文件、迁移器、导入 UI 或公开 API，也不实现插件运行时、动态库/子进程加载、脚本执行、第三方代码执行、插件市场、云账户、新协议或团队服务。

4. 发现记录不收集主机、用户名、路径、命令、凭据、终端输出或实际扩展文件。

## 现有契约与验证边界

| 数据面 | 当前版本/扩展方式 | 已有安全与测试基础 | 阻断稳定契约的缺口 |
| --- | --- | --- | --- |
| TermBridge 连接导出 | JSON `schemaVersion` 1–3；v2/v3 通过可选端口转发和快捷操作字段演进 | 导出不包含 profile ID、密码、私钥、passphrase 或本机 key ID；跳板、端口转发和快捷操作会清洗未知/敏感字段 | 读文件无大小上限，profiles/tags/字符串无统一数量长度上限；根对象和 profile 对象忽略未知字段；无效、新版本和合法空集都折叠为 `[]`；无显式逐版迁移器与固定夹具 |
| OpenSSH config 导入 | 宽松文本解析，是外部标准的部分子集 | 只取支持的标量字段，私钥路径在用户选择后才读取，批次失败会尝试逆序补偿 | 不是 TermBridge 可演进的对外 schema；无总大小/主机数限制，也不能承载 TermBridge 专有扩展语义 |
| Runbook | UTF-8 `.runbook.json`，`schemaVersion: 1` | 前端 exact-key 解析和 Rust `deny_unknown_fields`双重验证；512 KiB 文档、命令/集合上限；固定 keychainRef、明文秘密拒绝、风险重新分级与结果身份失败关闭 | 只有 v1，没有已发布的迁移窗口或 N-1 夹具；没有声明式扩展点；TS 长度按 UTF-16 code unit、Rust 按 UTF-8 byte，边界并非共享实现；保存使用直接 `write` 而非临时文件同步后原子替换 |
| 应用主题 | `ThemeMode = light | dark | system`；颜色是编译时 CSS token | 启动时主题 cache 可容错，切换/跟随系统有单测 | 没有文件、format ID、版本、校验、导入或回滚；CSS 变量涉及应用整个信任边界，不能接受任意 CSS/资源 URL |
| 终端配色 | `TERMINAL_COLOR_SCHEME_IDS` 与内置 `TerminalTheme` 映射 | 创建、切换、跟随应用主题与背景刷新有组件/注册表测试 | 没有外部语义；无颜色值、必需 token、对比度、数量、名称冲突或新版本校验 |
| 主题/设置持久化 | SQLite `preferences(key, value)`，主题另有 `localStorage` 首屏 cache | 默认值、新增快捷键合并与一个旧默认值迁移有测试；数据库会拒绝较新的内部 schema | preferences 自身无 schemaVersion；后端保存任意 key/value，前端除快捷键外主要以类型断言加载；设备路径、AI 配置等与普通外观混表，不得直接固化为外部契约 |

### 前后端信任边界

- 连接文件由 Rust `read_text_file` 无上限读入后交给前端解析。选中的候选项会通过 profile store 分别写入钥匙串和 SQLite；Rust 端没有重新解析原文本，`ProfileRow` 也没有与外部格式等价的完整长度/组织字段校验。
- Runbook 在前端编辑/预览，在打开、保存和每次执行前由 Rust 重新解析和分类。这是未来不受信任数据的可复用边界，但需以共享夹具证明两端对字节/字符边界的判断一致。
- 主题没有文件边界或 Rust 验证器。它是纯显示数据，未来候选可在前端严格解析，但文件选择/读取仍必须在 Tauri 边界先限制大小；任意 CSS、HTML、字体、图片或网络 URL 都不在数据契约范围。

## 稳定数据契约的必要性判断

必须区分两种“必要”：

1. **架构顺序必要**：一旦允许应用外部的生产者、生成器或任何插件 API 读写这些数据，就必须先建立稳定契约。否则内部 TypeScript/Rust/SQLite/CSS 结构会被意外固化为公共 API，安全修复也可能成为破坏性变更。
2. **当前产品必要**：未满足。没有直接用户需求、任务失败数据或真实文件试用队列，不能证明维护对外兼容面比继续提供内置预设更有价值。

因此审计中 `necessary` 保持 `false`，`extensionGates.dataContract` 保持 `not-established`，`extensionGates.pluginApi` 保持 `blocked`。

若未来重新准入，应稳定的是三个独立语义契约，而不是一个可携带任意数据或代码的“通用插件包”。共享的只应是版本、上限、错误和失败关闭原则。

## 未来候选契约的强制边界

以下是重新准入时的验收条件，不是本次实现承诺。

### 通用规则

- 文件顶层必须有不可混淆的 `format` 与整数 `schemaVersion`；根、嵌套对象和集合项均使用明确字段白名单。
- 在读入/解析前限制文件字节数，解析后限制对象深度、条目数、字符串 UTF-8 字节数、唯一 ID 和引用数量；限制值成为契约与测试的一部分。
- 默认拒绝未知必需字段、未知枚举、未知版本、重复 ID、悬空引用和超限值。只有显式命名且声明为 optional 的扩展段才能在预览中提示后跳过；不得将未知字段静默丢弃后宣称导入成功。
- 解析器返回可区分的类型错误：文件过大、JSON 无效、format 不匹配、版本过新、字段未知、语义无效、秘密边界违反和冲突；不得折叠为空集。
- 导入先完成无写入预检与范围/冲突预览；取消、拒绝、较新版本、任何校验失败都保持现有数据不变。
- 导出规范化 JSON，写入同目录唯一临时文件，完成 flush/sync 后原子替换；失败保留旧文件并清理临时文件。

### 秘密引用边界

- 连接格式默认不得包含密码、passphrase、私钥内容、API Key、原生钥匙串 ID 或其他设备本地引用。认证方式只能表达“导入后需重新绑定”。
- Runbook 只能保留已批准的有限 `keychain://profile/...` 引用，不得引入任意 service/account、环境变量、文件、URL 或扩展提供的秘密解析器。
- 主题不得包含 CSS、HTML、JavaScript、字体/图片路径、网络 URL 或任意文件引用；只允许固定 token 集与经过解析的颜色值。
- 无论格式是否默认无秘密，错误、日志、诊断和操作记录都不得回显原始文件或任意未知字段的值。

### 三种格式的独立边界

- **连接**：只表达非秘密 profile 语义。每个 schemaVersion 有独立解析类型和显式迁移器，迁移到当前内部语义后再预览。冲突默认跳过，不覆盖凭据；逐条写入不能替代整批 SQLite/钥匙串补偿证据。
- **Runbook**：继续使用纯声明 JSON 和当前逐步批准模型。任何新 action 类型、变量源、风险或执行语义都是新的必需 schema 版本，不得通过 optional 扩展绕过 Rust 重新分类、批准、输出上限或脱敏。
- **主题**：应用 chrome 与终端 ANSI 配色分为独立 section；主题 ID、显示名、light/dark 基线和全部必需 token 都要校验。缺少必需 token、无效颜色或对比度安全门槛失败时保留当前主题；不允许扩展新的 DOM 或组件样式表面。

## 版本、兼容、失败与恢复

### 版本与升级

- 每个格式独立版本化，不与应用版本、SQLite schema 或其他格式锁步。
- 只为已发布格式保留显式 `vN -> current semantic model` 迁移器；不以“新字段都可选”代替版本语义。
- 固定当前、N-1、支持窗口最旧版本、较新必需版本和未知必需字段夹具。新应用必须读取支持窗口内旧文件；旧应用必须在任何写入前拒绝新必需语义。
- 发布新版本前必须声明支持窗口和退出日期；格式导出默认使用当前版本，不默认改写用户的旧文件。

### 失败与恢复

| 失败 | 必需行为 | 恢复/回滚 |
| --- | --- | --- |
| 过大、截断、非 UTF-8、JSON 无效、较新版本或未知必需字段 | 在任何持久化或执行前失败关闭，显示类型化错误 | 原文件只读，本地数据与当前主题不变；用户可修复副本后重新预检 |
| 条目冲突 | 预览逐项标记，默认跳过；不默认覆盖 profile、Runbook 或主题 | 取消不写入；显式替换必须先保留当前值以供回滚 |
| SQLite 或原生钥匙串部分失败 | 不得宣称整批成功；连接格式默认不触及秘密 | SQLite 单事务回滚，新建的外部资源逆序补偿；补偿失败列出可定位待清理项 |
| Runbook 校验/风险/批准失败 | 不保存无效规范化结果，不发送命令 | 保留本地编辑副本供用户修正；远端状态不由格式导入改变 |
| 主题应用或可读性门槛失败 | 不写入偏好，不部分套用 token | 原子切回上一个已验证主题；内置 light/dark/system 始终是恢复选项 |
| 导出写入、sync 或替换失败 | 不留下被当作完整文件的部分输出 | 保留旧目标，清理唯一临时文件；清理失败可见且可重试 |

回滚是本次导入/主题切换的状态回滚，不等于承诺 SQLite 或应用可以安全降级。

## 跨平台实现与维护成本

纯 UTF-8 JSON 与语义对象可在 Windows x86_64 和 macOS ARM 共用，也不需要格式执行第三方代码。但“可共用”不是已验证：

- Windows 与 macOS 的路径、文件权限、原子覆盖、符号链接/重解析点和文件对话框语义不同，需要真实平台故障测试。
- 连接 profile 不应导出本机 key ID 或默认展开路径；Runbook keychainRef 保留语义但在目标设备上必须重新绑定 profile 凭据。
- 主题颜色在 WebView 与 xterm.js 中应共享解析结果，但字体渲染与对比度仍需两平台快照/可访问性验证。
- Linux 只能在它的正式发行候选独立准入后进入承诺矩阵，本节点不反向承诺新平台。

持续成本包括三个格式的版本窗口、TS/Rust 验证器、金色夹具、迁移器、文档、故障注入、两平台文件语义、主题可读性回归和安全响应。仓库没有候选实现的夹具体积、CI 时长、缺陷率或每月维护数据，所以维护成本保持未知。

## 插件 API 评估门槛

当前门槛是 `blocked`，不进行插件 API 能力设计。只有三种数据契约中经用户证据证明必要的子集完成上述版本、安全、失败/恢复和自动化门禁后，才可建立新的独立 EXPLORE 评审来判断是否连“插件 API”都有必要。

那次评审也不得默认扩展到运行时、任意命令、第三方代码、网络权限、凭据访问、市场、账户或团队服务。首个候选若有必要，也应优先是对已稳定、纯数据契约的离线生成/验证边界，而不是在 TermBridge 进程内执行不受信任代码。

## 复盘触发条件

1. 某一格式达到用户发现最小样本，并能证明现有内置预设/连接导出/Runbook v1 无法解决主要任务。
2. 候选范围、字节/数量上限、秘密引用白名单、错误类型、版本窗口和原子导入/导出协议通过安全评审。
3. TS/Rust 共享 corpus、N-1/较新版本、故障注入与 Windows/macOS 文件 E2E 可在 CI 中持续执行。
4. 候选实现产生可测量的 CI 时长、夹具体积、失败率、安全评审和月度维护成本。
5. 稳定数据契约本身完成独立验收后，再决定是否开始插件 API 的全新 EXPLORE 评估；本文不自动触发它。

即使上述证据齐全，也只能形成一次“是否进入正式阶段”的独立评审，不会自动建立产品承诺。
