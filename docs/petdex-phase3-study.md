>
> 最早有效截止：2026-09-11（14 天）

## 1. 研究问题与边界

本阶段只验证默认关闭的 Petdex 状态桥接是否带来小规模、可感知的价值，不开发目录、原生渲染、账户、遥测或上传能力。回答四个问题：

1. 外部桌宠是否帮助用户发现后台传输、AI 完成或连接失败？
2. 明确选择试用的用户是否在第 7 天仍主动保持启用？
3. 联动是否造成干扰、资源压力、遮挡、崩溃、业务阻塞或秘密泄露？
4. 用户更需要外部悬浮桌宠、TermBridge 窗口内角色，还是普通系统通知？

TermBridge 不观察设置开关，不生成参与者 ID，不发送使用事件，不读取 Petdex 使用记录。所有证据只能来自用户主动提交的 GitHub 反馈或经过明确同意的访谈。

## 2. 招募与知情选择

### 招募渠道

- 设置页中的“提供自愿反馈”按钮，只打开固定的 [GitHub Issue 表单](https://github.com/hi-fullmoon/TermBridge/issues/new?template=petdex-phase3-feedback.yml)，不附带应用数据。
- 发布说明、项目讨论或维护者邀请可以链接到同一表单。
- 访谈仅邀请已经主动表示愿意试用的人；不从应用行为反推、筛选或联系用户。

### 计入试用用户的条件

一名试用用户必须同时满足：

1. 知道功能为实验性、默认关闭，可随时退出；
2. 知道 Petdex Desktop 是独立外部应用；
3. 主动启用并实际试用，或提供可复核的等量需求证据；
4. 明确同意其脱敏反馈被计入聚合统计；
5. 通过 GitHub 表单或访谈主动提交，不由 TermBridge 自动记录。

公开 GitHub Issue 会显示提交者的 GitHub 身份；表单必须先告知这一点。希望保持匿名的人可以选择访谈，由保管者只为台账提供 `anonymous:<record-id>` 引用。台账本身不得保存姓名、账号、邮箱或可逆参与者标识。撤回时，在下一次聚合更新中扣除相应计数和证据引用。

### 去重与第 7 天复核

- 维护者在聚合前人工去重；去重过程不得把 GitHub 用户名写入仓库台账。
- 每名明确试用用户从其主动确认开始计算 7 天；第 7 天或之后只接受用户主动确认“仍启用”。
- `day7EligibleUsers` 必须覆盖最终截止时所有 `explicitOptInUsers`。未回复或无法确认的已到期用户计入 eligible，但不计入 enabled，避免选择性只统计回复者。
- 等量需求证据可用于 30 人/证据门槛，但不能代替真实试用用户的第 7 天留存分母。

## 3. 反馈问题

GitHub 表单与访谈使用同一组问题：

1. 是否实际启用过 Petdex 联动？是否已连续保持启用至少 7 天？
2. 是否帮助发现后台传输、AI 完成或连接失败？
3. 它是改善了状态感知，还是仅仅“有趣”，或没有价值？
4. 是否遇到干扰、资源占用、遮挡工作区？
5. 是否发生由联动引起的崩溃、SSH/SFTP/AI 业务阻塞或疑似秘密泄露？
6. 更偏好外部悬浮桌宠、窗口内角色、系统通知，还是都不需要？

表单明确禁止提交秘密、凭证、Token、终端或 AI 内容、日志、诊断包、主机名/IP/用户名、路径和文件名。疑似秘密泄露不得在公开 Issue 中粘贴细节；应先关闭联动，并通过维护者已有的可信私密渠道报告。公开表单只记录“疑似发生”这一选择。

## 4. 隐私与证据台账

[证据台账](./petdex-phase3/evidence-ledger.json) 由 [JSON Schema](./petdex-phase3/evidence-ledger.schema.json) 约束，只能表示：

- 明确同意后的试用人数或等量可复核需求计数；
- 第 7 天 eligible / still-enabled 聚合数；
- 已完成安全复核后的严重事件数量；
- 状态感知、干扰和界面偏好的分类计数；
- 公开 Issue URL 或脱敏保管记录 `anonymous:<record-id>`。

Schema 刻意不提供自由文本、参与者字段或任意 URL，因此不得在台账中存储终端内容、主机信息、路径、文件名、AI 内容、Token、日志或秘密。原始 GitHub 反馈由 GitHub 按用户主动提交处理；匿名访谈原始记录不进入仓库，且只在参与者明确同意的范围内由指定保管者留存。

初始台账中的人数为真实的 `0`，安全事件为 `null`（尚未完成复核），不能改写为推测值。每次更新应在同一变更中附上可复核证据引用，并运行门禁。

## 5. 观察节奏

| 时间 | 运行工作 | 可记录证据 |
| --- | --- | --- |
| 第 0 天 | 发布自愿入口，开始招募 | 明确 opt-in 与同意后的聚合人数 |
| 每 2–3 天 | 人工去重并更新聚合 | 新增 Issue/匿名证据引用、分类计数 |
| 第 7 天起 | 对到期试用者做一次自愿复核 | eligible 与明确确认 still-enabled |
| 全程 | 复核崩溃、业务阻塞、秘密泄露报告 | 仅严重事件计数和脱敏引用 |
| 第 14–28 天 | 选择真实截止日并冻结一次快照 | 设置 `endedOn`，完成安全复核，运行严格门禁 |

不得提前写入未来反馈、推算参与人数或用设置开关/本地日志补齐证据。若到第 28 天仍未建立真实截止，门禁返回 `blocked`，必须建立可审计截止，而不是回填日期。

## 6. 准入判定

Phase 3 只有在有效的 14–28 天截止后同时满足以下条件才可返回 `pass`：

- 不少于 30 名明确 opt-in 试用用户，或等量有证据引用的可复核需求；
- 所有实际试用用户都有第 7 天结果，且明确仍启用的比例不低于 30%；
- 安全复核完成，确认由联动引起的崩溃、业务阻塞或秘密泄露为 0；
- 至少一条有证据引用的定性反馈确认它改善了后台传输、AI 完成或连接失败中的至少一种状态感知，而非只觉得有趣。

状态含义：

- `collecting`：观察期仍在 2–4 周窗口内，证据尚未冻结或仍有缺口。
- `pass`：有效截止且全部门槛有证据地满足。
- `fail`：有效截止后门槛未满足，或任何时点确认发生严重安全问题。
- `blocked`：台账/schema/聚合关系无效、安全复核未完成却已截止，或观察期超过 28 天仍未截止。

`fail` 或 `blocked` 均不得进入 Phase 4。`collecting` 也不是准入。

## 7. 可重复运行

在仓库根目录运行当前状态报告：

```bash
pnpm petdex:phase3 -- --as-of 2026-08-28
```

机器可读输出：

```bash
pnpm petdex:phase3 -- --as-of 2026-08-28 --format json
```

Phase 4 的严格门禁（任何非 `pass` 状态退出非零）：

```bash
pnpm petdex:phase3:gate -- --as-of YYYY-MM-DD
```

日常报告模式允许 `collecting` / `fail` 以退出码 0 输出，便于审阅真实结论；结构损坏的 `blocked` 始终退出 2。严格模式下非 `pass` 退出 1，`blocked` 仍退出 2。自动化测试覆盖空台账、收集中、通过、留存失败、严重安全失败、超期阻塞和聚合矛盾。
