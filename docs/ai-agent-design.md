# TermBridge AI Agent 功能设计

> 版本：v0.1（草案）
> 目标：在现有「终端 + SFTP + 凭证托管」的运维主链路上叠加 AI Agent 能力，形成可收费的商业化功能。

## 1. 为什么 TermBridge 适合做 AI Agent

通用 AI 助手（ChatGPT、Claude 等）在运维场景的短板是：**没有上下文、没有执行通道、没有安全边界**。TermBridge 恰好三者皆有：

- **上下文**：终端输出流、当前会话的主机/路径/用户、SFTP 目录树、连接配置都在本地应用内。
- **执行通道**：应用本身就持有 SSH/SFTP 连接，AI 生成的命令可以直接投递执行，无需复制粘贴。
- **安全边界**：凭证在系统钥匙串，会话在本机，天然适合做「本地优先、数据不出门」的差异化卖点。

竞品（Warp、Tabby、Termius、Xterminal）都在做 AI，说明付费意愿已被验证；但它们多数依赖云端转发，TermBridge 可以用「本地直连 + 自带模型（BYOK）」打差异化。

## 2. 功能场景（按商业价值排序）

### 2.1 终端内 AI 助手（核心入口）

在终端面板旁开一个 AI 侧边栏 / 唤起浮层（如 `Ctrl+I`），具备以下能力：

- **自然语言转命令**：「找出 /var/log 下大于 100M 的日志文件」→ 生成 `find` / `du` 命令，附解释，确认后一键写入当前终端。
- **上下文感知**：自动携带当前主机的 OS 类型、shell、工作目录，生成的命令贴合环境（区分 Linux/macOS/Alpine 无 `systemctl` 等）。
- **命令解释**：选中终端里任意命令或输出，右键「解释这段」，AI 用中文讲清每个参数。
- **错误诊断**：终端检测到非零退出码或典型报错（permission denied、connection refused、OOM），AI 主动给出原因分析和修复建议，并给出可直接执行的修复命令。

**商业价值**：这是付费转化率最高的一档功能——高频、刚需、体验差距立竿见影。

### 2.2 Agent 模式（多步任务自动执行）

用户给出任务而非单条命令，例如「帮我排查这台机器为什么 CPU 高」。Agent 自主执行多轮：

1. 规划步骤（`top` → 定位进程 → `systemctl status` → 看日志）。
2. 每条命令执行前弹出确认卡片（命令 + 目的 + 风险等级），用户批准后才执行。
3. 读取终端输出，决定下一步，直到给出结论报告。

**风险分级策略**：

| 等级 | 例子 | 策略 |
|------|------|------|
| 只读 | `ls`、`cat`、`ps`、`df` | 可选自动批准 |
| 可逆写操作 | 创建文件、编辑配置 | 每次确认 |
| 危险 | `rm -rf`、`kill -9`、重启服务、`iptables` | 强制确认 + 高亮警告 + 命令原文展示 |

危险命令匹配用本地规则表先行拦截，不依赖模型自觉。

**商业价值**：这是 Pro 版的核心卖点，对标 Warp Agent / Claude Code 的运维化版本。

### 2.3 SFTP 与文件运维

- **自然语言批量操作**：「把 nginx 配置备份到本地并打包下载」→ Agent 组合 SFTP 下载/压缩命令完成。
- **大文件/日志分析**：远程日志太大，AI 先在远端 `grep`/`tail` 抽取片段，再本地分析，避免整文件下载。
- **配置文件审查**：预览 nginx.conf / docker-compose.yml 时，AI 检查常见错误与安全风险（如 root 运行、端口暴露）。

**商业价值**：把 SFTP 从「搬运工具」升级为「运维助手」，与终端场景形成闭环。

### 2.4 命令片段与工作流库

- AI 生成/补全常用脚本（备份脚本、巡检脚本、一键部署），可保存到本地片段库并复用。
- 「一键巡检」：预设的 Agent 工作流——磁盘、内存、僵尸进程、失败服务、证书到期——跑完输出一份健康报告。

**商业价值**：片段库和巡检模板适合做内容增值与团队共享，是企业版的切入点。

### 2.5 会话记录与知识沉淀

- 终端会话脱敏后（屏蔽密码/token/IP 可选）生成摘要：今天在这台机器上做了什么、踩了什么坑、怎么解决的。
- 下次连接同一主机时，AI 能引用历史摘要作为上下文（「上次你是通过重启 nginx 解决的」）。

**商业价值**：这是最难被复制的护城河——数据留在本地、随使用时间增值，提高用户迁移成本。

## 3. 技术架构设计

### 3.1 总体结构

```
┌───────────── 前端 (React) ─────────────┐
│  AI 侧边栏 / Agent 确认卡片 / 报告视图  │
└──────────────┬─────────────────────────┘
               │ Tauri commands / events
┌──────────────▼─────────────────────────┐
│           Rust 后端                     │
│  ┌─────────────────────────────────┐   │
│  │ ai/ 模块                         │   │
│  │  ├─ provider/  LLM 客户端抽象     │   │
│  │  ├─ agent/     规划-执行-观察循环  │   │
│  │  ├─ context/   终端输出采集、脱敏  │   │
│  │  ├─ safety/    危险命令规则表      │   │
│  │  └─ history/   会话摘要存储(SQLite)│  │
│  └─────────────────────────────────┘   │
│   复用现有：session.rs(SSH) sftp_pool.rs│
└────────────────────────────────────────┘
```

关键原则：**AI 不新建连接通道**。Agent 执行命令走现有 `session.rs` 的 SSH 会话，SFTP 操作走 `sftp_pool.rs`，权限与审计逻辑只写一份。

### 3.2 LLM 接入策略：BYOK 优先

- 抽象一个 `LlmProvider` trait，首版支持：OpenAI 兼容协议（覆盖 DeepSeek、通义、Kimi 等国内模型）、Anthropic、Ollama（纯本地模型）。
- API Key 随厂商配置保存在本机 TermBridge 数据库，并只在发起对应厂商请求时传给后端。
- 请求直连用户配置的 endpoint，**不经过 TermBridge 任何服务器**——这既是成本优势（零推理成本），也是隐私卖点。

### 3.3 Agent 执行循环（Rust 侧）

```
用户任务 → 规划(调 LLM) → 产出命令候选
        → safety 规则表分级
        → 前端确认卡片 → 用户批准
        → 注入终端会话执行 → 采集输出(截断+脱敏)
        → 回传 LLM 观察 → 继续或终止
        → 输出结论报告
```

约束设计：

- 最大步数上限（如 15 步），防失控烧 token。
- 终端输出按尾部截断 + 敏感模式（`AKIA…`、`password=`、私钥块）正则脱敏后再发给 LLM。
- 全程事件流推送前端，每一步可视、可中断（一键 Stop）。

### 3.4 与现有代码的复用点

| 现有模块 | 复用方式 |
|----------|----------|
| `src-tauri/src/session.rs` | Agent 命令执行通道，附带 pty 输出流 |
| `src-tauri/src/sftp_pool.rs` | SFTP 类工具的实现基础 |
| `src/stores/aiSettingsStore.ts` | LLM 厂商配置与 API Key 本机持久化 |
| `src-tauri/src/db.rs` (rusqlite) | 会话摘要、片段库、Agent 审计日志 |
| `src/stores/terminalStore.ts` | 终端输出上下文采集入口 |
| 日志面板 / 审计 | Agent 所有操作写入操作日志，可导出（企业合规刚需） |

## 4. 商业化方案

### 4.1 分层设计

| 层级 | 内容 | 定价思路 |
|------|------|----------|
| **免费版** | 自然语言转命令、命令解释（BYOK，每日限次） | 引流，验证场景 |
| **Pro（个人订阅）** | Agent 模式、错误诊断、SFTP 智能操作、会话摘要、无限次 | 月度/年度订阅 |
| **Team / Enterprise** | 巡检模板共享、操作审计导出、统一模型网关接入、私有化模型（Ollama/内网）支持 | 按席位授权 |

### 4.2 核心卖点话术

- **「AI 不下云，运维不出门」**：BYOK + 本地直连，服务器输出不经过第三方——对比 Warp/Termius 的云端模式，面向对数据敏感的运维团队。
- **「带刹车的 Agent」**：风险分级 + 强制确认，解决运维场景对 AI 自动执行的最大顾虑，这是比「更聪明的模型」更有说服力的差异点。

### 4.3 成本结构

BYOK 模式下推理成本为零，收费的是软件能力本身，毛利结构健康。后续可提供官方托管模型作为增值选项（代付 API 成本 + 加价），但不应是默认路径。

## 5. 实施路线图

| 阶段 | 内容 | 验收标准 |
|------|------|----------|
| P0（2-3 周） | `LlmProvider` 抽象 + OpenAI 兼容接入；终端侧边栏；自然语言转命令、命令解释 | 配置 Key 后可在终端旁生成并投递命令 |
| P1（3-4 周） | 上下文采集（OS/shell/cwd/最近输出）+ 脱敏；错误诊断；危险命令规则表 | 报错后 AI 给出可执行修复建议；危险命令被拦截确认 |
| P2（4-6 周） | Agent 模式（规划-确认-执行循环 + 事件流 + 中断）；Pro 授权/订阅骨架 | 「排查 CPU 高」类任务端到端跑通 |
| P3（后续） | SFTP 智能操作、会话摘要与历史引用、片段库/巡检模板 | 巡检报告生成；Pro 版发布 |

## 6. 风险与对策

- **模型幻觉产生危险命令** → 规则表先行拦截 + 强制确认，模型建议永远不能绕过确认流。
- **终端输出泄露敏感信息给 LLM** → 本地正则脱敏层 + 文档明示数据流向，设置项可关闭上下文采集。
- **token 成本失控** → 步数上限、输出截断、上下文窗口预算管理，Agent 运行中实时显示已消耗 token。
- **用户不信任自动执行** → 默认全确认模式，「自动批准只读命令」为显式开启的选项而非默认。
