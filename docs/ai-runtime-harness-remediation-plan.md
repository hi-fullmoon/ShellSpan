## 必须验证的行为

### 1. 基线与门禁

- [ ] 最终代码在 Windows CRLF checkout 下通过 prompt golden；统一 fixture 换行。
- [ ] package scripts 与 CI 引用一致，无悬空 Runtime / Provider 门禁。
- [ ] 保留用户已有改动；交接后的代码及新增文件完整，无临时脚本、日志或凭据混入产品代码。

### 2、4. 压缩与语义连续性

- [ ] 保留当前目标、仍有效的用户约束、决策及理由、已完成/未完成工作、文件与命令、阻塞项和下一步。
- [ ] 上一份已提交 checkpoint 与新增原始对话共同参与摘要；较早约束、长消息尾部以及后续撤销/覆盖均有测试。
- [ ] 超过 100 KiB 的普通待压缩对话不会因为固定小尺寸分块上限而必定放弃语义摘要。
- [ ] 模型输入、输出、尝试次数及耗时有明确边界；预算不足或分段失败不得提交已知遗漏原上下文的 checkpoint。
- [ ] 工具大输出受控裁剪，并保留哈希、引用和可验证的完整证据；连续压缩不递归嵌套旧摘要产物。
- [ ] 只在安全的完整 Turn 边界替换；压缩后重新计算整个请求预算。
- [ ] 摘要请求/响应与降级原因有可恢复的 provenance；append-only 日志和 generation 更新保持原子性。
- [ ] 覆盖空/非法摘要、预算不足、失败、取消、artifact 写入后取消、连续压缩和重启恢复。

### 3. 请求可靠性

- [ ] 重试遵循 Provider 可配置策略、指数退避、jitter、Retry-After 秒数/日期/毫秒提示及上限；配置和旧数据迁移完整，等待可以取消。
- [ ] 连接/响应头、首字节和流空闲分别受控；持续有输出的流不受固定 120 秒总时长误杀。
- [ ] 输出提交前可以重试；已提交部分内容后的中断不能重放成重复文本、工具调用或副作用。
- [ ] 失败持久化尝试次数、累计等待、HTTP/code 和中断状态；前端投影与恢复一致。
- [ ] 取消与就绪 chunk / response 竞态优先处理取消。
- [ ] 最终累计复验 Harness partial-stream 与空响应恢复。阶段 3B 已支持同 Session、同 step/series 有界恢复，失败 attempt 只保留 chunk/failure 审计，成功消息与工具在完成后提交；最终工作区仍需复验此行为。

### 4. Provider 契约

- [ ] TypeScript 与 Rust 使用同一显式能力契约；profile 优先于 hostname，兼容代理与旧配置迁移。
- [ ] 区分接收 reasoning、用户可切换 thinking、历史 reasoning 保留及其必要请求字段。
- [ ] 覆盖 Qwen、GLM、DeepSeek、MiniMax、Kimi 及通用兼容协议的请求、流和历史回放差异。
- [ ] MiniMax 原始 reasoning details 无损回放；GLM / Qwen 的保留开关按实际支持范围发送。
- [ ] 工具、并行工具参数、usage、schema、上下文及输出预算与契约一致；不支持的参数在发请求前处理。
- [ ] 同时有共享 fixture 和实际 HTTP mock 合同；测试不能只证明 JSON 与自身一致。
- [ ] Provider smoke / CI 入口完整，真实调用结果与条件跳过分别列出。

### 5. 并行工具调度

- [ ] 用有界 rolling pool 替代整组无上限 join_all；并发配置有默认值和有效范围。
- [ ] 并发完成不打乱模型顺序的持久化结果；读组与写操作、审批、编排、Session 工具之间保持屏障。

- [ ] 子 Agent 工具预算覆盖已提交和已保留的调用，不能在仅剩一个额度时启动整组调用。
