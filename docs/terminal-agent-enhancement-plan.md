# ShellSpan 终端 Agent 增强计划

> 状态：Draft
> 创建日期：2026-08-31
> 适用版本：v2.1 之后
> 目标：将当前单终端、单工具的安全执行 Agent，升级为面向本地与远程运维的通用 Agent 工作台。

## 1. 背景

ShellSpan 当前已经具备终端 Agent 的核心安全基础：

- 只接受结构化 `run_terminal_command` 工具调用，不执行普通 Assistant 文本。
- 任务与连接实例绑定，并冻结主机、端口、用户和会话身份。
- 支持请求批准、自动批准部分只读命令和完全访问三种权限模式。
- 支持停止、超时、退出码验证、输出限制、敏感信息脱敏和本地审计。
- 断线、重连、目标漂移或应用退出时 fail closed，不自动重放未完成命令。
- 已有原生 SSH 执行基础设施，可提供目标复验、独立 stdout/stderr、取消和有界输出。

当前主要限制：

- Agent 工具固定为 `run_terminal_command`，大量能力只能通过拼接 Shell 命令完成。
- 单次运行最多 8 个工具步骤，每轮只允许一个工具调用。
- 同一时刻只能有一个全局活动 Agent 请求。
- 任务只能绑定单个终端连接，不能编排本地、SFTP 和多台远程主机。
- 缺少文件编辑、差异预览、检查点、后台进程、恢复、计划、Skills、Hooks 和 MCP。
- Agent 上下文主要来自聊天与近期终端输出，缺少主机、项目、文件和长期记忆层。
- 命令风险分类、审批和 PTY Agent 执行主要位于前端；高权限模式下需要更强的原生信任边界。

## 2. 产品目标

### 2.1 核心目标

1. 建立与模型厂商无关的通用工具运行时。
2. 支持可靠、可观察、可取消、可恢复的长任务。
3. 将本地终端、远程 SSH、SFTP、主机监控和外部服务统一为结构化工具。
4. 支持任务级、目标级和工具级的精细权限控制，并提供可选的最大权限 Operator 模式。
5. 支持项目指令、Skills、Hooks、MCP 和可复用 Runbook。
6. 支持多连接、多主机和有限并行编排。
7. 建立可量化的正确性、安全性、延迟、成本和可靠性评测体系。

### 2.2 非目标

- 不让模型直接读取明文密码、私钥口令、API Token 或系统钥匙串内容。
- 不把普通 Markdown、代码块或终端输出解释为可自动执行指令。
- 不在缺少目标绑定、权限证明或审计记录的情况下执行高权限操作。
- 不以无限步骤、无限输出或无限并发作为“完全访问”的含义。
- 不在首个阶段同时引入多 Agent、Fleet、自动化调度和完整插件市场。

## 3. 设计原则

### 3.1 工具优先

文件、进程、SFTP、主机状态和外部服务应优先通过结构化工具访问。Shell 作为通用逃生口保留，但不再承担所有能力。

### 3.2 原生层强制授权

前端负责展示计划、审批、差异和结果；Rust 原生层负责：

- 校验工具 schema。
- 冻结和复验目标。
- 评估权限与风险策略。
- 签发和验证短期能力令牌。
- 执行工具并约束资源。
- 脱敏、审计和提交工具结果。

前端不得仅凭本地状态绕过原生授权。

### 3.3 权限与秘密分离

Agent 可以获得执行某类操作的权限，但不能获得完成认证所需的明文秘密。提权和认证由原生凭证代理完成。

### 3.4 先计划、后执行、再验证

高影响任务必须具备明确目标、预期影响、成功条件和验证步骤。写操作完成不等于任务完成。

### 3.5 可恢复而非盲目重放

恢复任务时重建任务状态、工具句柄和上下文；不得在无法证明幂等性的情况下自动重放已发出命令。

### 3.6 默认有界

所有步骤数、运行时间、输出、并发、Token、费用和外部请求均需有默认上限，并允许按任务提升。

## 4. 目标架构

```text
┌──────────────────────────────────────────────────────────────┐
│ React UI                                                     │
│ 对话 · 计划 · 审批 · Diff · 任务中心 · Artifact · Trace      │
└──────────────────────────────┬───────────────────────────────┘
                               │ typed Tauri commands/events
┌──────────────────────────────▼───────────────────────────────┐
│ Rust Agent Orchestrator                                      │
│ Agent loop · budgets · retry · resume · verification         │
├──────────────────────────────────────────────────────────────┤
│ Tool Registry              │ Policy Engine                   │
│ schema · discovery         │ grants · effects · risk · TTL   │
├──────────────────────────────────────────────────────────────┤
│ Execution Drivers                                            │
│ PTY · Direct SSH · Local FS · SFTP · Host APIs · MCP          │
├──────────────────────────────────────────────────────────────┤
│ Event Store · Checkpoints · Audit · Redaction · Artifacts     │
└──────────────────────────────────────────────────────────────┘
```

### 4.1 Agent Contract v3

Agent v3 不再把工具调用硬编码为单一命令类型。建议的逻辑结构：

```ts
interface AgentToolCallV3 {
  requestId: string;
  callId: string;
  toolName: string;
  arguments: unknown;
  target: AgentToolTarget;
  capabilityId: string;
  idempotencyKey?: string;
}

interface AgentToolResultV3 {
  requestId: string;
  callId: string;
  status: 'completed' | 'rejected' | 'failed' | 'timedOut' | 'cancelled';
  summary: string;
  data?: unknown;
  artifacts?: AgentArtifactRef[];
  effects?: AgentObservedEffect[];
  truncated?: boolean;
}
```

必须保留：

- 严格 schema 与未知字段拒绝。
- 请求、调用和目标的强关联。
- 工具结果关联校验。
- Assistant 文本永不进入执行路径。
- 明确的完成或未完成终态。

### 4.2 工具元数据

每个工具声明：

- 名称、版本、输入和输出 schema。
- 支持的目标类型。
- 只读、写入、破坏性、外部副作用等 effect。
- 是否幂等、是否可取消、是否可重试。
- 默认超时、输出和并发上限。
- 所需能力和可审批范围。
- 结果中哪些字段属于不可信外部数据。

## 5. 首批内置工具

首批工具控制在约 12 个，确保工具选择稳定且上下文开销可控。

| 工具 | 目标 | 主要用途 | 默认 effect |
| --- | --- | --- | --- |
| `exec_command` | 本地、远程 | 启动有界命令并返回结果或进程句柄 | 动态分类 |
| `write_stdin` | 进程句柄 | 向非秘密交互程序写入输入 | 状态修改 |
| `wait_process` | 进程句柄 | 等待或读取新增输出 | 只读 |
| `kill_process` | 进程句柄 | 中止前台或后台任务 | 状态修改 |
| `read_file` | 本地、远程 | 有界读取文本或二进制元数据 | 只读、可能敏感 |
| `list_directory` | 本地、远程 | 分页列出目录 | 只读 |
| `search_text` | 本地、远程 | 文件名与内容检索 | 只读、可能敏感 |
| `apply_patch` | 本地、远程 | 基于前置摘要或版本应用文本补丁 | 写入 |
| `transfer_file` | 本地、远程 | 通过 SFTP 上传或下载 | 写入或读取 |
| `host_snapshot` | 本地、远程 | 获取 OS、资源、服务和网络摘要 | 只读 |
| `ask_user` | UI | 获取缺失选择或授权 | 无系统副作用 |
| `update_plan` | 任务 | 更新计划、步骤状态和成功条件 | 无系统副作用 |

后续结构化工具候选：

- `service_status`、`service_restart`。
- `query_logs`、`follow_logs`。
- `list_processes`、`inspect_process`。
- `docker_inspect`、`docker_compose_apply`。
- `kubernetes_get`、`kubernetes_apply`、`kubernetes_rollout_status`。
- `port_forward_manage`。
- `database_query`，默认只读并显式区分事务与非事务。

## 6. 执行通道

### 6.1 PTY 通道

适合依赖当前 shell 状态的操作：

- 当前工作目录。
- 当前环境变量。
- 已激活的虚拟环境。
- 用户正在观察的交互式终端。

继续保留现有冻结会话、包装器、输出边界和 Ctrl-C 中止机制。

### 6.2 Direct Exec 通道

适合自动化和并行任务：

- 独立 stdout/stderr。
- 稳定退出码。
- 无终端提示符和 ANSI 干扰。
- 后台运行和句柄化等待。
- 更容易执行多主机并发。

优先复用现有 `src-tauri/src/execution` 模块，将其从测试/内部基础设施提升为受策略引擎保护的 Agent 执行驱动。

### 6.3 通道选择规则

- 用户明确要求“在当前终端执行”时使用 PTY。
- 诊断、批处理、并行和后台任务默认使用 Direct Exec。
- 需要 shell 状态但又要求后台运行时，先由 Agent 说明状态继承边界。
- 工具结果必须标注实际使用的通道。

## 7. 权限模型

### 7.1 用户模式

保留现有三档模式，并调整语义：

| 模式 | 行为 |
| --- | --- |
| 请求批准 | 所有有副作用工具逐次批准 |
| Scoped Autopilot | 自动执行授权范围内的读取和低风险写入，超出范围时请求扩权 |
| Operator | 在显式能力令牌范围内自动执行高权限、破坏性和多目标操作 |

### 7.2 能力令牌

能力令牌至少绑定：

- Agent 请求和用户会话。
- 目标连接、主机或主机组。
- 允许的工具与 effect。
- 本地或远程路径范围。
- 允许的网络出口域名或地址范围。
- 是否允许提权。
- 最大并发、次数、持续时间和费用。
- 签发时间、过期时间和撤销状态。

能力令牌由 Rust 签发、验证和撤销，不将认证秘密作为令牌内容。

### 7.3 最大权限边界

Operator 模式可允许：

- 任意受支持工具。
- 文件写入与删除。
- 软件安装和服务重启。
- 受控网络访问。
- 多主机并发。
- 通过凭证代理执行提权操作。

以下边界不可关闭：

- 冻结目标和身份复验。
- 用户停止、超时和资源上限。
- 凭证隔离与输出脱敏。
- 完整审计和工具结果关联。
- 根目录、主目录、磁盘设备和大规模批量破坏的熔断器。
- 无法证明目标或权限时 fail closed。

### 7.4 凭证代理

- 模型只能请求 `elevated: true`，不能请求密码文本。
- 优先支持受限 `sudoers`、服务账号、已有 sudo ticket 或系统授权机制。
- 需要人工输入时，由原生安全对话框接收，内容不进入 WebView、聊天、日志和工具结果。
- 自动提权授权应绑定目标、工具、命令摘要和短 TTL。

## 8. 上下文与记忆

### 8.1 上下文层级

1. 用户级：语言、输出偏好、默认安全策略。
2. 工作区级：项目说明、指令文件、Runbook、代码或配置结构。
3. 主机级：OS、Shell、包管理器、服务、容器和环境标签。
4. 会话级：当前目录、终端状态、SFTP 路径、近期输出。
5. 任务级：目标、计划、工具结果、决策、未解决问题和成功条件。

### 8.2 指令文件

支持项目内约定，例如：

- `AGENTS.md`。
- `.shellspan/instructions.md`。
- `.shellspan/runbooks/*.md`。
- 用户级 ShellSpan Agent 指令。

指令文件必须显示来源、作用域和信任等级。远程仓库或下载内容不得自动获得高信任等级。

### 8.3 压缩与检索

- 使用结构化任务摘要替代简单删除最早消息。
- 长输出保存为本地 Artifact，模型只接收摘要、索引和按需片段。
- 文件和仓库场景建立符号/目录地图，并按任务检索相关内容。
- UI 展示当前上下文来源、大小、被省略内容和预计费用。

## 9. 计划、验证与恢复

### 9.1 任务状态机

```text
queued → planning → running → waitingApproval → waitingExternal
      → verifying → completed | partial | failed | cancelled
```

### 9.2 计划模型

每个计划步骤包含：

- 描述和依赖。
- 目标与所需工具。
- 预期 effect。
- 成功条件。
- 回滚或补偿动作。
- 当前状态和证据引用。

### 9.3 自动验证

- 写文件后重新读取相关片段或运行解析/测试。
- 重启服务后检查状态、端口和关键日志。
- 部署后检查健康端点、版本和错误率。
- 批量操作先验证样本主机，再扩大范围。
- 最终完成状态必须引用至少一个有效验证结果。

### 9.4 检查点

- 本地 Git 工作区可使用影子 Git 或补丁快照，不修改用户分支历史。
- 非 Git 文件保存内容摘要、元数据和可恢复副本。
- 远程文件修改前通过 SFTP 创建受限检查点。
- 系统配置修改记录原值、修改值和补偿命令。
- 检查点设置容量与保留期，可由用户清理。

### 9.5 重启恢复

- 保存任务图、计划状态、能力令牌引用、工具调用和 Artifact 引用。
- 应用重启后将未知状态工具标记为 `needsReconciliation`。
- 通过进程、文件、服务或部署状态查询完成对账。
- 只有幂等且尚未开始的调用可以自动重试。
- 不能确认的调用必须由用户选择继续、跳过或终止。

## 10. 扩展体系

### 10.1 MCP

支持：

- stdio。
- Streamable HTTP。
- OAuth 或安全令牌引用。
- 用户级和工作区级配置。
- 工具发现、连接状态、重载和禁用。
- 服务级与工具级权限策略。
- 按需工具 schema 加载，避免上下文膨胀。

首期 MCP 保持实验性，并默认逐工具审批外部写入。

### 10.2 Skills

Skill 由说明、脚本、参考资料和资源组成：

- 支持用户显式调用和模型按描述选择。
- 采用渐进加载，只把名称和描述放入常驻上下文。
- Skill 可以声明所需工具、目标类型和权限。
- 用户或项目 Skill 不得绕过原生策略引擎。

### 10.3 Hooks

建议事件：

- `sessionStart`、`sessionEnd`。
- `userPromptSubmitted`。
- `beforeTool`、`afterTool`、`toolFailed`。
- `permissionRequested`。
- `beforeCompact`。
- `taskCompleted`、`taskFailed`。

同步 Hook 可以允许、拒绝或修改工具参数；异步 Hook 只用于日志、通知和指标，不能追溯改变已执行操作。

### 10.4 Runbook

- 将常见运维流程定义为版本化 Markdown/YAML 工作流。
- 支持参数、前置检查、步骤、成功条件和回滚。
- Runbook 只定义流程，不自行授予权限。
- 支持从成功 Agent 任务中提炼候选 Runbook，但发布前需人工检查。

## 11. 多主机与多 Agent

### 11.1 Fleet 执行

- 使用主机标签、环境和分组选择目标。
- 默认限制并发并加入随机抖动。
- 支持 canary、批次、最大失败数和失败即停。
- 每个目标独立记录状态、结果和回滚。
- 汇总结果不能掩盖单机失败。

### 11.2 子 Agent

候选角色：

- Explorer：收集主机、代码和配置上下文，只读。
- Diagnostician：分析症状和候选根因。
- Operator：执行经授权的修改。
- Verifier：独立验证结果，不复用 Operator 的结论。
- Reviewer：审查计划、差异和安全风险。

原则：

- 子 Agent 使用隔离上下文和独立工具权限。
- 只有可独立拆分的任务才并行。
- 写同一目标或同一文件的任务默认串行。
- 主 Agent 负责合并结果和最终状态，不直接相信子 Agent 的成功声明。

## 12. 用户体验

### 12.1 Agent 运行视图

显示：

- 当前目标和权限范围。
- 计划步骤及依赖。
- 正在执行的工具、持续时间和输出摘要。
- 审批卡、命令或 diff、风险和影响范围。
- 验证证据、检查点和回滚入口。
- Token、费用、步骤和时间预算。

### 12.2 审批体验

支持以下批准粒度：

- 仅本次调用。
- 本任务内相同工具和目标。
- 本任务内指定命令前缀或路径。
- 当前连接在指定时间内。
- 已保存的主机/主机组策略。

禁止使用含义模糊的“永远允许一切”按钮。持久 Operator 策略必须在设置中心可见、可撤销并显示最后使用时间。

### 12.3 后台任务中心

- 展示运行、等待审批、失败和已完成任务。
- 支持停止、继续、重试、归档和打开关联终端。
- 任务结束、等待审批或触发熔断时发送桌面通知。
- 关闭 AI 面板不应自动取消已明确转入后台的任务。

## 13. 可观测性与审计

每个任务记录：

- 模型、厂商、推理等级和请求轮次。
- 输入/输出 Token、缓存使用和估算费用。
- 工具调用、目标、effect、审批、时长和结果。
- 输出截断、上下文压缩和重试事件。
- 权限签发、扩权、撤销和过期。
- 检查点、Artifact、验证和回滚。

审计要求：

- 不默认保存完整敏感输出。
- 对关键事件形成追加式记录和完整性摘要。
- 支持用户导出脱敏诊断包。
- 为企业场景预留 OpenTelemetry/JSONL 导出接口。

## 14. 测试与评测

### 14.1 单元测试

- 所有工具 schema 边界和未知字段拒绝。
- 权限规则优先级、TTL、撤销和目标匹配。
- 路径规范化、符号链接和目录逃逸。
- 命令 effect 分类与未知命令 fail closed。
- 输出截断、二进制内容和秘密脱敏。
- 任务状态机和重启对账。

### 14.2 集成测试

- 本地 PowerShell、cmd 和 Unix Shell。
- SSH 密码、私钥、跳板机和断线重连。
- SFTP 读写、冲突、取消和恢复。
- PTY 与 Direct Exec 结果一致性。
- MCP 连接、重载、超时和恶意 schema。
- 前端崩溃、后端继续运行和应用重启恢复。

### 14.3 安全测试

- 终端输出和远程文件中的提示注入。
- 读取秘密后通过网络或其他工具外传。
- 绕过审批、伪造工具结果和重放能力令牌。
- 命令替换、编码脚本、解释器嵌套和后台逃逸。
- 符号链接、路径穿越和竞态替换。
- 多主机目标混淆和连接身份漂移。
- 取消、超时、迟到结果和重复事件竞态。

### 14.4 任务评测集

至少覆盖：

- 磁盘空间诊断与安全清理建议。
- 服务故障诊断、配置修改、重启和验证。
- 日志检索与根因分析。
- 本地编辑配置并通过 SFTP 发布。
- Docker 容器健康诊断。
- 多主机版本检查和 canary 升级。
- 任务中断、应用重启和恢复对账。

核心指标：

- 任务成功率和验证通过率。
- 错误修改率和误报完成率。
- 未授权副作用数量，目标为 0。
- 平均工具调用数、延迟、Token 和费用。
- 用户审批次数和不必要审批率。
- 中止成功率和恢复成功率。

## 15. 里程碑

### M0：基线与协议设计

交付物：

- Agent Contract v3 草案和 JSON Schema。
- 工具 effect、目标和结果模型。
- 原生策略引擎接口。
- v2 → v3 兼容与回滚方案。
- 代表性任务评测集和基线数据。

验收标准：

- v2 Agent 行为不回归。
- v3 schema 可以表达首批 12 个工具。
- 未注册工具、无效目标和无能力令牌均 fail closed。

### M1：原生工具运行时

交付物：

- Rust Tool Registry。
- 原生能力令牌和策略评估。
- PTY 与 Direct Exec 驱动。
- `exec_command`、`wait_process`、`write_stdin`、`kill_process`。
- 多活动任务存储模型，但暂不开放多主机。

验收标准：

- 高权限授权和执行不依赖前端本地判断。
- 前端刷新或 AI 面板关闭不会丢失后台任务状态。
- 命令结果包含独立状态、退出码、stdout/stderr 和截断元数据。

### M2：文件、计划与检查点

交付物：

- 文件读取、目录、检索、补丁和传输工具。
- Diff 审批界面。
- 计划工具与成功条件。
- 本地和远程文件检查点。
- 写后验证和恢复入口。

验收标准：

- 文件修改不再依赖 Shell 拼接。
- 所有写入均可展示精确目标和差异。
- 可恢复修改在 UI 中提供有效撤销入口。

### M3：上下文与扩展

交付物：

- 工作区、主机、会话和任务上下文层。
- 指令文件和结构化压缩。
- MCP 实验支持。
- Skills、Hooks 和 Runbook v1。
- 上下文和费用查看器。

验收标准：

- 长任务可以压缩上下文后继续，并保留关键目标和决策。
- MCP/Skill/Hook 均不能绕过原生权限引擎。
- 工具 schema 按需加载，空闲扩展不会显著增加每轮上下文。

### M4：后台恢复与 Operator

交付物：

- 后台任务中心和桌面通知。
- 应用重启后的任务对账与恢复。
- Operator 权限配置、TTL、撤销和审计。
- 原生凭证代理和受控提权。
- 网络出口与敏感路径策略。

验收标准：

- 任务可在关闭面板后继续运行。
- 重启后不会重复未知状态的写操作。
- 模型、WebView、日志和工具结果中均不出现明文凭证。

### M5：Fleet 与多 Agent

交付物：

- 主机组、批次、canary 和失败阈值。
- 多目标结果矩阵和逐目标回滚。
- 只读 Explorer、Operator、Verifier 等子 Agent。
- 并发、预算和冲突控制。

验收标准：

- 多主机写入默认先 canary 后扩展。
- 单机失败不会被汇总状态隐藏。
- 子 Agent 不能突破父任务权限或直接声明未经验证的完成状态。

## 17. 迁移与发布策略

- 保留 Agent Contract v2，直到 v3 完成至少一个稳定版本周期。
- 使用独立 rollout flag 开放 v3，不复用 v2 Stable 开关。
- v2 会话历史按只读方式继续展示，不转换为可恢复 v3 任务。
- 首先在请求批准模式验证 v3，再开放 Scoped Autopilot。
- Operator、MCP 写工具、后台恢复和 Fleet 分别使用独立功能开关。
- 每个里程碑必须具备一键回退到上一执行路径的能力。

## 18. 主要风险与缓解

| 风险 | 缓解措施 |
| --- | --- |
| 工具数量导致模型选择不稳定 | 首批限制工具数量；按需加载 schema；建立工具选择评测 |
| 高权限放大提示注入影响 | 不可信数据标记；原生策略；出口限制；敏感路径策略；写后验证 |
| 前后端状态竞态 | Rust 作为任务状态权威；事件带序号；幂等提交；重启对账 |
| 后台命令无法可靠中止 | 进程组/作业对象；远程 PID 证明；明确显示“中止未确认” |
| 多主机误操作 | 主机组快照；canary；失败阈值；并发上限；逐目标审计 |
| MCP 扩展供应链风险 | 服务信任级别；固定版本；schema 限制；工具权限；连接隔离 |
| 检查点占用大量磁盘 | 容量上限、保留期、压缩、按任务清理和用户可见管理 |
| 多模型兼容性差异 | 能力矩阵、现场探测、厂商适配测试和安全降级 |

## 19. 完成定义

只有同时满足以下条件，终端 Agent 增强计划才视为完成：

- 可以在本地和远程目标上使用结构化工具完成读取、修改、传输和验证。
- 高权限执行由 Rust 策略和执行边界强制控制。
- 长任务支持计划、后台运行、停止、恢复和对账。
- 文件和高影响操作具备差异、检查点或补偿方案。
- 支持至少一种 MCP 传输、项目 Skills 和生命周期 Hooks。
- 支持安全的 Operator 模式和不暴露秘密的提权流程。
- 支持有限多主机编排，并具备 canary 和失败即停。
- 安全评测中未授权副作用为 0，且取消、断线和迟到结果竞态测试全部通过。
- 文档、迁移、诊断、审计导出和回滚方案完整。
