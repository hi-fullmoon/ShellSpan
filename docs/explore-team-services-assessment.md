# EXPLORE 团队共享、集中策略与集中审计产品发现评估

> 独立审计基线：`6c14836`
> 审核日期：2026-08-24
> 路线图范围：团队共享、集中策略与审计服务仅在个人工作区模型稳定后进入产品发现
> 首个发现对象：无秘密、待审阅的团队运维资料共享问题；不实现同步或服务

## 结论

本项保持 `candidate` / `researching`，`necessary` 为 `false`。个人工作区模型为 `not-stable`，产品发现和独立评审门禁均保持 `blocked`。本次只完成需求、依赖和安全边界评估，没有新增账户、组织/成员、同步、策略执行、远程审计收集、服务端或 UI。

- TermBridge 自身公开 issue 中没有可复核的团队共享、集中策略或集中审计请求，且 issue 创建受限。外部 SSH/连接工具的用户讨论能证明这些问题类别存在，但不能替代 TermBridge 用户需求。
- Runbook、多主机、操作记录、脱敏导出和逐步审批已有较完整的本地证据；这些是未来发现工作的输入，不是团队服务已经安全。
- 本次独立审计已关闭三项仓库内硬缺口：所有相关远程入口在认证前强制解析 Known Hosts 路径；AI API Key 只从旧 SQLite 明文迁入系统钥匙串；终端工作区采用 v1 并限制大小、数量、字段和布局深度。个人模型仍受完整数据库灾难恢复、当前提交的托管平台检查以及 Windows/macOS 原生钥匙串、休眠/网络切换、更新恢复和故障 E2E 阻断。
- 团队共享、集中策略和集中审计面向不同角色，不能作为一个“企业版”包自动一起实现。共享主要解决资料一致性，策略解决授权决策，审计解决跨成员证据；后两者都要求稳定身份、租户、服务可用性和不可绕过的执行边界。
- 若前置稳定性完成，首个产品发现问题只验证 **2–20 人运维团队能否通过共享不含秘密的连接元数据与待审 Runbook 降低配置漂移和交接成本**。发现可用访谈和无后端原型进行；真实文件试用仍依赖扩展数据契约另行达到稳定，不授权同步后端。

因此本次不建立云账户、组织/成员管理、同步后端、集中策略执行、远程审计收集、插件运行时、第三方代码执行、市场或托管服务，也不改变本地优先定位。

这些证据没有来自 TermBridge 用户的团队规模、频率、失败成本、合规期限、部署偏好或试用意愿，故用户群、用户价值和必要性均未满足。

在产品发现门禁打开前，至少需要 5 个彼此独立的真实团队（每个至少 2 名实际操作者）完成脱敏访谈，分别记录：

1. 当前共享的是主机元数据、Runbook、凭据、审批规则还是复盘证据；不得收集真实主机、用户名、命令输出、密钥或客户标识。
2. 资料变化频率、分发/交接耗时、配置漂移与误连次数，以及现有 Git、配置管理、密码管理器或 PAM 已解决的部分。
3. 团队共享、集中策略、集中审计中哪一个问题实际阻断工作；不得把采购、合规和操作者需求合并成一票。
4. 自托管、本地文件、第三方云或完全不引入服务的部署约束；离线、离职撤权、事故恢复和数据删除要求。
5. 至少 3 个团队愿意用无后端、无真实秘密的原型验证邀请/撤销、版本冲突、陈旧资料、审批拒绝、审计缺口和删除流程。

## 个人工作区稳定性审计

“相关审计条目为 `verified`”不等于个人工作区产品模型稳定。稳定要求连接到记录的完整链路在正式平台上失败关闭、可恢复且可升级；本次逐边界结果如下：

| 边界 | 可复用证据 | 未闭合缺口 | 结论 |
| --- | --- | --- | --- |
| 连接与凭据 | profile 密码、私钥、passphrase 与 AI API Key 均走 OS 钥匙串；旧 AI 明文只向钥匙串迁移，写入/清理失败保留可恢复副本；preferences 拒绝敏感 provider 字段 | 正式平台原生钥匙串故障 E2E 单独归入跨平台边界 | `met` |
| Known Hosts | 未知/不匹配 key 有明确状态；信任/移除写入串行化；交互连接、远程文件/传输、转发、健康与 Runbook 都在认证前强制解析路径并失败关闭 | 当前仓库内无 `None` 降级旁路；正式平台文件权限/休眠故障仍归入跨平台边界 | `met` |
| 会话与工作区恢复 | 远程会话恢复为断开状态；SFTP 与终端均有版本化契约、数量/大小/字段边界和清除入口；终端 v1 兼容旧无版本形状、拒绝未来版本，Rust 保存同步校验 | 正式平台崩溃、休眠与 N-1 端到端证据仍归入跨平台边界 | `met` |
| Runbook / 多主机 | v1 严格字段，512 KiB 文档、8 KiB 命令、64 KiB 输出、5 分钟超时；风险分级、逐步批准、1–8 并发、1–50 批次、按主机熔断和安全重试均有 TS/Rust/隔离 SSH 证据 | 当前缺口主要归入跨平台真实运行；本地模型本身的失败、取消、身份隔离和部分成功语义已经闭合 | `met` |
| 操作记录 | SQLite v5 结构化事件关联 task/operation/profile/批准/结果；最大读取 20,000 事件，失败和部分成功是一等状态 | 写入是观察性 best-effort，失败不会阻止操作；这适合个人记录，但不能被集中审计宣称为完整、不可绕过的合规证据 | `met`（仅个人本地语义） |
| 脱敏导出 | 不存终端输入、原始输出或文件内容；可疑命令整体替换；导出最多 5,000 个任务，临时文件 `sync_all` 后替换，失败清理临时文件 | 中央收集所需的成员身份、事件真实性、端到端确认、驻留位置、法律保留和租户删除尚不存在 | `met`（仅个人本地语义） |
| 本地数据库 | schema v1–v5 迁移、WAL、foreign keys、较新版本拒绝、AI 敏感字段拒绝及终端 workspace 后端版本/大小/数量校验存在 | 通用 preferences 与其他 workspace 尚未统一总量边界；没有全迁移链路断电/磁盘满/损坏恢复夹具，数据库也不是团队同步契约 | `not-met` |
| 权限与审批 | Runbook 的 exact risk、command、profile/host/port/user 和证据在前后端复验；多主机逐主机批准 | 交互终端输入有意不进操作记录，也没有策略执行点；直接 SFTP/终端用户动作不是组织身份下的角色授权。集中策略不能声称覆盖这些旁路 | `met`（仅个人显式操作） |
| 跨平台 | Windows x86_64 与 macOS ARM 运行常规 Rust fmt/Clippy/unit tests，并各自构建发行物 | SSH/SFTP、Runbook、多主机、健康和转发的隔离 E2E 只在 Ubuntu Docker；没有正式平台的原生钥匙串、Known Hosts 失败、工作区恢复、休眠/网络切换和更新恢复 E2E | `not-met` |
| 自动化门禁 | `now-quality-gates` 的仓库内工作流、精确 ROADMAP 映射、安全收口与回归证据为 `verified`；`review:frontend`、Windows/macOS Rust 与隔离 SSH job 已定义 | 当前提交仍需托管 Windows/macOS 检查；正式平台原生钥匙串、休眠/网络切换、更新恢复和完整数据库故障 E2E 没有全部闭合 | `not-met` |

只要任一前置不是 `met`，`personalWorkspaceModel` 就不能标记为 `stable`，团队产品发现门禁也不能打开。

## 三个候选方向比较

| 方向 | 假设用户与价值 | 维护成本与跨平台实现 | 安全与失败/恢复 | 升级与自动化测试 | 当前决定 |
| --- | --- | --- | --- | --- | --- |
| 团队共享 | 2–20 人运维/SRE 团队共享变化的主机元数据和待审 Runbook，减少交接、重复配置和误连；需求信号最接近现有个人资料 | 仍需成员/工作区、冲突、撤权、离线缓存和多设备一致性；客户端可跨平台复用纯数据契约，但真实共享需要文件或服务载体，成本未知 | 必须默认无秘密，成员只能看获授权资料；部分同步不覆盖本地原件，冲突不可静默 last-write-wins；取消保留 last-known-good，撤权阻止新操作 | envelope/artifact/membership 分别版本化，覆盖 N-1/较新拒绝、双端严格校验、离线双写、重放/乱序、删除复活、超限、断网/磁盘满/崩溃和两平台多设备 E2E | **稳定后首个发现问题**；当前不开始正式发现、不实现 |
| 集中策略 | 平台/安全管理员希望统一限制目标、风险、批准、MFA 或变更窗口；操作者得到一致规则 | 需要身份源、策略语言/编辑器、签名发布、客户端/服务端双重执行、缓存与紧急访问；Windows/macOS 不是主要难点，不可绕过性和控制面可用性才是，成本高且未知 | principal/action/resource/tenant 必须冻结；未知动作与无可信策略失败关闭；离线/过期策略、撤销、回滚和 break-glass 均需审计；交互 shell 与现有直连 SFTP 是明确旁路 | policy/decision 版本化，覆盖确定性求值、规则冲突、签名/过期/撤销、缓存故障、服务中断、break-glass、每个入口旁路、N-1 客户端和 Windows/macOS 相同决策 corpus | 不选；先证明具体策略任务和所有执行入口可约束 |
| 集中审计 | 安全、事故响应和合规角色希望跨成员检索批准、目标与结果并执行保留/删除 | 需要身份化事件、签名/序列、缓冲、幂等摄取、存储/索引、密钥轮换、导出和容量运营；远端会话记录会显著扩大隐私、跨平台采集和长期成本 | 事件最小化、租户隔离、传输/静态加密、保留/法律保留/删除必须一致；网络中断只可有界缓冲，溢出不得静默丢弃；恢复后不能跨成员/租户重放 | event/export/tombstone 版本化，覆盖签名/序列、幂等/乱序、spool 上限、存储中断、密钥轮换、脱敏、保留/法律保留/租户删除、N-1 读取和两平台离线恢复 E2E | 不选；本地 best-effort 记录不能直接升级成合规服务 |

三个方向不会共享一个必要性结论。一个团队需要共享主机别名，不表示它需要集中执行策略；需要审计导出，也不表示允许收集终端内容。

## 首个产品发现对象与前置依赖

若个人模型稳定，首个对象是 **无秘密、待审阅的团队运维资料共享问题**，优先验证 Runbook 与连接元数据是否需要一个共同来源。它是访谈/原型对象，不是同步方案：

- 只研究名称、说明、标签、主机别名/端口、Runbook 文本、版本、作者/审核者和变更摘要；密码、私钥、passphrase、AI Key、终端/SFTP 内容、环境变量与操作记录默认排除。
- 资料到达本机后仍需用户选择本地 profile、复用本机钥匙串和 Known Hosts，并重新走 Runbook 风险复验与逐步批准；共享不能自动执行、信任 host-key 或替换凭据。
- 产品发现可用访谈、静态原型和人工准备的脱敏样例，不需要账户或后端。任何真实交换试用必须等待 `explore-extension-data-contracts` 的相应连接/Runbook 契约达到稳定，并另行评审载体。

正式产品发现的硬前置：

1. 本文十个个人工作区前置均为 `met`，`now-quality-gates` 为 `verified`，Windows/macOS 正式平台门禁持续通过。
2. Known Hosts 路径失败在所有连接、SFTP、转发、健康和 Runbook 入口认证前失败关闭；不存在 `None` 降级旁路。
3. 所有 API/连接秘密只存在支持的系统钥匙串，数据库/日志/导出秘密泄露回归覆盖迁移前后。
4. 终端/SFTP 工作区和数据库写入冻结版本、大小/数量、损坏恢复与 N-1 升级语义。
5. Runbook、多主机、审批、操作记录和脱敏导出继续保持 `verified`，并明确本地 best-effort 记录不是中央合规证据。
6. 五团队需求样本和三团队无秘密原型队列成立；否则即使个人模型稳定，也只能继续 `candidate`。
7. 共享对象的数据契约先通过独立 EXPLORE 评审；插件 API、代码执行和服务端不因数据契约稳定而获准。

## 未来候选的强制边界

以下要求只定义重新准入所需的可测试契约，不授权实现。

### 授权、租户、工作区、主机与凭据

- 每次加入、邀请、共享、撤销、策略发布、审计导出和删除都要显式授权，绑定不可变的 tenant/workspace/member/artifact ID 和版本。任何缺失、重复、跨租户、悬空或身份错配都在读取秘密、写本地库或执行前失败关闭。
- 工作区成员资格不隐含主机访问权；共享的 host/profile 元数据不隐含凭据或 Known Hosts 信任。凭据继续属于设备本地钥匙串，除非未来有单独的秘密共享需求、安全模型和评审。
- 最小权限必须区分查看、提议、审核、发布、撤销、导出和删除；不能用一个 `admin` 绕过 Runbook 逐步批准、host-key 验证或本地用户确认。
- 若集中策略未来被评审，所有被宣称受控的终端、SFTP、转发、健康、Runbook 和 AI 入口都必须经过同一版本化决策点；无法约束的交互 shell 必须明确排除，不能以操作记录代替执行控制。

### 大小、数量、并发、重试和最小化

- 任一候选必须在独立评审前冻结并双端验证 tenant/workspace/member/artifact/rule/event 的字节、数量、嵌套深度和批次上限，以及设备并发、同步并发、服务请求、超时、退避和最大重试次数；未给出具体数值即视为 `not-met`，不得以队列或存储“可扩展”为由无界处理。
- 共享最小候选不得携带终端输出、SFTP 内容、私钥、口令、环境秘密或 API Key。集中审计也默认只允许结构化批准/目标/状态/稳定错误；采集命令或会话内容需要新的必要性和隐私评审。
- 重试必须幂等，携带原 operation/request ID 和新 attempt ID；达到上限后保持可见失败，不循环重试、不跨工作区回退，也不把部分成功包装为成功。

### 失败关闭、取消、恢复与服务不可用

- 下载或策略包必须先完整验证身份、版本、大小、签名/完整性、权限和引用，再原子应用；失败保留 last-known-good 与本地未发布草稿，不做部分覆盖或静默 last-write-wins。
- 取消停止新网络/写入工作，清理临时产物并保留可复核 checkpoint；恢复只能从已验证版本继续。撤权、租户切换或成员删除立即使未开始任务失败，正在运行的远端修改不能被静默迁移给另一身份。
- 集中策略不可用时，受管操作只能按已评审的 fail-closed/有时限 last-known-good 规则运行；没有可信、未过期策略时拒绝，不自动降级成本地无限制模式。
- 集中审计不可用时只能使用有大小/事件数/期限上限的加密本地 spool；溢出、磁盘满、密钥不可用或确认超时必须可见，并按风险规则失败关闭，不能覆盖最旧事件后继续宣称完整。

### 版本、保留、删除与脱敏

- 共享 envelope、artifact、membership、policy、decision 和 audit event 分别版本化；支持窗口、N-1 迁移、较新必需字段拒绝、原子升级/回滚和客户端最低版本必须可测试。服务端不得让旧客户端静默丢失权限或删除语义。
- 删除必须区分退出工作区、撤销成员、删除资料、删除本地缓存、租户删除与法律保留；用版本化 tombstone 防止离线旧数据复活，并为保留期结束、备份清理和加密密钥销毁给出可验证期限。
- 导出沿用本地秘密遮蔽并再次在接收端验证；错误、指标和审计不得包含凭据、原始终端/SFTP 内容、未批准命令输出或跨租户标识。用户必须能预览范围并取消。

## 自动化测试门槛

现有 `connection`、workspace、Runbook、多主机、operation history 与 roadmap audit 测试只支撑本次判断。任何未来候选在七项准入变为 `met` 前至少需要：

| 层级 | 必需故障测试 |
| --- | --- |
| 身份与隔离 | 租户/工作区/成员/设备/资料 ID 错配；越权查看/发布/导出/删除；撤权竞态；跨租户缓存、重试和搜索隔离 |
| 凭据与主机 | 共享包含秘密、钥匙串不可用、未知/不匹配 host-key、Known Hosts 路径失败、profile 删除/改绑；全部在认证或执行前拒绝 |
| 同步与冲突 | 截断/篡改/重放/乱序/重复包，离线双写、删除复活、部分批次、超限对象、磁盘满、取消、崩溃和原子恢复 |
| 策略 | 签名、版本、过期、默认拒绝、未知动作、规则冲突、缓存撤销、服务中断、break-glass、所有入口旁路和 N-1 客户端 |
| 审计 | 事件签名/序列、幂等摄取、乱序、spool 上限/溢出、服务/存储中断、脱敏、保留、法律保留、成员/租户删除和导出取消 |
| 跨平台 | Windows x86_64 与 macOS ARM 的原生钥匙串、文件权限、休眠/唤醒、网络切换、升级/回滚和多设备冲突 E2E；隔离服务只使用合成秘密/主机 |
| 运营 | 明确并发、超时、退避、最大重试、配额、背压和故障预算；容量耗尽不得静默丢数据或扩大权限 |

## 复盘与独立评审条件

1. 十个个人工作区前置全部 `met`，`personalWorkspaceModel` 才能改为 `stable`，产品发现门禁才可从 `blocked` 改为 `eligible`。
2. 产品发现取得 TermBridge 自身的团队样本、对照基线和无秘密原型结果，并分别证明所选方向的用户群、用户价值与必要性。
3. 七项 EXPLORE 准入全部为 `met`、`necessary: true`、`status: verified`，且本文列出的失败/恢复、上限、版本、保留/删除、脱敏和跨平台故障测试持续通过后，`independentReviewGate` 才能为 `eligible`。
4. `eligible` 只允许独立评审一个最小候选，不自动授权账户、组织/成员、同步后端、集中策略、远程审计、插件、代码执行、市场、托管或发布。

在上述条件完成前，首个发现对象只是有边界的研究假设；集中策略和集中审计仍是比较对象，不进入实现队列。
