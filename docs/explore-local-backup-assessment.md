# EXPLORE 本地加密备份与设备迁移准入评估

> 基线：`6355d69`
> 审核日期：2026-08-24
> 范围：安全的加密备份与设备迁移；优先本地文件，不默认引入账户体系

## 结论

本项保持 `candidate` / `researching`，不进入正式阶段，也不实现备份入口、账户体系、云同步或秘密迁移。

当前可以证明用户数据分散在版本化连接导出、SQLite、独立 Runbook、系统钥匙串、`known_hosts`、AI 会话文件和日志目录中，也能复用连接导入的预览/冲突/补偿回滚与操作记录导出的原子写入模式；但以下准入证据仍未闭合：

- 没有可复核的 TermBridge 用户请求、设备更换阻断或候选试用队列，不能证明完整备份相对继续完善现有无秘密连接导出确有必要。
- 现有连接导出只覆盖连接元数据，导入时生成新 profile ID；工作区、最近连接和传输恢复记录仍引用旧 ID，不能直接拼成一致迁移。
- 仓库没有备份容器、口令 KDF、认证加密、秘密清零或篡改/错密码测试。`Cargo.toml` 也没有直接声明相应密码学依赖，不能把传递依赖当作可审核实现。
- `preferences` 不是可整体复制的“设置”集合：它混有设备路径、传输恢复和操作记录策略。`ai.providers` 已只保留非敏感元数据并由数据库拒绝敏感字段，但完整数据库复制仍会固化设备绑定数据，且不是经过认证加密、可回滚的备份契约。
- 元数据在 SQLite、SSH 秘密在原生钥匙串，二者没有跨存储事务；现有测试尚不能证明导入中断、钥匙串锁定或回滚失败后不会留下半导入 profile、孤儿凭据或被覆盖的本机配置。

因此本次只记录候选边界和准入门槛。探索证据齐全后仍需独立评审；不得由本评估、候选文件格式或测试通过自动转为路线图承诺。

### 当前证据

2026-08-23 的公开仓库快照中，`backup`、`备份` 与 `migration` issue 查询均为 0，且 GitHub 显示 issue creation is restricted：

- [backup issue 查询](https://github.com/hi-fullmoon/TermBridge/issues?q=is%3Aissue+backup)
- [备份 issue 查询](https://github.com/hi-fullmoon/TermBridge/issues?q=is%3Aissue+%E5%A4%87%E4%BB%BD)

这些结果只能说明公开 issue 中没有需求证据；受限入口会漏掉外部反馈，不能据此断言没有需求。仓库已有“导出连接”说明便携性存在合理产品假设，但既有功能和路线图文字都不是用户验证。

### 待验证用户群

候选用户群是需要更换、重装或同时维护两台个人设备，并已积累多条连接、主题/终端偏好、书签或 Runbook 的个人运维用户。价值假设是减少重新录入与重新绑定成本，同时不把凭据交给云账户。

准入前至少需要：

1. 5 名独立意向用户，记录当前平台、连接规模、需要迁移的数据类别、现有人工步骤、可接受恢复时间和是否确实需要迁移秘密。
2. 至少 3 人愿意在两台真实设备或一次干净重装中完成候选文件的导出、预览、导入、冲突处理和恢复验证。
3. 明确区分“只迁移连接/设置即可”与“必须迁移 SSH 私钥、密码或 API Key”；秘密需求不能从一般备份需求推断。
4. 发现过程只记录分类与数量，不收集主机名、用户名、路径、命令、凭据、终端输出、AI 对话或备份文件。

上述数量只是最低发现样本，不是市场规模结论。若无直接需求或现有连接导出已经解决主要任务，应继续保持候选，避免承担不必要的密码学与跨平台恢复责任。

## 持久化面与现有契约审计

| 数据面 | 现有位置与契约 | 当前安全/恢复证据 | 备份判断 |
| --- | --- | --- | --- |
| 连接 | SQLite `profiles`；连接导出 `schemaVersion: 3` | 导出省略密码、passphrase、私钥内容和设备本地 key ID；导入有范围预览、冲突标记、默认跳过冲突和批次补偿回滚 | 可作为默认无秘密范围的基础，但新 ID 会使工作区引用失效；跳板机 key auth 也需明确重绑提示 |
| 连接组织数据 | `organization_json` 中的分组、标签、收藏、备注、端口转发与快捷操作 | 导出/导入有字段清洗，备注和标签做启发式脱敏 | 可选默认范围；备注、路径与命令仍属敏感元数据，必须在预览中明示 |
| SSH key 元数据 | SQLite `key_credentials` 保存 label、kind、service、公钥等；profile 保存 key ID 引用 | v2 迁移删除旧明文 value 列；测试证明数据库不再保存 SSH 私钥值 | 元数据本身不能恢复凭据；不得把引用存在误报为秘密已迁移 |
| SSH 密码、私钥与 passphrase | macOS Keychain、Windows Credential Manager 或 Secret Service；三个固定 service 与 profile/key ID | 原生存储不可用时失败关闭；store/delete 与数据库元数据有部分补偿测试 | 默认排除；若未来支持，必须使用独立授权、认证加密和跨钥匙串补偿事务 |
| 通用设置与主题 | SQLite `preferences`；主题另有 `localStorage` 首屏缓存 | App 设置有默认值与兼容合并；主题 cache 只是优化 | 只能按白名单导出，不能复制整个表；主题 cache 无需迁移 |
| AI provider 设置 | `preferences.ai.providers` + 系统钥匙串 | provider 元数据不含 API Key；旧 SQLite 明文只迁入钥匙串，写入/清理失败保留可恢复状态 | 非敏感 provider 元数据可候选迁移；钥匙串秘密必须另行授权和设计，不能随普通备份进入容器 |
| 设备/运行期偏好 | 下载目录、最近连接、`transferResumeCandidates`、操作记录保留策略、启动更新检查时间、AI 面板宽度 | 部分数据有版本与边界校验 | 下载目录只能预览后验证；最近连接、传输恢复、更新时间与面板宽度默认排除 |
| Runbook | 用户选择的独立 `.runbook.json`，`schemaVersion: 1` | 前后端拒绝未知字段、明文秘密、未知 keychainRef、风险低报；保存前规范化 | 不在应用数据库中；默认不扫描磁盘。仅允许用户明确选择文件，保留 keychain 引用而不解析秘密 |
| 终端工作区 | SQLite `terminal_workspace.sessions_json` | v1 限制 1 MiB、100 会话、字段长度和布局深度，兼容旧无版本形状、拒绝未来版本；不保存终端输入/输出且恢复为断开态 | 仍引用设备本地 profile ID；默认排除，完成可移植 ID 重映射和备份容器 N-1 迁移后再评审 |
| SFTP 工作区 | SQLite `sftp_workspace.workspace_json`，版本 1 | 保存 profile ID、本地/远端路径、书签与比例；不恢复传输 | 路径和书签会暴露敏感结构且可能在新设备无效；默认排除或单独明确选择，并需路径预检 |
| SFTP 书签 | SQLite `sftp_bookmarks` | CRUD 与 host/port/username 过滤有测试 | 可作为独立敏感元数据类别，不能被“设置”笼统包含 |
| 主机信任 | `~/.termbridge/known_hosts` | 连接时强制校验；写入有进程内锁，但新增/删除不是临时文件替换 | 属于安全决策而非普通设置。默认排除；若迁移，冲突或指纹不匹配必须逐项人工处理，绝不静默覆盖 |
| 操作记录 | SQLite `operation_history_events` | 结构化白名单、二次脱敏、筛选导出；现有导出使用临时文件、`sync_all` 和原子替换 | 包含主机、命令预览和时间线，默认排除；原子写入模式可复用 |
| 诊断与日志 | app log 目录；诊断包 `schemaVersion: 1` | 诊断包只包含显式选中日志并做启发式脱敏；原始日志导出不脱敏，通用导出直接写目标文件 | 全部默认排除，不能复用为备份容器；启发式脱敏也不能证明任意日志无秘密 |
| AI 会话 | `~/.termbridge/sessions/**/*.jsonl` | append-only、Unix 权限 0700/0600、损坏行容错 | 可能包含终端上下文、命令、主机身份与对话，默认排除且不进入首个候选 |
| 临时缓存 | `open-cache`、运行中会话、传输队列 | 可重建或明确不恢复 | 永不备份 |

数据库当前为 schema v5，并会拒绝高于当前版本的数据库而不继续迁移。这能保护应用启动，但不能替代备份格式：原始复制 `termbridge.db` 还会遗漏 WAL 一致性、钥匙串和独立文件，并把内部表、设备路径与本地引用固化为外部契约；AI 明文已被拒绝，但这不提供容器级认证加密或完整性。

## 若重新准入，首个安全本地文件的最小范围

以下是未来实现的准入边界，不是本次实现承诺。

### 默认范围

- 连接非秘密元数据：主机、端口、用户名、认证方式、分组/标签/收藏、经清洗的备注、端口转发和快捷操作。
- 经固定白名单验证的通用设置、主题、终端外观与快捷键；设备路径必须单列并在目标设备预检。
- 只记录“需要重新绑定密码/私钥/passphrase”的缺口，不导出 key ID 或虚构秘密已恢复。

### 仅经独立明确选择

- 用户逐个选择的 Runbook 文件；不扫描任意目录，不解析或替换 keychainRef。
- SFTP 书签、终端/SFTP 工作区和 `known_hosts` 必须作为独立开关，并在预览中展示数量、路径/主机敏感性、旧 ID 映射和冲突结果。
- SSH 密码、私钥、passphrase 与 API Key 必须使用独立于普通范围的秘密授权。秘密类别、数量、来源和目标存储在确认前可见；不得用“全选”默认勾选，也不得在预览、日志、错误或操作记录中出现秘密值。

### 始终排除首个候选

- 原始数据库文件、WAL/SHM、最近连接、传输恢复候选、活动会话/传输/端口转发、操作记录、原始日志、诊断包、AI 对话、`open-cache` 与任何云端状态。
- 账户、设备注册、恢复邮箱、托管密钥、后台同步、静默定时备份和团队共享。

## 安全模型准入门槛

### 威胁边界

必须覆盖备份文件丢失或被复制、文件被篡改/截断、错误口令、恶意 KDF 参数或超大清单、导入较新格式、目标设备已有冲突数据、导出中断、SQLite 提交失败、原生钥匙串锁定/拒绝/部分失败。它不能承诺保护已经被攻陷的源设备、解锁后的目标设备或用户遗失且没有托管恢复渠道的口令。

### 文件与密码学

- 使用经审阅的密码口令 KDF 与 AEAD 组合，不自创加密协议。候选可评估 RFC 9106 的 Argon2id 与经标准化的认证加密；算法、参数、salt、nonce、格式版本必须显式编码并有上限，不能无界接受文件提供的内存/时间参数。参考 [RFC 9106](https://www.rfc-editor.org/rfc/rfc9106.html) 与 [NIST SP 800-38D](https://csrc.nist.gov/pubs/sp/800/38/d/final)。
- 每个文件使用密码学安全随机 salt 和 nonce；header 作为附加认证数据，清单与所有 section 都在认证密文内。明文 header 只能包含识别和解密所需的最小字段，不能泄露主机、用户名、路径、条目数量或秘密类别。
- 口令和派生密钥不写数据库、钥匙串、日志、剪贴板、操作记录或临时明文文件；敏感 buffer 在可行范围内及时清零。错误口令、篡改与截断统一在任何状态变更前失败。
- 即使默认范围不含凭据，文件仍保持加密和完整性保护，因为主机、用户名、备注、路径和 Runbook 也是敏感资产。
- 导出在目标目录创建唯一临时密文文件，写完并 `sync_all` 后原子替换；失败清理临时文件并保留既有目标。不得先写明文 archive 再加密。Windows 与 macOS 都要验证覆盖、权限不足、断电模拟和目标为符号链接/重解析点时的行为。

### 导入、冲突与回滚

1. 限制文件大小，解析最小 header，先检查格式/算法/KDF 参数上限，再派生密钥和认证解密。
2. 对解密后的版本化清单做严格字段、数量、长度、枚举、section digest、profile 引用和设备路径校验；未知必需 section 或较新格式失败关闭。
3. 在任何写入前显示范围预览：每类包含/排除数量、秘密授权、需要重绑的凭据、旧 ID 到新 ID 映射、设置变化、路径可用性和逐项冲突策略。
4. 默认跳过冲突；替换或合并必须按类别显式选择。`known_hosts` 指纹不匹配、Runbook 同 ID 不同摘要和 device-local 路径无效都不得自动覆盖。
5. 非秘密数据库变更使用单个 SQLite 事务。导入新 profile 必须建立稳定 ID 映射后再写工作区/书签引用，不能依赖现有连接导入每次生成随机 ID 的行为。
6. 秘密导入先写新、独立的原生钥匙串条目并记录补偿日志，全部成功后才提交引用；失败时逆序删除新条目并恢复被替换值。若补偿本身失败，必须报告可定位的待清理项，不能宣称已完整回滚。
7. 成功前不删除目标设备现有数据；源备份始终保持只读可重试。导入失败后应用应继续使用导入前快照，允许修正口令、范围或冲突策略后重新预检。

## 升级与兼容策略

- 备份 envelope、加密 suite、manifest 和各 section 分别版本化；manifest 记录创建应用版本、最低读取版本、scope、数量与 section 摘要，但这些字段位于密文内。
- 导出语义对象而不是 SQLite 文件或 Rust/TypeScript 内部结构。只为已发布格式保留显式迁移器；未知必需字段失败关闭，未知可选 section 只有在完整性验证后才能在预览中明确跳过。
- N-1、当前版本和“高于当前版本”都要有固定夹具。新版本必须能导入仍在支持窗口内的旧文件；旧版本遇到新必需格式必须在写入前拒绝，不能部分导入。
- workspace 只有在取得独立 schema version 和 profile ID 重映射后才可加入。Runbook 保持自己的 v1 契约，不由备份格式悄悄重写。
- 数据库迁移仍保持前向；若导入触发不可逆 schema 迁移，恢复说明必须明确不能直接降级应用。回滚指的是本次导入的数据变更，不是承诺数据库降级。

## 维护成本

已有 JSON 校验、Tauri 文件对话框、SQLite 事务、原生钥匙串和操作记录原子导出能降低部分实现成本，但关键成本仍未知：

- 需要长期维护密码学 suite、参数升级、旧格式读取、恶意文件边界、秘密内存生命周期和安全公告响应。
- Windows 与 macOS 的文件替换、权限和原生凭据写入/删除语义不同；当前正式平台必须各自有真实设备/runner 证据。Linux 只能在其正式发行候选独立准入后增加，不能让备份节点反向承诺 Linux 支持。
- 元数据和钥匙串无法共享原子事务，故障注入、补偿日志与人工恢复说明会成为持续维护面。
- 范围预览、逐类冲突、秘密二次授权、可访问性、国际化和口令恢复说明都需要产品与 UI 维护；不能用单一“备份全部”按钮掩盖差异。

在候选实现的构建时长、夹具体积、跨平台失败率、安全评审工时和每月缺陷成本可测量前，维护成本保持未知。

| 导入预检 | 无写入解密/校验、冲突默认跳过、路径检查、profile ID 重映射、known_hosts mismatch、Runbook 摘要冲突、取消不变更状态 |
| 回滚 | SQLite begin/commit 失败、每一种钥匙串 set/get/delete 失败、部分秘密写入、补偿失败可见、无孤儿凭据、现有配置与源文件保持不变 |
| 跨平台 | Windows Credential Manager 与 macOS Keychain 的显式秘密 round-trip、锁定/拒绝/删除、文件权限、原子替换与真实两设备迁移 |
| 端到端 | 当前版本导出到干净 profile、N-1 夹具导入、连接重绑、workspace 断开恢复、错误口令重试和导入后全量前端/Rust/隔离 SSH 门禁 |

仓库当前没有以上备份测试、专用 fuzz/property 测试或两设备迁移 E2E，因此自动化测试准入未满足。

## 复盘触发条件

每四周复盘一次，或在以下任一事件发生时提前复盘：

1. 达到最低用户发现包，并能证明现有连接导出不能解决主要迁移任务。
2. 数据范围白名单、workspace 版本/ID 重映射、AI API Key 排除或安全存储边界通过设计审核。
3. 密码学 suite、参数策略、原子文件协议和跨 SQLite/钥匙串补偿事务通过独立安全审核。
4. Windows 与 macOS 的格式、故障注入、原生钥匙串、N-1 与真实设备迁移门禁能够自动执行。
5. 候选明确维持本地文件、手动导入和默认无秘密；任何账户、云同步或团队共享需求必须另立探索项。

即使六项证据齐全，也只能形成一次“是否进入正式阶段”的独立评审，不自动实现或发布。
