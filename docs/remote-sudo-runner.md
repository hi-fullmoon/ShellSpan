# 远端受限提权执行器

ShellSpan 的审批绑定主机、作业、完整命令和本地配置版本。主机管理员独立部署执行器，并在主机上限制该账号可以运行的作业。普通 SSH 账号继续使用自己的权限，不能取得执行器的独立凭据。启用执行器后，ShellSpan 会在这个受管连接上停用普通 Agent 原生命令和文件工具。

## 主机侧部署

1. 安装 OpenSSH、Python 3 和 sudo。把 `scripts/remote-sudo/shellspan-sudo-runner` 安装为 `/usr/local/libexec/shellspan-sudo-runner`。文件及上级目录归 root 所有，普通用户和执行器账号均不可写。
2. 创建一个专用非 root 账号（示例为 `shellspan-runner`），将登录 shell 设为上一步的程序。使用与普通 SSH 账号不同的密码。账号的主目录和配置由管理员控制。普通 Agent 所用的其他账号须没有广泛的 sudo 权限，也不能修改执行器、作业和它们依赖的文件。
3. 为独立的 sshd 实例生成独有主机密钥。参考 `scripts/remote-sudo/sshd_config.example`，使用独立端口、`ForceCommand` 和禁用转发的配置。执行器端口可以直接开放给授权客户端，或仅向该连接配置的跳板机开放，并允许跳板机转发到这个端口。普通 sshd 实例应拒绝执行器账号登录，例如以 `DenyUsers shellspan-runner` 拒绝该账号。用 `sshd -t -f <配置路径>` 检查后由管理员启动。管理员通过可信渠道提供该实例的 SHA256 主机密钥指纹。
4. 把作业安装到 `/usr/local/libexec/shellspan-sudo-jobs` 下。每个作业使用 `#!/bin/sh`，命令和依赖路径由管理员固定。作业、配置文件、所声明的输入以及它们的所有父目录必须由 root 持有，组和其他用户不可写，且不能经过符号链接。作业不得加载 Agent 可修改的代码、环境或配置。
5. 编写由 root 持有的 `/etc/shellspan-sudo/jobs.json`。配置需要让执行器账号可以读取，不能让它写入：

   ```json
   {
     "runnerUser": "shellspan-runner",
     "operations": {
       "check-service": {
         "argv": ["/usr/local/libexec/shellspan-sudo-jobs/check-service"],
         "trustedInputs": ["/etc/example-service/config.conf"]
       }
     }
   }
   ```

6. 由主机管理员在现有 sudo 策略中授权该账号仅运行已安装的具体作业及其固定参数。执行器调用 `sudo -n`，因此通过 SSH 单独认证的执行器账号需要仅限这些作业的非交互权限。请用 `visudo` 校验；不要授予通用 shell、编辑器或任意命令权限。ShellSpan 无法部署或修改远端权限策略。

## ShellSpan 连接配置

断开此主机的普通连接和执行器连接后，在 **连接管理 → 编辑连接 → Agent 提权 → 管理提权操作** 中启用受限执行器，填写同一主机上独立服务的端口、账号和管理员提供的指纹。为需要开放的作业录入与主机配置一致的操作 ID 和完整命令。原有本机提权名单可以保留，启用远端执行器后才会发布给 Agent。存在名单但尚未设置执行器时，Agent 的普通原生操作也保持停用，直到配置完成或管理员清空名单。

批准操作后，密码弹窗只用于认证独立执行器的 SSH 账号。配置了跳板机时，ShellSpan 先用原连接的跳板机凭据和已知主机密钥建立转发，再独立验证执行器的指纹。跳板机连接失败会结束这次请求。SSH 握手验证通过后直接由 SSH 协议完成密码认证，密码不会进入远端 shell 的标准输入。执行器在接到执行许可前再次核对作业与所声明的依赖，随后由 sudo 最终决定是否执行。结果通过原 SSH 通道回传。

常规 SSH 终端和 SFTP 保留原有用法。尚不能部署执行器的主机可继续手动运维；原有提权名单会保留，自动提权在执行器可用前暂停。新版会迁移本机数据库。若需切回旧版，请在升级前备份数据目录，并在退出新版后用升级前的备份启动旧版；旧版不能直接打开已经迁移的数据库。

锁定的主机配置与收到发出执行许可的时点是两条独立边界。本机撤销提交早于首次允许的非阻塞发送时，旧许可不会发出；发送已经获准后，操作可能已离开客户端。若没有可确认的结果，系统进入待核对状态。未发出执行许可的旧审批在应用重启时结清，已发出且结果未知的作业保留待核对状态。

开发验证可运行 `node scripts/verify-restricted-sudo.mjs`。该脚本在一次性 Docker 容器中启动实际的受限 sshd 和 sudo，验证直连和跳板机路径、撤销、两层主机身份检查和远端权限边界。
