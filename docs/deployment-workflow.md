# Deployment Runbook v2 用户工作流

TermBridge 的 **部署** 工作台把 Deployment Runbook v2 的后端安全边界组织成一条可见工作流。普通 Runbook v1 仍在原 **Runbook** 页面中运行；两者没有隐式迁移，也不共享执行入口。

## 从模板或文件开始

内置模板只有两项：

1. **单主机 systemd Web 服务**：一个显式 profile、一个已校验归档、原子软链接切换、固定 systemd 动作、service/HTTP 健康检查和独立回滚声明。
2. **金丝雀 + 滚动 systemd Web 服务**：相同的合法 v2 文档，加上显式有序目标、金丝雀数量、批次大小、并行上限、健康阈值、失败阈值和逐批人工门。

模板本身可通过 v2 解析器，但 `replace-me` 值和全零 SHA-256 是明确占位符。所有占位符替换完成前，后端审阅按钮保持禁用。模板不包含秘密、任意 Shell、流量切换、负载均衡器配置、供应商 API 或真实凭证。

**导入 v2** 读取本地 JSON 并立即通过权威 TypeScript v2 解析器；v1 或无效 v2 不会替换当前草稿。**导出 v2** 只写规范化、无连接凭证的文档。高级用户可在只读对话框中查看后端返回或本地验证后的规范化 JSON，但不能从该视图执行。

## 目标、审阅和冻结

- 目标只能从已保存的安全 connection profile 中显式勾选。Rollout 顺序由用户上移/下移确定；不接受 tag、动态发现或运行中替换。
- 连接密码、passphrase、私钥和跳板凭证只在现有 profile/keychain 提示链路中临时组装为 IPC connection；它们不进入部署草稿、React 持久状态、localStorage、部署数据库、operation history 或渲染日志。
- **请求后端部署审阅** 后，后端重新解析文档并冻结文档/计划摘要、环境、版本、风险、目标身份、动作、策略、批次与到期时间。
- 一旦 review 返回，所有会影响 document、target、order 或 policy 的控件都锁定。编辑必须先点击 **废弃审阅并编辑**；旧 review 随即从 UI 状态移除，不能再次审批。
- profile 的 host、port、username、认证方式或 jump host 在审阅后变化时，UI 在调用前即失败关闭；后端仍会再次重验。到期 review 每秒重新计算并禁用审批。

## 执行、批次和失败

单主机审批明确显示环境、冻结目标、版本和风险。Rollout 审批还显示精确批次序号和主机数；“金丝雀批次”和“下一滚动批次”使用不同文案，不存在含糊的“继续”。确认框必须由键盘或指针勾选精确授权文案后才能执行。

执行结果只来自强类型 IPC。单主机页面显示语义动作、健康证据和后端终态；rollout 页面显示每个批次的健康门、每台主机的状态/证据以及熔断原因。后端不可用、身份漂移、审批过期、目标/计划错配、部分成功、取消和迟到结果都不会被转换成成功。IPC 身份检查拒绝跨 review、跨 batch 或跨 target 的结果。

## 重启恢复与回滚手册

应用重启后，运行中的部署会成为 `interrupted + recoveryRequired`。部署工作台启动时读取持久化摘要：

1. 打开 **需要审阅的中断部署**。
2. 对 rollout 选择 **加载精确恢复**。文档、策略、目标顺序和已成功主机保持锁定；点击 **请求精确恢复审阅**。
3. 后端重新冻结所有未完成目标。已成功主机没有新的 child review、connection slot 或执行机会；审批只覆盖当前未完成批次。
4. 对单主机中断，可把规范文档加载为新的前向草稿，或从持久 activation snapshot 请求独立回滚审阅。两条路径都不会自动重放。

当失败 rollout 返回回滚建议时，每个建议只包含成功主机的 `sourceOperationId`。用户必须逐台点击 **审阅独立回滚**：后端从持久快照派生 current/previous release 和固定动作，UI 显示环境、目标、版本、发布切换与风险，再要求新的确认。部署审批、批次审批和其他主机的回滚审批都不能授权该回滚。回滚失败不会递归回滚。

## 当前不支持

- 流量切换、负载均衡器或供应商流量 API；
- tag/服务注册中心等动态目标发现；
- 任意 Shell、hook、脚本、环境注入、数据库迁移、Compose 或 Kubernetes；
- 无人审批自动回滚、递归回滚或后台静默恢复；
- 实际 release cleanup 与后台 GC（cleanup 仍只可审阅、不可执行）。

这些限制是产品安全边界，不应通过 JSON 高级视图、前端状态或新的 IPC 绕过。
